왜 배워야 하나?

Dockerfile은 “이 이미지를 이렇게 만들어라”라고 적어 둔 조리법입니다. 위에서 아래로 한 줄씩 실행되며 이미지가 완성됩니다. 오늘 두 개를 만드니, 두 파일을 비교하면 구조가 보입니다.

api/Dockerfile파이썬 API 이미지
1 # 매출 집계 API 이미지 2 FROM python:3.12-slim 3 4 WORKDIR /app 5 6 # 실행할 코드와 데이터를 이미지 안에 넣는다 7 COPY api.py . 8 COPY sales.csv . 9 10 # 이 컨테이너는 5000번으로 서비스한다는 표시 11 EXPOSE 5000 12 13 # 컨테이너가 시작되면 API 서버를 띄운다 14 CMD ["python", "api.py"]
줄무슨 일왜 필요한가
FROM python:3.12-slim파이썬이 깔린 바탕 이미지파이썬을 직접 설치하지 않는다 · slim은 가벼운 판
WORKDIR /app작업 폴더를 /app으로이후 명령이 이 폴더에서 실행된다 (cd와 비슷)
COPY api.py .코드를 이미지 안으로이미지에 들어가야 어디서든 같은 코드가 돈다
COPY sales.csv .데이터도 함께오늘은 데이터까지 이미지에 넣는다 (밖에서 주는 방법은 3.3)
EXPOSE 50005000번을 쓴다는 표시문서 역할 · 실제 연결은 실행할 때 -p로 한다
CMD ["python", "api.py"]컨테이너가 뜨면 이 명령 실행nginx 이미지가 알아서 웹 서버를 띄우는 것과 같은 자리

docker build

docker build -t my-api:1.0 .
       ↑ 굽는다      ↑ 이름:태그        ↑ 빌드 컨텍스트(이 폴더를 통째로 도커에 넘긴다)
옵션무엇언제
-t 이름:태그이미지에 이름표를 붙인다항상 · 없으면 이름 없는 이미지가 생긴다
. (마지막 점)이 폴더를 빌드에 쓴다Dockerfile과 COPY할 파일이 있는 곳
-f 경로/Dockerfile다른 이름·위치의 Dockerfile 사용파일이 Dockerfile.dev 처럼 다를 때
--no-cache캐시 없이 처음부터 다시“고쳤는데 반영이 안 될 때” 확인용
--build-arg KEY=값빌드 중에 값 전달버전·경로를 바꿔 굽고 싶을 때
왜 “이 폴더를 통째로” 넘기나 COPY는 빌드 컨텍스트 안의 파일만 넣을 수 있습니다. 그래서 폴더 밖의 파일은 COPY할 수 없고, 불필요한 큰 파일이 있으면 빌드가 느려집니다(.dockerignore로 제외).

명령무엇주의
docker save -o 파일.tar 이미지:태그이미지를 tar 파일로-o는 출력 파일 이름

헷갈리는 짝차이
-t (build) vs -t (run)build의 -t는 태그 · run의 -t는 터미널(보통 -it로 씀)

-v vs COPY-v는 바깥 폴더를 붙임 · COPY는 이미지 안에 넣음
stop vs rm멈춤 · 삭제 · rm -f는 둘 다
