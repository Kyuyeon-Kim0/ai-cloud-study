리다이렉션02
REDIRECTION

명령의 결과를 화면 대신 파일로 보낸다

리다이렉션은 명령어의 입력 또는 출력을 다른 파일이나 명령어로 전환하는 기능입니다. 명령 실행 결과를 파일로 저장하거나, 파일의 내용을 명령어의 입력으로 사용할 수 있습니다.

출력 리다이렉션

기호하는 일예시
>기존 파일에 내용을 덮어씀echo "Hello, World!" > output.txt
>>기존 파일의 끝에 내용을 추가echo "추가 내용" >> output.txt
ubuntu
ubuntu@myUbuntu:~$ echo "Hello, World!" > output.txt
ubuntu@myUbuntu:~$ echo "추가 내용" >> output.txt
ubuntu@myUbuntu:~$ cat output.txt
Hello, World!
추가 내용

입력 리다이렉션

<는 파일의 내용을 명령어의 입력으로 사용합니다. 키보드로 입력받는 프로그램에 파일을 대신 넣어 줄 수 있습니다.

plus.pypython
print("첫 번째 수를 입력해 주세요: ") a = int(input()) print("두 번째 수를 입력해 주세요: ") b = int(input()) print(f"덧셈의 결과는: {{a+b}}")
input.txttext
1 2
ubuntu
ubuntu@myUbuntu:~$ python3 plus.py < input.txt
첫 번째 수를 입력해 주세요:
두 번째 수를 입력해 주세요:
덧셈의 결과는: 3

키보드를 두 번 두드리는 대신 input.txt의 두 줄이 차례로 입력되었습니다. 같은 작업을 여러 번 반복할 때 유용합니다.

알아 두면 좋은 것 오류 메시지는 별도 통로로 나옵니다. 명령 2> error.txt는 오류만 저장하고, 명령 > all.txt 2>&1은 결과와 오류를 한 파일에 모읍니다. 2가 오류 통로의 번호입니다.

파이프03
PIPE

한 명령의 결과를 다음 명령에게 넘긴다

파이프는 한 명령어의 출력을 다른 명령어의 입력으로 연결하는 기능입니다. | 기호를 사용해 여러 명령어를 이어 복잡한 작업을 수행합니다.

명령 A
결과를 내놓음|명령 B
그 결과를 입력으로|명령 C
다시 그 결과를›화면 또는 파일
표현뜻
A | B명령어 A의 출력을 명령어 B의 입력으로 사용
A > tmp.txt
B < tmp.txt		결과는 위와 비슷하다. 다만 파이프는 A가 완전히 끝나지 않아도 B가 처리를 시작할 수 있어 100% 같지는 않고, 중간 파일도 남지 않는다

예시

ubuntu
ubuntu@myUbuntu:~$ ls -l | grep "^d" # 현재 디렉터리에서 디렉터리만 나열
drwxrwxr-x 2 ubuntu ubuntu 4096 … test2
ubuntu@myUbuntu:~$ cat file.txt | sort | uniq # 정렬하고 중복 제거
명령원래 말하는 일
grep "^d"global regular expression print글자가 들어간 줄만 고른다. ^d는 “d로 시작하는 줄” → 권한 첫 글자가 d인 디렉터리
sort정렬줄을 순서대로 정렬한다. -r은 내림차순
uniqunique이웃한 중복 줄을 하나로 합친다. 그래서 보통 sort 다음에 쓴다
wc -lword count · line줄 수를 센다
xargsextended arguments앞에서 넘어온 목록을 뒤 명령의 인자로 붙여 준다
zcatz + cat압축(.gz)을 풀지 않고 내용만 읽는다
파이프와 리다이렉션은 함께 쓴다 A | B > result.txt는 “A의 결과를 B에 넘기고, 그 최종 결과를 파일에 저장”입니다. 리눅스는 이렇게 작고 단순한 도구를 이어 붙여 복잡한 일을 처리합니다.

grep으로 찾기04
GREP

필요한 줄만 골라낸다

grep은 파일이나 앞 명령의 결과에서 특정 글자가 들어간 줄만 출력합니다. 로그가 수천 줄이어도 필요한 줄만 뽑아낼 수 있어, 파이프와 함께 가장 많이 쓰이는 명령입니다.

파일에서 찾기
ubuntu@myUbuntu:~$ grep "bash" /etc/passwd
root:x:0:0:root:/root:/bin/bash
ubuntu:x:1000:1000:…:/bin/bash
파이프로 받아서 찾기
ubuntu@myUbuntu:~$ ls -l | grep "^d"
drwxrwxr-x 2 ubuntu ubuntu 4096 … test2

쓰는 방법은 두 가지입니다. 파일 이름을 직접 주거나, 파이프로 앞 명령의 결과를 넘기거나입니다.

자주 쓰는 옵션

옵션원래 말하는 일
-iignore case대소문자를 구분하지 않는다 (Error와 error를 함께)
-nnumber몇 번째 줄인지 줄 번호를 함께 보여 준다
-ccount줄을 보여 주지 않고 개수만 센다
-vinvert반대로, 그 글자가 없는 줄만 고른다
-rrecursive폴더 안의 모든 파일을 뒤진다 (grep -r "alias" ~/)

자리 표시 기호 두 개

기호뜻예
^줄의 시작grep "^d" → 권한 첫 글자가 d인 줄 = 디렉터리만
$줄의 끝grep "bash$" → 줄이 bash로 끝나는 줄

따라하기

ubuntu
ubuntu@myUbuntu:~$ grep -c "bash" /etc/passwd # 개수만
2
ubuntu@myUbuntu:~$ grep -n "root" /etc/passwd | head -n 2 # 줄 번호와 함께
1:root:x:0:0:root:/root:/bin/bash
ubuntu@myUbuntu:~$ ls -l | grep -v "^d" # 디렉터리가 아닌 것만
PART 2와 연결 ls -l의 첫 글자가 d면 디렉터리, -면 파일이었습니다. grep "^d"는 그 첫 글자를 보고 고르는 것이라, 권한 표기를 읽을 줄 알면 필요한 줄을 정확히 뽑을 수 있습니다.

왜 텍스트 편집기인가08
WHY EDITOR

편집기 실력이 곧 시스템 관리 역량이다

WHY

리눅스 환경에서 텍스트 편집기는 단순한 문서 작성 도구를 넘어 시스템 제어와 운영의 핵심 인터페이스입니다.

리눅스는 “모든 것은 파일이다”라는 유닉스 철학을 따릅니다. 하드웨어 설정, 네트워크 구성, 프로세스 정보까지 대부분 일반 텍스트로 저장되기 때문에 편집기의 숙련도가 시스템 관리 역량과 직결됩니다.

1. “모든 것은 파일” 철학의 직접적인 실행 도구

  • 설정 관리의 중심: 네트워크(netplan, /etc/network), 서비스(systemd), 사용자 권한(/etc/sudoers) 등 주요 설정 파일은 모두 평문(Plain Text)입니다. GUI 제어판 대신 설정 텍스트 파일을 직접 수정해 시스템 전체를 제어합니다.
  • 원격 및 서버 환경(CLI)의 유일한 수단: 대부분의 서버는 자원 절약과 보안을 위해 GUI를 설치하지 않는 Headless 서버로 운영됩니다. SSH 터미널에서는 텍스트 편집기만이 파일 수정 수단입니다.

2. 자동화 및 스크립트 작성의 기본

  • 셸 스크립트 개발: Bash, Python 등으로 일괄 작업(배치), 백업, 모니터링 스크립트를 즉시 만들고 실행 권한을 주어 자동화합니다.
  • 배포 및 인프라 코드 관리: Dockerfile, Docker Compose, Nginx 설정, CI/CD 파이프라인 스크립트 등 클라우드·DevOps 작업의 기본이 되는 구성 코드를 터미널에서 즉시 수정합니다.

3. 트러블슈팅 및 비상 복구

  • 로그 분석 및 패치: /var/log/ 아래의 대용량 로그를 점검하고, 문제가 생긴 설정 값을 즉시 고쳐 서비스를 재시작합니다.
  • 응급 복구 모드: 부팅 장애로 싱글 유저 모드나 복구 셸에 진입하면 GUI는 동작하지 않습니다. 오직 터미널 편집기로만 /etc/fstab 같은 부팅 오류를 고칠 수 있습니다.
PART 2와 연결 앞에서 echo와 >만으로 스크립트를 만들었습니다. 한 줄짜리는 그렇게 되지만, 여러 줄을 고치고 지우는 일은 편집기가 필요합니다.

WHY SCRIPT

사람이 치던 명령을 파일 하나로 묶는다

WHY

셸 스크립트는 터미널에서 수행하는 명령들을 하나로 묶어 자동화하는 실행 파일입니다.

사람이 일일이 타이핑하던 반복 작업을 코드화하여 운영체제가 스스로 실행하도록 만드는, 리눅스 시스템 관리의 핵심 축입니다.

1. 반복 작업의 자동화 및 인적 실수 방지

  • 휴먼 에러 최소화: 복잡한 배포·백업 명령을 수동으로 입력하다 보면 오타나 순서 누락이 생깁니다. 스크립트로 표준화해 두면 항상 동일하고 안전한 결과를 보장합니다.
  • 시간 절약: 매일 아침 하는 로그 정리, 캐시 삭제, 서버 상태 점검을 한 번의 실행으로 끝냅니다.

2. 스케줄링(cron)과의 결합을 통한 무중단 운영

리눅스의 스케줄링 데몬인 cron과 결합하면 시스템이 알아서 동작합니다.

  • 새벽 3시에 데이터베이스를 덤프해 원격 백업 스토리지로 전송
  • 디스크 사용량이 90%를 초과할 때 관리자에게 알림 전송
  • 비정상 종료된 데몬(Nginx, MySQL 등)의 상태를 주기적으로 확인하고 자동 재시작

3. 도구와 데이터의 연결고리 (Glue Logic)

리눅스의 핵심 철학은 “작고 단순한 도구를 파이프(|)로 연결해 복잡한 문제를 해결하는 것”입니다. grep, awk, sed, curl, find 같은 유틸리티를 스크립트 안에서 조합하면, 무거운 애플리케이션 개발 없이도 대용량 로그 필터링이나 API 연동 데이터 파싱을 가볍게 처리할 수 있습니다.

4. 클라우드·컨테이너 환경(DevOps)의 기본기

  • 도커: 컨테이너가 뜰 때 실행되는 entrypoint.sh를 작성해 환경 변수를 주입하고 서비스를 구동합니다.
  • 클라우드 초기 세팅(Cloud-init): AWS, GCP 등에서 가상 머신이 생성되는 즉시 패키지를 설치하고 방화벽을 구성하는 User Data 스크립트의 기본 언어가 Bash입니다.

자동 실행은 cron이 맡는다

스크립트를 만들어 두어도 누군가 실행해야 합니다. cron은 정해진 시각에 스크립트를 대신 실행해 주는 데몬입니다. 지금은 형식만 봐 둡니다.

crontab -e 로 등록하는 형식bash
# 분 시 일 월 요일 실행할 명령 0 3 * * * /home/ubuntu/backup.sh # 매일 새벽 3시 */10 * * * * /home/ubuntu/check_disk.sh # 10분마다
명령하는 일
crontab -e내 예약 작업을 편집한다 (edit · 편집기가 열린다)
crontab -l등록된 예약 작업 목록을 본다 (list)
crontab -r등록된 작업을 모두 지운다 (remove · 주의)
이 교재에서는 형식만 cron은 스크립트가 충분히 익숙해진 다음에 등록해야 안전합니다. 잘못 등록하면 1분마다 잘못된 명령이 반복 실행될 수 있습니다. 먼저 손으로 실행해 정상 동작을 확인하고, 그다음 등록하는 순서를 지킵니다.
AI에게 그대로 물어보기더 공부할 것
cron 표현식 5칸의 의미와 자주 쓰는 예를 표로 알려 줘. logrotate로 로그를 자동 압축·삭제하는 설정 예시를 보여 줘. 셸 스크립트에서 오류가 났을 때 멈추게 하는 set -e, set -u 옵션이 무엇인지 알려 줘.

같은 일을 여러 번 시킨다

반복문은 특정 작업을 여러 번 반복 실행하는 구조입니다. Bash에서는 주로 for와 while을 사용하며, 파일 처리와 결합하면 대량의 파일을 효율적으로 처리할 수 있습니다.

for 반복문

리스트나 범위의 각 항목에 대해 반복합니다. 파일 목록 처리, 정해진 횟수 반복, 배열 요소 처리에 씁니다.

for 예시bash
# 1부터 10까지 2씩 증가하며 출력 for ((i=1; i<=10; i+=2)) do echo $i done # 디렉터리 내 모든 .txt 파일 처리 for file in *.txt do echo "처리 중인 파일: $file" done # 1부터 5까지의 숫자 출력 for i in {{1..5}} do echo $i done

while 반복문

조건이 참인 동안 계속 반복합니다. 사용자 입력 처리, 파일을 끝까지 한 줄씩 읽기 등에 씁니다.

while 예시bash
# 사용자가 q를 입력할 때까지 반복 while [ "$input" != "q" ] do echo "명령을 입력하세요 (종료: q):" read input done # 파일의 각 줄 읽기 while read line do echo "읽은 줄: $line" done < input.txt

마지막 줄의 < input.txt가 0파트에서 배운 입력 리다이렉션입니다.

조건문으로 작은 수와 큰 수를 정하고, 반복문으로 그 사이를 더합니다. 지금까지 배운 변수 · 입력 · 조건 · 반복이 한 스크립트에 모두 들어갑니다.

배열은 여러 개의 값을 하나의 변수에 저장하는 데이터 구조입니다. 관련된 데이터를 그룹으로 묶어 효율적으로 관리할 수 있습니다.

#!/bin/bash

6. 파일이 있는지 확인

findfile.shbash
#!/bin/bash
echo "파일 이름을 입력하세요:"
read fname
if [ -f "$fname" ]; then
    echo "$fname 있습니다."
else
    echo "$fname 없습니다."
fi

7. 실행 권한 한 번에 주기

set_exec.shbash
#!/bin/bash
for file in ~/p3/*.sh
do
    chmod +x "$file"
    echo "실행 권한 부여: $file"
done

8. 폴더 백업하기

backup.shbash
#!/bin/bash
target=~/p3
if [ -d "$target" ]; then
    tar -czf ~/p3_$(date +%Y%m%d).tar.gz "$target"
    echo "백업 완료"
else
    echo "$target 폴더가 없습니다."
fi
~/p3
ubuntu@myUbuntu:~/p3$ chmod +x backup.sh && ./backup.sh
백업 완료
