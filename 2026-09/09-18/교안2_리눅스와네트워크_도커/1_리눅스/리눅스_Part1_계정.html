권한을 분리해야 하는 기술적 이유03
THREE TECHNICAL REASONS

모두가 root로 일하면
안전장치 · 기록 · 격리가 한꺼번에 무너진다

권한을 분리하지 않고 모든 작업자가 root로 작업하면 휴먼 에러 방지, 로그 추적, 보안 격리가 모두 사라집니다. 세 가지를 하나씩 봅니다.

① 실수 방지 안전장치

root 상태에서는 잘못된 경로를 지우는 명령(rm -rf /)도 즉시 실행되어 서버가 영구적으로 파괴됩니다. 일반 계정이나 sudo 환경에서는 권한 거부가 나거나 비밀번호를 다시 묻는 단계를 거치므로 대형 장애로 번지기 전에 멈출 수 있습니다.

일반 계정막힘
dev1@myUbuntu:~$ rm /etc/hosts rm: cannot remove '/etc/hosts': Permission denied
sudo 계정한 번 더 확인
ubuntu@myUbuntu:~$ sudo apt update [sudo] password for ubuntu: _ # 멈추고 다시 생각할 기회

② 작업 이력 추적 (감사 로그)

여러 사람이 root로 로그인해 작업하면 로그에는 “root가 실행함”만 남아 장애를 일으킨 사람을 특정할 수 없습니다. 각자의 계정으로 로그인해 sudo를 쓰면 /var/log/auth.log 같은 시스템 로그에 실제 작업자 ID와 실행한 명령이 시각과 함께 기록됩니다.

/var/log/auth.log 예시누가 · 언제 · 무엇을
Sep 17 23:10:42 myUbuntu sudo: ubuntu : TTY=pts/0 ; PWD=/home/ubuntu ; USER=root ; COMMAND=/usr/bin/apt update

③ 침해 사고 시 피해 격리

웹 서버나 데이터베이스 같은 프로그램이 해킹당해도, 그 프로그램이 sudo 불가 일반 계정으로 돌고 있었다면 공격자는 서버 전체를 장악하지 못하고 그 계정의 권한 안에 갇힙니다. Ubuntu의 웹 서버가 www-data라는 별도 계정으로 실행되는 이유입니다.

HOME DIRECTORY

계정마다 하나씩 주어지는 방,
로그인하면 처음 서 있는 곳이다

홈 디렉터리는 계정마다 따로 주어지는 개인 작업 공간입니다. 앞에서 본 것처럼 sudo 불가 일반 계정은 자기 홈 안에서만 파일을 만들고 고칠 수 있습니다. 일반 사용자의 홈은 /home 아래에 모이고, root의 홈만 따로 /root에 있습니다.

/ ← 최상위 ├── root/ ← root의 홈 ├── home/ ← 일반 사용자 홈 │ └── ubuntu/ ← 나의 홈 ~ │ ├── .bashrc │ ├── .profile │ └── .ssh/ └── etc/ └── skel/ ← 홈 원본
계정홈 위치
root/root
ubuntu/home/ubuntu
dev1 (만들면)/home/dev1
~ 는 사람마다 다르다 같은 ~라도 ubuntu가 쓰면 /home/ubuntu, root가 쓰면 /root를 뜻합니다.

내가 어디에 있는지 확인하기

ubuntu@myUbuntu위치 확인
ubuntu@myUbuntu:~$ whoami # 나는 누구인가 ubuntu ubuntu@myUbuntu:~$ pwd # 지금 어디에 있나 /home/ubuntu ubuntu@myUbuntu:~$ echo $HOME # 내 홈은 어디로 정해져 있나 /home/ubuntu ubuntu@myUbuntu:~$ ls # 아무것도 안 나온다! ubuntu@myUbuntu:~$
왜 ls에는 아무것도 안 나올까?

홈이 비어 있어서가 아닙니다. 이름이 점(.)으로 시작하는 파일은 숨김 파일이라서 ls가 기본으로 보여 주지 않습니다. 새 계정의 홈에는 이런 숨김 설정 파일만 들어 있으니 화면이 비어 보이는 것입니다. 숨김 파일까지 보려면 -a 옵션이 필요합니다.

pwd = print working directory(현재 위치 출력) · $HOME = 홈 경로가 담긴 환경 변수. cd만 치면 이곳으로 돌아온다.

BASH · FOLLOW ALONG

명령을 해석해 전달하는 프로그램, Bash

핵심Bash는 무엇을 하는가

Bash는 사용자가 입력한 명령어를 해석하여 리눅스에 전달하는 명령어 해석 프로그램입니다. Bash는 Bourne Again Shell의 약자입니다.

  • Bourne: 초기 셸을 만든 Stephen Bourne의 이름
  • Again: 기존 Bourne Shell을 발전시켜 다시 만들었다는 의미
  • Shell: 사용자와 운영체제 사이에서 명령을 해석하는 프로그램

예를 들어 사용자가 다음을 입력하면:

ubuntu@myUbuntu:~$ ls -la

즉, 관계를 구분하면 다음과 같습니다.

터미널: 글자를 입력하고 결과를 보는 화면 Bash : 입력한 명령을 해석하는 프로그램 Linux : 프로그램과 컴퓨터 자원을 관리하는 운영체제

Bash가 다음과 같이 처리합니다.

  1. ls가 실행할 명령어임을 파악합니다.
  2. -la가 ls의 옵션임을 파악합니다.
  3. 리눅스에 ls 프로그램 실행을 요청합니다.
  4. 실행 결과를 터미널에 표시합니다.

옵션 표기: - 와 --12
OPTIONS

옵션은 - 한 개로 짧게,
-- 두 개로 길게 쓸 수 있다

명령 뒤에 붙어 동작을 바꾸는 것을 옵션이라고 합니다. 아래 두 명령은 같은 기능입니다. 입력이 빠른 쪽은 짧은 옵션, 뜻이 잘 읽히는 쪽은 긴 옵션입니다.

짧은 옵션- 한 개
ubuntu@myUbuntu:~$ ls -a . .. .bash_history .bash_logout .bashrc .cache .profile .ssh
긴 옵션-- 두 개
ubuntu@myUbuntu:~$ ls --all . .. .bash_history .bash_logout .bashrc .cache .profile .ssh
형식의미예
- 한 개한 글자짜리 짧은 옵션-a, -l, -h
-- 두 개단어로 된 긴 옵션--all, --human-readable

짧은 이름 ↔ 긴 이름

짧은긴하는 일
-a--all숨김 항목까지
-h--human-readable크기를 K·M·G로
-r--reverse순서 뒤집기
-R--recursive하위 폴더까지
-l없음자세히 보기
없음--color=never색 끄기

쓰는 규칙

  • 짧은 옵션은 붙여 쓸 수 있다. -l -a = -la = -al
  • 긴 옵션은 붙일 수 없다. 하나씩 띄어 쓴다. --all --human-readable
  • 섞어 써도 된다. ls -l --all
  • 값이 필요한 긴 옵션은 =로 잇는다. --color=never
  • 대소문자를 구분한다. -r과 -R은 다른 옵션이다.
-h 를 더해 보기ls -lah
ubuntu@myUbuntu:~$ ls -lah total 32K drwxr-x--- 4 ubuntu ubuntu 4.0K Sep 17 23:08 . -rw-r--r-- 1 ubuntu ubuntu 3.7K Mar 31 2024 .bashrc # 3771 바이트 → 3.7K -rw-r--r-- 1 ubuntu ubuntu 807 Mar 31 2024 .profile # 1K 미만은 그대로

옵션 전체 목록은 ls --help(짧은 안내) 또는 man ls(설명서, q로 종료)로 확인합니다.

WHY

리눅스는 본질적으로 다중 사용자(Multi-user) 환경을 전제로 설계된 운영체제입니다.

계정과 그룹을 정교하게 관리하지 않으면 단 한 번의 실수나 보안 침해로 시스템 전체가 마비될 수 있습니다.

사용자 계정 및 그룹 관리를 잘해야 하는 이유

01 · PoLP

최소 권한의 원칙

모든 작업자가 관리자 권한을 가질 필요는 없습니다. 개발자, 웹 데몬, DB 관리자 등 역할별로 그룹을 분리하고 필요한 디렉터리와 명령어에만 권한을 주어야 보안 사고를 막을 수 있습니다.

02 · Blast Radius

피해 반경 격리

특정 서비스(예: Apache, Nginx)나 개인 계정이 해킹당해도 권한이 분리되어 있다면, 침입자가 시스템 전체를 장악하거나 다른 사용자의 데이터를 열람하는 것을 막습니다.

03 · Audit & Accountability

책임 추적성 확보

root나 공용 계정 하나를 여럿이 함께 쓰면 로그에 누가 했는지가 남지 않습니다. 개인별 계정으로 접속해 필요할 때만 sudo를 써야 장애나 파일 변조 시 누가 어떤 명령을 내렸는지 추적할 수 있습니다.

04 · 프로세스 격리

서비스 전용 계정

www-data, nobody 같은 서비스 전용 시스템 계정으로 프로그램을 실행하면, 그 프로그램의 버그나 취약점이 운영체제 전체로 번지는 것을 막습니다.

1. 나는 누구이고 어디에 있나

ubuntu
ubuntu@myUbuntu:~$ whoami
ubuntu@myUbuntu:~$ pwd
ubuntu@myUbuntu:~$ echo $HOME

2. 숨은 파일 찾기

ubuntu
ubuntu@myUbuntu:~$ ls -a
ubuntu@myUbuntu:~$ ls --all

3. 폴더 만들고 지우기

ubuntu
ubuntu@myUbuntu:~$ mkdir practice
ubuntu@myUbuntu:~$ cd practice
ubuntu@myUbuntu:~/practice$ pwd
ubuntu@myUbuntu:~/practice$ cd
ubuntu@myUbuntu:~$ rmdir practice
ubuntu@myUbuntu:~$ ls

rm practice는 폴더라서 거부됩니다.

4. 기록은 어디에 있나

ubuntu
ubuntu@myUbuntu:~$ history -a
ubuntu@myUbuntu:~$ cat .bash_history

종료 전에도 -a로 지금 바로 파일에 덧붙입니다.

5. 나만의 별칭

ubuntu
ubuntu@myUbuntu:~$ cp ~/.bashrc ~/.bashrc.bak
ubuntu@myUbuntu:~$ nano ~/.bashrc # 맨 끝에 alias h='history' 추가
ubuntu@myUbuntu:~$ source ~/.bashrc
ubuntu@myUbuntu:~$ h

6. 새 사용자 st3

ubuntu
ubuntu@myUbuntu:~$ sudo adduser st3
ubuntu@myUbuntu:~$ id st3

7. st3의 한계

ubuntu → st3 → ubuntu
ubuntu@myUbuntu:~$ su - st3
st3@myUbuntu:~$ ls /root
st3@myUbuntu:~$ sudo whoami
st3@myUbuntu:~$ exit

8. st3에게 sudo 주기

ubuntu → st3
ubuntu@myUbuntu:~$ sudo usermod -aG sudo st3
ubuntu@myUbuntu:~$ su - st3
st3@myUbuntu:~$ sudo whoami
root
st3@myUbuntu:~$ exit

새 그룹은 다시 로그인해야 반영됩니다.
