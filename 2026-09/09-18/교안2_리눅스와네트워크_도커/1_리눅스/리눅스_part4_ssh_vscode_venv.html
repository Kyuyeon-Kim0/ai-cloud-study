왜 SSH인가02
WHY SSH

멀리 있는 서버에 안전하게 들어가는 표준

WHY

SSH(Secure Shell)는 네트워크 너머의 컴퓨터에 암호화된 통로로 접속해 명령을 실행하는 프로토콜입니다.

클라우드의 서버는 눈앞에 없습니다. 모니터도 키보드도 없습니다. 실무에서 서버를 다루는 일은 거의 모두 SSH 접속으로 시작합니다.

SSH가 하는 일

항목설명
원격 명령 실행내 PC의 터미널에 입력하지만 실제로는 서버에서 실행된다
암호화주고받는 내용이 모두 암호화된다. 예전에 쓰던 telnet은 비밀번호가 그대로 흘러 다녔다
파일 전송같은 통로로 scp, sftp를 써서 파일을 주고받는다
포트 22기본 통신 문 번호. PART 1에서 본 “1~1023번 포트”에 속해 root 권한으로 열린다

비밀번호 대신 키를 쓰는 이유

비밀번호 인증

사람이 기억하는 문자열

짧으면 무작위 대입 공격(Brute Force)에 뚫립니다. 인터넷에 열린 서버는 하루에도 수천 번 시도를 받습니다. PART 1에서 /var/log/auth.log로 그 흔적을 봤습니다.

키 인증

수학적으로 짝이 맞는 두 파일

개인키는 내 PC에만 두고, 공개키는 서버에 등록합니다. 키 없이는 접속할 수 없고, 비밀번호를 입력할 필요도 없습니다. 클라우드(AWS EC2 등)는 처음부터 이 방식만 씁니다.

파일어디에 두나성격
id_ed25519내 PC .ssh 폴더개인키 · 절대 남에게 주지 않는다. 유출되면 접속 권한을 잃는다
id_ed25519.pub서버 ~/.ssh/authorized_keys공개키 · 공개해도 안전하다. 자물쇠 역할
지금까지의 접속 multipass shell myUbuntu는 Multipass가 내부에서 대신 SSH 접속을 해 준 것입니다. 이 장에서는 그 과정을 직접 해 봅니다. 클라우드 서버에 접속할 때 하는 일과 똑같습니다.

① 키 만들기05
LAB · KEYGEN

내 PC에서 키 한 쌍을 만든다

Windows 10 이상에는 SSH 도구가 기본으로 들어 있어 PowerShell에서 바로 만들 수 있습니다.

Windows PowerShell내 PC
PS C:\Users\user> ssh -V # 설치 확인
OpenSSH_for_Windows_9.5p1 …
PS C:\Users\user> ssh-keygen -t ed25519 -C "myubuntu-key"
Enter file in which to save the key: (Enter — 기본 위치)
Enter passphrase: (Enter 또는 암호 입력)
Your identification has been saved in C:\\Users\\user/.ssh/id_ed25519
Your public key has been saved in C:\\Users\\user/.ssh/id_ed25519.pub
조각뜻
ssh-keygenSSH 키를 만드는 명령 (key generator)
-t ed25519키 종류(type). 짧고 빠르며 안전해 요즘 기본으로 쓴다. 예전 방식은 rsa
-C "메모"키에 붙이는 설명(comment). 어느 PC의 키인지 구분하는 용도
passphrase개인키 자체에 거는 암호. 비워도 되지만, 노트북 분실에 대비하려면 설정을 권한다

만들어진 파일 확인

Windows PowerShell내 PC
PS C:\Users\user> ls ~/.ssh
id_ed25519 ← 개인키 · 절대 밖으로 내보내지 않는다
id_ed25519.pub ← 공개키 · 서버에 등록할 것
PS C:\Users\user> cat ~/.ssh/id_ed25519.pub
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI… myubuntu-key
다음 단계 준비 위 cat 결과 한 줄 전체를 마우스로 긁어 복사해 두세요. ssh-ed25519로 시작해 메모로 끝나는 한 줄입니다. 이것을 서버에 등록합니다.
개인키는 복사하지 않는다 확장자가 없는 id_ed25519는 내 PC에만 둡니다. 서버에 올리는 것은 .pub가 붙은 공개키뿐입니다.

LAB · AUTHORIZED KEYS

서버의 authorized_keys에 붙여 넣는다

아직 SSH로는 못 들어가므로, 지금까지 쓰던 방법으로 서버에 접속합니다.

Windows PowerShell내 PC → 서버
PS C:\Users\user> multipass shell myUbuntu

1. .ssh 폴더 준비

ubuntu
ubuntu@myUbuntu:~$ mkdir -p ~/.ssh # 이미 있으면 그대로 둔다
ubuntu@myUbuntu:~$ chmod 700 ~/.ssh
ubuntu@myUbuntu:~$ ls -ld ~/.ssh
drwx------ 2 ubuntu ubuntu 4096 … /home/ubuntu/.ssh

2. 공개키 한 줄 추가

ubuntu
ubuntu@myUbuntu:~$ vim ~/.ssh/authorized_keys # 파일 끝으로 가서(G) o 를 누르고 붙여넣기
# 붙여넣기: 터미널 창에서 마우스 오른쪽 클릭
ubuntu@myUbuntu:~$ cat ~/.ssh/authorized_keys
ssh-rsa AAAAB3… ← Multipass가 넣어 둔 기존 키 (지우지 않는다)
ssh-ed25519 AAAAC3… myubuntu-key ← 방금 추가한 내 공개키

키는 한 줄에 하나씩 적습니다. 줄이 중간에 끊기면 인식되지 않습니다.

3. 권한 맞추기

ubuntu
ubuntu@myUbuntu:~$ chmod 600 ~/.ssh/authorized_keys
ubuntu@myUbuntu:~$ ls -l ~/.ssh/authorized_keys
-rw------- 1 ubuntu ubuntu 512 … /home/ubuntu/.ssh/authorized_keys
대상권한안 맞으면
~/.ssh700SSH가 “남이 볼 수 있는 상태”로 판단해 키를 무시하고 접속을 거부한다
~/.ssh/authorized_keys600
PART 1·2와 연결 홈의 .ssh가 처음부터 drwx------(700)이던 이유가 여기 있습니다.

여기까지 하고 exit로 서버에서 나옵니다. 다음 쪽에서 SSH로 다시 들어갑니다.

내 PC의 VS Code가 서버를 편집한다

내 PC
VS Code 화면SSH서버
VS Code Server›파일 · 터미널 · 실행
모두 서버 쪽

Remote-SSH는 서버에 VS Code Server라는 작은 프로그램을 자동으로 설치하고, 내 PC의 창은 그 화면만 보여 줍니다. 그래서 파일도 실행도 모두 서버에서 이루어집니다.

1. 확장 설치

  1. VS Code 왼쪽 Extensions(확장) 아이콘단축키 Ctrl+Shift+X
  2. Remote - SSH 검색 후 설치게시자가 Microsoft인 것을 고른다

2. 서버에 연결

  1. F1 또는 Ctrl+Shift+P명령 팔레트를 연다
  2. Remote-SSH: Connect to Host 입력A파트에서 만든 config를 읽어 myubuntu가 목록에 보인다
  3. myubuntu 선택새 창이 열리고, 처음에는 서버에 VS Code Server를 설치하느라 몇십 초 걸린다
  4. 왼쪽 아래 표시 확인초록색 칸에 SSH: myubuntu가 보이면 연결된 것이다
목록에 안 보이면 Remote-SSH: Add New SSH Host를 선택하고 ssh ubuntu@172.23.45.67처럼 직접 입력합니다. 그러면 config 파일에 자동으로 추가됩니다. 접속이 안 되면 PowerShell에서 ssh myubuntu가 되는지부터 확인합니다.

disk.pypython
import subprocess
from io import StringIO
import pandas as pd

# 1. 셸 명령을 실행해 결과를 문자열로 받는다
out = subprocess.run(["df", "-h"], capture_output=True, text=True).stdout

# 2. 첫 줄(제목)은 건너뛰고 컬럼 이름을 직접 지정
cols = ["fs", "size", "used", "avail", "use", "mount"]
df = pd.read_csv(StringIO(out), sep=r"\s+", skiprows=1, names=cols)

# 3. 실제 디스크만 남기고 사용률을 숫자로 변환
df = df[df["fs"].str.startswith("/dev")].copy()
df["use_pct"] = df["use"].str.rstrip("%").astype(int)

# 4. 사용률 높은 순으로 정렬해 출력하고 파일로 저장
df = df.sort_values("use_pct", ascending=False)
print(df[["fs", "size", "use_pct", "mount"]])
df.to_csv("disk_report.csv", index=False)

if (df["use_pct"] >= 90).any():
    print("경고: 사용률 90% 이상인 디스크가 있습니다")

import pandas as pd

path = "/var/log/auth.log"
records = []

with open(path, encoding="utf-8", errors="ignore") as f:
    for line in f:
        if "sshd" not in line:
            continue
        if "Accepted" in line:
            result = "성공"
        elif "Failed" in line:
            result = "실패"
        else:
            continue

        parts = line.split()
        user = parts[parts.index("for") + 1] if "for" in parts else "unknown"
        records.append({{"user": user, "result": result}})

df = pd.DataFrame(records)
print(df["result"].value_counts())
print(df.groupby(["user", "result"]).size())
df.to_csv("auth_report.csv", index=False)

실습 문제 풀이

풀이는 한 가지 예입니다. 확인 조건을 통과했다면 다른 방법도 정답입니다.

1. 서버 정보 확인

내 PC
PS C:\Users\user> multipass list

2. 키 상태 점검

내 PC → 서버
PS C:\Users\user> ls ~/.ssh
PS C:\Users\user> ssh myubuntu
ubuntu@myUbuntu:~$ cat ~/.ssh/authorized_keys

3. 권한 점검

서버
ubuntu@myUbuntu:~$ ls -ld ~/.ssh
ubuntu@myUbuntu:~$ ls -l ~/.ssh/authorized_keys
ubuntu@myUbuntu:~$ chmod 700 ~/.ssh
ubuntu@myUbuntu:~$ chmod 600 ~/.ssh/authorized_keys

4. 보고서 보내고 받기

서버 → 내 PC
ubuntu@myUbuntu:~$ cd ~/p3 && ./disk_check.sh
ubuntu@myUbuntu:~$ exit
PS C:\Users\user> scp myubuntu:~/p3/disk_*.txt .

5. 새 프로젝트 준비

서버
ubuntu@myUbuntu:~$ mkdir -p ~/p4/lab
ubuntu@myUbuntu:~$ cd ~/p4/lab
ubuntu@myUbuntu:~/p4/lab$ python3 -m venv .venv
ubuntu@myUbuntu:~/p4/lab$ source .venv/bin/activate

6. 어떤 파이썬을 쓰는지 확인

서버
ubuntu@myUbuntu:~/p4/lab$ which python3
/usr/bin/python3
(.venv) ubuntu@myUbuntu:~/p4/lab$ which python3
/home/ubuntu/p4/lab/.venv/bin/python3

7. 패키지 설치와 목록 남기기

서버
(.venv) ubuntu@myUbuntu:~/p4/lab$ pip install pandas
(.venv) ubuntu@myUbuntu:~/p4/lab$ pip freeze > requirements.txt

8. 같은 환경 다시 만들기

서버
(.venv) ubuntu@myUbuntu:~/p4/lab$ deactivate
ubuntu@myUbuntu:~$ mkdir -p ~/p4/lab2 && cd ~/p4/lab2
ubuntu@myUbuntu:~/p4/lab2$ python3 -m venv .venv
ubuntu@myUbuntu:~/p4/lab2$ source .venv/bin/activate
(.venv) ubuntu@myUbuntu:~/p4/lab2$ pip install -r ~/p4/lab/requirements.txt
(.venv) ubuntu@myUbuntu:~/p4/lab2$ pip list
