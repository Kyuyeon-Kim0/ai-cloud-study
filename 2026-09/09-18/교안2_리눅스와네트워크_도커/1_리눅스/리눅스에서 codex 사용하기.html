0. 학습 전제

이 교재는 Multipass Ubuntu 설치와 Linux 터미널 기초 학습이 완료되어 있다는 전제에서 시작한다. Python 개발보다 Linux 운영 명령을 Codex와 함께 사용하는 데 초점을 둔다.

1. Codex 작업 폴더부터 만든다

mkdir ~/codex_linux
cd ~/codex_linux

현재 위치와 자료를 확인한다.

pwd
ls -la
왜 폴더부터 만드는가?
Codex는 현재 작업 위치를 기준으로 프로젝트 파일을 읽고 작업한다. 따라서 먼저 “어디에서 Codex에게 일을 시킬 것인가”를 정한다.

2. Codex 실행

codex

처음 사용하는 계정/환경이라면 로그인 선택 화면이 나타날 수 있다.

번호방식의미
1Sign in with ChatGPT브라우저를 직접 사용할 수 있는 환경의 일반적인 ChatGPT 로그인
2Sign in with Device CodeMultipass처럼 브라우저가 없는 Linux에서 다른 브라우저를 이용해 인증
3Provide your own API keyAPI Key를 직접 사용하는 별도 방식
이 실습에서는 2번 Device Code 방식을 사용한다.
왜 2번인가?
Codex는 Multipass Ubuntu에서 실행하지만 로그인 화면은 Windows 브라우저에서 처리하는 것이 편하기 때문이다.

3. Device Code 인증 — 최초 실행의 핵심

2번을 선택하면 Ubuntu 터미널에 인증 페이지 주소와 일회용 Device Code가 표시된다.

예시

Open this URL in your browser:
https://auth.openai.com/codex/device

Enter this one-time code:
XXXX-XXXX
중요: XXXX-XXXX는 API Key가 아니며 ChatGPT의 “보안 키/패스키” 입력란에 넣는 값도 아니다. Codex 장치 인증 과정에서만 사용하는 일회용 Device Code다.

Windows 브라우저에서 진행

  1. Ubuntu 화면에 표시된 인증 링크를 Windows의 Chrome/Edge에서 연다.
  2. ChatGPT/OpenAI 계정으로 로그인한다.
  3. 계정에서 Codex의 장치 코드 인증 사용을 요구하면 안내에 따라 허용한다.
  4. 다시 Device 인증 페이지로 이동한다.
  5. Ubuntu 터미널에 표시된 일회용 Device Code를 코드 입력란에 입력한다.
  6. 연결을 승인한다.
  7. Ubuntu 터미널로 돌아온다.
Ubuntu Codex → Device Code 발급 → Windows 브라우저 → Codex 장치 인증 허용 → Device Code 입력 → 승인 → Ubuntu Codex 연결
왜 이런 과정을 거치는가?
Multipass Ubuntu 안에서 브라우저 로그인을 직접 처리하는 대신, 브라우저가 있는 Windows에서 사용자 인증을 완료하고 그 결과를 Ubuntu의 Codex CLI와 연결하기 위해서다.

인증이 막힌 경우

터미널에서 장치 코드 인증을 다시 시작할 필요가 있다면:

codex login --device-auth

화면에 새 링크와 새 Device Code가 표시되면 그 값을 사용한다.

Device Code는 일회용이며 만료될 수 있다. 수업 자료 캡처에는 실제 코드를 노출하지 말고 XXXX-XXXX처럼 가린다.

4. 인증 후 Codex 첫 작업 — 무조건 자료부터 확인

Codex에 바로 파일 생성을 지시하지 않는다. 먼저 현재 프로젝트를 확인하게 한다.

현재 작업 디렉터리의 모든 자료를 먼저 확인해줘.
ls -la를 사용해.

파일과 디렉터리가 무엇이 있는지 간단히 설명하고
아직 아무 파일도 수정하지 마.
왜 ls부터 시키는가?
사람과 Codex 모두 현재 프로젝트에 어떤 자료가 있는지 확인한 다음 작업해야 기존 파일을 불필요하게 덮어쓰거나 잘못된 위치에서 작업하는 것을 줄일 수 있다.

6. Codex 기본 지침 파일 — AGENTS.md 두 위치

파일적용 범위
~/.codex/AGENTS.md내 Codex 작업의 공통 지침
현재프로젝트/AGENTS.md현재 프로젝트에 적용할 지침
파일명이 두 종류인 것이 아니다. 둘 다 AGENTS.md이고 위치와 적용 범위가 다르다.

7. 모든 프로젝트 공통 AGENTS.md 만들기

~/.codex/AGENTS.md 가 모든 프로젝트에 적용할 사용자 공통 지침위치임

ubuntu@myUbuntu:~/codex_linux$ ls ~/. -la 로 .codex 폴더가 있는지 확인한다.

ls ~/.codex -la 로 목록리스트를 확인한다. 

cat > ~/.codex/AGENTS.md <<'EOF'
# Common Codex Rules

- 작업 전에 현재 디렉터리와 파일을 확인한다.
- Linux 명령을 실행하기 전에 왜 필요한지 설명한다.
- 답변은 짧고 단계적으로 작성한다.
- 삭제, 프로세스 종료, 서비스 중지는 사용자 확인 없이 실행하지 않는다.
- 시스템 점검은 조회 명령을 우선한다.
- 작업 후 무엇이 변경되었는지 알려준다.
EOF

반드시 확인한다.

cat ~/.codex/AGENTS.md

8. 현재 프로젝트 전용 AGENTS.md 만들기

작업 폴더로 돌아온다.

cd ~/codex_linux
ls -la
cat > AGENTS.md <<'EOF'
# Linux Codex Lab Rules

- 작업 시작 시 ls -la로 자료를 먼저 확인한다.
- Linux 명령어를 사용할 때 사용 이유를 설명한다.
- 기존 파일은 내용을 확인한 뒤 수정한다.
- rm 명령은 사용자 승인 없이 실행하지 않는다.
- CPU, 메모리, 디스크 상태는 조회 명령으로 먼저 조사한다.
EOF

확인:

ls -la
cat AGENTS.md

9. cat으로 AGENTS.md 추가·수정 실습

>는 새로 작성/덮어쓰기, >>는 기존 내용 뒤에 추가한다.

주의: 기존 파일에 >를 잘못 사용하면 기존 내용이 사라질 수 있다.

기존 AGENTS.md에 규칙 추가:

cat >> AGENTS.md <<'EOF'

- 로그 분석은 최근 기록부터 확인한다.
- 오류 발생 시 원인을 설명하고 다음 확인 명령을 제안한다.
EOF

cat AGENTS.md

10. Codex에게 AGENTS.md를 수정시키기

codex

Codex에게:

먼저 ls -la로 현재 프로젝트의 모든 자료를 확인해줘.

AGENTS.md가 있으면 내용을 확인해줘.

다음 규칙을 기존 AGENTS.md에 추가해줘.

- 시스템 변경 명령보다 조회 명령을 먼저 사용한다.
- 위험한 작업은 실행 전에 사용자에게 알려준다.

기존 내용은 삭제하지 마.

작업 후 직접 검증:

cat AGENTS.md
ls -la → AGENTS.md 확인 → Codex 수정 → cat으로 사람이 검증

12-1. Linux 운영 실습 샘플1

Codex에게:

현재 Linux 시스템 상태를 조사하려고 해.

1. CPU, 메모리, 디스크 순으로 확인해줘.
2. 사용할 Linux 명령어를 먼저 알려줘.
3. 각 명령을 왜 사용하는지 설명해줘.
4. 아직 삭제, 종료, 설정 변경은 하지 마.

예상되는 조회 명령 예:

uptime
free -h
df -h
ps aux --sort=-%cpu | head
ps aux --sort=-%mem | head

12-2. Linux 운영실습 샘플2

서버가 갑자기 느려졌다: 평소에는 괜찮았는데 Ubuntu가 갑자기 느려졌다. 원인은 모른다.

느리다 → 원인 가설 → 확인 → 범위 좁히기

Codex에게:

현재 Linux 시스템 상태를 조사하려고 해.

현재 Linux 시스템이 평소보다 느리다.
트러블슈팅 방식으로 원인을 조사해줘.

조건:
1. 먼저 원인 후보를 생각해줘.
2. CPU, 메모리, 디스크, 프로세스 상태를 순서대로 조사해줘.
3. Linux 명령을 실행하기 전에 왜 사용하는지 설명해줘.
4. 한꺼번에 모든 명령을 실행하지 말고 결과를 보고 다음 조사를 결정해줘.
5. 프로세스 종료나 시스템 설정 변경은 하지 마.

예상되는 조회 명령 예:

uptime
free -h
df -h
ps aux --sort=-%cpu | head
ps aux --sort=-%mem | head

12-3. Linux 운영실습 샘플3

디스크 용량이 부족하다:Linux를 사용하다 보니 디스크 공간이 부족한 것 같다. 어떤 파일이 문제인지는 모른다.

느리다 → 원인 가설 → 확인 → 범위 좁히기

Codex에게:

현재 Linux 시스템의 디스크 공간이 부족한 것 같다.

트러블슈팅 방식으로 조사해줘.

조건:
1. 먼저 전체 디스크 상태를 확인해줘.
2. 문제가 있는 영역을 찾으면 범위를 단계적으로 좁혀줘.
3. 각 명령을 왜 사용하는지 실행 전에 설명해줘.
4. 큰 파일이나 디렉터리를 찾더라도 삭제하지 마.
5. 한 단계 결과를 확인한 후 다음 명령을 결정해줘.

예상되는 조회 명령 예:

df -h  #어느 파일 시스템이 큰지 확인
sort
find  
 ==>등을 조합해서 원인을 좁혀가는지를 확인해봄
