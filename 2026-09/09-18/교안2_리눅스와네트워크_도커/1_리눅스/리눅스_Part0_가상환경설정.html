시작하기 전에02
BEFORE START

실무의 축소판을 노트북 안에

MISSION

실무에서 리눅스 서버를 쓰는 흐름과, 이 교재에서 만들 구조를 비교한다.

WHY 실무에서 리눅스는 내 노트북에 설치하는 것이 아니라 가상 머신 위의 서버에 원격 접속해서 씁니다. 이 교재는 그 구조를 노트북 한 대로 만듭니다.

실무에서는

내 노트북 (Windows · Mac)→ SSH →클라우드 VM (AWS · Azure …)·그 안의 리눅스

이 교재에서는

PowerShell (Windows 10 Pro)→ multipass shell →Hyper-V 가상 컴퓨터·그 안의 우분투 서버
SSHSecure Shell
네트워크로 떨어져 있는 서버에 암호화된 연결로 접속해 명령어를 입력하는 방법입니다. 실무의 서버 작업은 대부분 SSH로 합니다. 이 교재에서는 SSH를 직접 다루지 않고, Multipass가 SSH 연결을 대신 만들어 주는 multipass shell로 접속합니다.

클라우드로 넘어가면 달라지는 것은 VM을 만드는 화면과 접속 방법(SSH)이고, 리눅스 명령어는 그대로 씁니다. 참고로 Azure는 Hyper-V 기반입니다.

명령어를 입력하는 두 곳

윈도우 PowerShell (관리자)
PS C:\WINDOWS\system32>
multipass 명령어로 서버를 만들고, 켜고, 끄고, 접속합니다.
우분투 서버 안
ubuntu@myUbuntu:~$
ls, apt, sudo 같은 리눅스 명령어를 여기서 입력합니다.

가상 머신(VM)이란03
CONCEPT

소프트웨어로 만든 컴퓨터, VM

MISSION

VM이 무엇이고, 실제 컴퓨터와 무엇이 다른지 설명할 수 있다.

WHY 클라우드 엔지니어에게 VM은 모든 클라우드 인프라의 기초 공사입니다. 클라우드가 자원을 어떻게 나누고 운영하는지 이해하는 출발점입니다.

VM(Virtual Machine, 가상 머신)은 실제 컴퓨터처럼 동작하도록 소프트웨어로 만든 가상의 컴퓨터입니다. Windows, Linux, Windows Server를 실제 PC처럼 설치하고 실행할 수 있습니다.

VM이 갖춘 부품

vCPU

가상 CPU

실제 CPU 코어를 나눠 받음

vRAM

가상 메모리

실제 RAM 일부를 할당

vDISK

가상 하드디스크

실제로는 파일 하나 (.vhdx)

vNIC

가상 네트워크 카드

가상 스위치에 연결

실제 컴퓨터와 비교

구분실제 컴퓨터VM
하드웨어실제 부품가상 부품 (실제 자원을 빌려 씀)
OS 설치보통 1개한 PC에 여러 개 동시에 가능
고장 시수리 · 재설치가 위험하고 번거로움삭제하거나 검사점으로 되돌리면 끝
용도실사용실습 · 테스트 · 서버 운영

VM을 쓰는 경우

  • 윈도우에서 리눅스를 쓰고 싶을 때처럼 서로 다른 OS가 필요할 때
  • 실제 컴퓨터와 완벽하게 격리해야 할 때 (예: 악성코드 분석, 검증 안 된 프로그램 테스트)
  • 한 대의 PC로 회사 서버 환경을 그대로 연습할 때
노트북 한 대 ├─ VM 1 Windows Server (AD 서버) ├─ VM 2 Windows 10 (클라이언트) └─ VM 3 Linux 서버 ← 이 교재에서 만드는 것

가상화 소프트웨어04
HYPERVISOR

VM을 돌리는 엔진, 하이퍼바이저

가상화 소프트웨어는 한 대의 물리 컴퓨터 자원(CPU, 메모리, 디스크, 네트워크)을 논리적으로 나눠 여러 VM이 각각 독립된 컴퓨터처럼 동작하게 합니다. 하드웨어를 직접 다루는 이 소프트웨어를 하이퍼바이저(Hypervisor)라고 부릅니다.

VM 1 (Windows Server) VM 2 (Linux) VM 3 (Windows 10) ↑ 자원을 나눠 받음 가상화 소프트웨어 (Hypervisor) ↑ 하드웨어 (CPU / RAM / Disk / NIC) 한 대의 서버 = 여러 대의 서버처럼

설치 위치에 따른 두 가지 유형

TYPE 1 · 베어메탈 (Bare-Metal)

하드웨어 바로 위에 설치. 중간 OS가 없어 성능과 안정성이 뛰어나 데이터센터 · 기업 서버에서 사용합니다.

  • VMware ESXi 기업용 업계 표준
  • Microsoft Hyper-V 윈도우에 내장, Azure의 기반
  • KVM 리눅스 커널 기반, 많은 클라우드의 핵심
  • Xen 과거 AWS가 주력으로 사용
TYPE 2 · 호스트형 (Hosted)

이미 쓰는 OS(Windows, macOS) 위에 앱처럼 설치. 학습 · 개발용으로 많이 씁니다.

  • Oracle VirtualBox 무료, 다양한 OS 지원
  • VMware Workstation / Fusion 기능이 풍부
  • Parallels Desktop Mac에서 윈도우 실행용
Hyper-V가 TYPE 1인 이유

Hyper-V를 켜면 하이퍼바이저가 하드웨어 바로 위에서 먼저 실행되고, 우리가 쓰는 윈도우도 그 위의 특별한 구역(루트 파티션)에서 돌아갑니다. 그래서 윈도우 기능으로 켜지만 데이터센터용과 같은 구조입니다.

컨테이너 가상화

OS 전체가 아니라 애플리케이션 실행 환경만 격리하는 방식입니다. Docker(대표), LXC(리눅스 시스템 수준), Podman(보안 강점) 등이 있습니다.

비교Type 1 (서버용)Type 2 (학습용)컨테이너 (실무형)
대표 예시Hyper-V, KVM, ESXiVirtualBox, VMware WorkstationDocker, Podman
주요 용도실제 서비스 운영개인 학습, 개발 테스트마이크로서비스 배포
핵심 이점높은 성능과 격리성간편한 설치와 사용가벼움, 빠른 배포

클라우드 엔지니어가 VM을 알아야 하는 이유

01

하이퍼바이저의 이해

구조를 알아야 성능 병목을 진단하고, 물리 서버 한 대를 얼마나 쪼개 쓸지(밀도) 결정할 수 있습니다.

02

비용 최적화 (FinOps)

AWS EC2, Azure VM, GCP Compute Engine 비용은 어떤 사양의 VM을 얼마나 오래 띄우느냐로 정해집니다.

03

확장성과 가용성

VM은 이미지로 저장·복제됩니다. 부하가 커질 때 같은 VM을 자동으로 늘리는 오토 스케일링의 바탕입니다.

04

컨테이너와의 차이

컨테이너도 결국 VM 위에서 도는 경우가 많습니다. 언제 VM을, 언제 컨테이너를 쓸지 판단하려면 둘 다 알아야 합니다.

리눅스와 배포판07
LINUX

리눅스는 하나인데 종류는 여러 개?

MISSION

커널과 배포판의 차이를 알고, 주요 배포판 계열을 구분한다.

WHY 클라우드에서 서버를 만들 때 가장 먼저 어떤 리눅스(이미지)를 고릅니다. 계열마다 설치 방법이 다릅니다.

커널과 배포판

리눅스 커널Kernel
운영체제의 심장. CPU · 메모리 · 디스크 · 네트워크 같은 하드웨어를 직접 관리합니다. 1991년 리누스 토르발스가 만들었고, 엄밀히 말해 ‘리눅스’는 이 커널의 이름입니다.
배포판Distribution
커널에 명령어 도구 · 패키지 관리자 · 설치 프로그램 · 기본 설정을 묶어 바로 쓸 수 있게 만든 완성품. 우분투가 대표적인 배포판입니다.
리눅스 커널+명령어 도구+패키지 관리자+설치 · 설정=배포판 (예: Ubuntu)

비유하면 커널은 자동차 엔진, 배포판은 엔진을 얹어 완성한 차 모델입니다. 엔진은 같아도 회사마다 차의 구성과 조작법이 조금씩 다릅니다.

주요 배포판 계열

계열대표 배포판패키지 관리특징
Debian 계열Ubuntu, Debian, Linux Mintapt · .deb자료가 가장 많고 클라우드 · 교육에서 널리 사용
Red Hat 계열RHEL, Rocky, AlmaLinux, Fedora
(지원 종료된 CentOS의 후속)		dnf(yum) · .rpm기업 · 금융권 서버에서 많이 사용. RHEL은 유료 지원
클라우드 전용Amazon Linuxdnf · .rpmAWS가 만든 배포판. Red Hat 계열과 사용법이 비슷
경량Alpine Linuxapk매우 작아서 Docker 컨테이너 이미지로 많이 사용
이 교재가 우분투를 쓰는 이유

무료이고, 클라우드에서 기본 이미지로 흔히 제공되며, 자료가 많습니다. 익힌 명령어 대부분은 다른 배포판에서도 같고, 패키지 설치 명령(apt ↔ dnf)만 다릅니다.

24.04 LTS는 무슨 뜻일까?

우분투는 캐노니컬(Canonical)이 만드는 배포판으로(Multipass도 같은 회사), 매년 4월과 10월에 새 버전이 나옵니다.

속도 (GHz)

Hz(헤르츠)는 1초에 몇 번 반복하는지를 나타내는 단위이고, GHz(기가헤르츠)는 1초에 10억 번입니다. CPU는 시계처럼 일정한 박자(클럭)에 맞춰 일하는데, 2.65GHz는 1초에 약 26억 5천만 번 박자를 맞춘다는 뜻입니다.

기본 속도 2.80GHz제품 규격
이 CPU(i7-1165G7)에 정해진 기준 속도입니다.
속도 2.65GHz지금 이 순간
한가할 때는 전기를 아끼려고 낮추고, 바쁠 때는 터보 부스트로 기본 속도보다 높입니다(이 CPU는 최대 4.7GHz). 그래서 계속 바뀝니다.

GHz는 같은 세대 CPU끼리 비교할 때만 의미가 있습니다. 세대가 다르면 박자 한 번에 처리하는 양이 달라서, 숫자가 낮아도 더 빠를 수 있습니다.

L1 · L2 · L3 캐시

캐시는 CPU 안의 아주 빠르고 작은 메모리로, 자주 쓰는 데이터를 가까이 두어 RAM까지 가는 시간을 줄입니다.

L2 캐시5.0MB코어마다 (1.25MB × 4)빠름 · 작음책상 위
L3 캐시12.0MB모든 코어 공용조금 느림 · 조금 큼사무실 공용 책장

VM과 연결하면

Hyper-V와 Multipass가 VM에 나눠 주는 CPU(vCPU)는 이 논리 프로세서 단위입니다. STEP 3의 --cpus 2는 논리 프로세서 8개 중 2개 분량을 쓴다는 뜻이라, 한 VM에는 최대 8개까지 줄 수 있고, 여러 VM의 합계가 8을 넘으면 서로 나눠 쓰느라 느려집니다. 클라우드 vCPU도 보통 논리 프로세서 1개입니다.

SUDO · APT

관리자 권한과 프로그램 설치

MISSION

sudo가 무엇인지, 우분투에서 프로그램을 설치하는 apt가 어떻게 동작하는지 설명할 수 있다.

WHY 서버를 받으면 가장 먼저 하는 일이 업데이트와 필요한 프로그램 설치입니다. 웹 서버, 데이터베이스, 파이썬 모두 이 방법으로 설치합니다.

sudo — 잠깐 관리자 권한 빌리기

root최고 관리자
리눅스에서 모든 것을 할 수 있는 계정입니다. 시스템 파일을 지우는 것도 막지 않기 때문에 평소에는 root로 일하지 않습니다.
sudosuperuser do
일반 사용자가 명령 하나만 root 권한으로 실행하게 해 줍니다. 명령 앞에 붙여 씁니다. 누가 언제 sudo를 썼는지 기록이 남습니다.
sudo 없이 설치하면
$ apt install cowsay
E: Could not open lock file … (13: Permission denied)
E: Unable to acquire the dpkg frontend lock …, are you root?
“관리자(root)냐?”고 되묻으며 거절합니다.
sudo를 붙이면
$ sudo apt install cowsay
root 권한으로 실행되어 설치됩니다.
sudo가 필요한 일sudo가 필요 없는 일
프로그램 설치 · 삭제 · 업데이트파일 목록 보기 (ls), 위치 확인 (pwd)
시스템 설정 파일 수정 (/etc 아래)내 홈 폴더(/home/ubuntu) 안의 파일 만들기 · 수정
서비스 시작 · 중지, 서버 끄기 (sudo poweroff)상태 확인 (df -h, free -h)
비밀번호를 묻지 않는 이유 보통 sudo는 내 비밀번호를 한 번 묻습니다. Multipass가 만든 ubuntu 계정은 클라우드 서버처럼 비밀번호 없이 sudo를 쓰도록 미리 설정되어 있습니다.
sudo는 확인 없이 실행됩니다. 특히 sudo rm(삭제)은 되돌릴 수 없습니다. 명령을 한 번 더 읽고 Enter를 누르는 습관을 들입니다.

apt — 우분투의 앱스토어

리눅스는 배포판이 운영하는 저장소에서 패키지로 프로그램을 받아 설치합니다. 우분투(Debian 계열)는 apt(Advanced Package Tool), Red Hat 계열은 dnf가 맡습니다(07쪽).

서버의 주소, IP22
IP ADDRESS

서버에도 주소가 있다

MISSION

multipass list에 보이는 IPv4가 무엇인지 설명할 수 있다.

WHY 네트워크의 모든 컴퓨터는 주소를 가집니다. 여기서는 개념만 간단히 봅니다.

IP 주소란

IP 주소는 네트워크 안에서 컴퓨터를 구분하는 집 주소입니다. 172.25.30.12처럼 0~255 사이 숫자 4개를 점으로 이어 쓰며, 이런 형식을 IPv4라고 합니다.

내 서버의 IP 보기

PowerShell밖에서 보기
PS> multipass list Name State IPv4 Image myUbuntu Running 172.xx.xx.xx Ubuntu 24.04 LTS
Ubuntu · myUbuntu안에서 보기
$ hostname -I 172.xx.xx.xx ← 밖에서 본 값과 같음

기억할 세 가지

AUTO

자동으로 받는다

서버를 만들 때 Hyper-V의 Default Switch가 주소를 자동으로 나눠 줍니다. 직접 정할 필요가 없습니다.

PRIVATE

내 노트북 안에서만 통한다

172.…은 내부용(사설) 주소입니다. 내 노트북과 VM 사이에서만 쓰이고, 다른 사람의 컴퓨터에서는 찾아올 수 없습니다.

CHANGE

바뀔 수 있다

노트북을 재부팅하면 주소가 달라질 수 있습니다. 필요할 때마다 multipass list로 다시 확인합니다.

Ubuntu · myUbuntu~
$ ping -c 3 ubuntu.com # 3번만 신호를 보내 봄 3 packets transmitted, 3 received, 0% packet loss ← 인터넷 연결 정상

VM은 노트북의 인터넷을 함께 씁니다. STEP 5에서 apt가 패키지를 받아 온 이유입니다. 네트워크 방식과 고정 IP는 네트워크 단원에서 다룹니다.
