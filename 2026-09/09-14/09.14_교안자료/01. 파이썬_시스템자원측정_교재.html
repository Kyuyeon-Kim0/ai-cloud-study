MISSION

WHY 이 세 가지가 마지막 결과물의 뼈대입니다. 문법을 다 알 필요는 없고, 측정 한 줄 = 딕셔너리 하나라는 구조만 잡으면 됩니다.

내 프로세스만 보기

전체 사용률은 다른 프로그램의 영향을 받습니다. 내가 돌린 코드가 얼마나 쓰는지 보려면 내 프로세스를 지정해야 합니다.

현재 프로세스 측정PYTHON
import os, psutil proc = psutil.Process(os.getpid()) # 지금 이 파이썬 프로세스 # RSS — 실제로 물리 메모리에 올라와 있는 양 mem_mb = proc.memory_info().rss / 1024**2 print(round(mem_mb, 1), "MB") # 이 프로세스의 CPU 사용률 proc.cpu_percent(interval=None) # 첫 호출은 기준점 (0.0 반환) # ... 작업 수행 ... print(proc.cpu_percent(interval=None)) # 두 번째부터 의미 있는 값
cpu_percent 는 두 번 불러야 합니다  첫 호출은 기준점을 잡는 것이라 항상 0.0이 나옵니다. 두 번째 호출에서 그 사이의 사용률을 돌려줍니다. 이걸 모르면 “CPU가 0%로만 나온다”에서 막힙니다.

다른 프로세스도 볼 수 있습니다

프로세스 목록 — 작업 관리자에 해당PYTHON
import psutil rows = [] for p in psutil.process_iter(["pid", "name", "memory_info"]): try: rows.append({ "pid": p.info["pid"], "name": p.info["name"], "mem_mb": round(p.info["memory_info"].rss / 1024**2, 1), }) except (psutil.NoSuchProcess, psutil.AccessDenied): continue # 사라졌거나 권한 없는 프로세스는 건너뜀 top = sorted(rows, key=lambda r: r["mem_mb"], reverse=True)[:5] for r in top: print(r["name"], r["mem_mb"], "MB")
그림 1-1 작업 관리자에서 메모리 열을 눌러 정렬한 것과 같은 결과입니다. 다른 점은 이 결과를 파일로 남기고 매일 비교할 수 있다는 것입니다.
try / except 가 필요한 이유  프로세스 목록을 도는 중에 프로세스가 종료되거나 권한이 없을 수 있습니다. 그러면 예외가 나고 프로그램이 멈춥니다. 시스템을 다루는 코드에서는 “있을 수 있는 실패”를 미리 처리하는 것이 기본입니다.

measure.py — 이후 STEP에서 계속 importPYTHON
import os, csv, time, psutil from datetime import datetime PROC = psutil.Process(os.getpid()) def to_mb(v): return round(v / 1024**2, 1) def measure(func, target="", action="", lib="", width="", height=""): """func 을 실행하면서 메모리·CPU·시간을 측정해 딕셔너리로 돌려준다.""" PROC.cpu_percent(interval=None) # 기준점 before = to_mb(PROC.memory_info().rss) t0 = time.perf_counter() result = func() # ← 실제 작업 elapsed = time.perf_counter() - t0 after = to_mb(PROC.memory_info().rss) cpu = PROC.cpu_percent(interval=None) row = { "time": datetime.now().strftime("%Y-%m-%d %H:%M:%S"), "target": target, "action": action, "lib": lib, "width": width, "height": height, "mem_before_mb": before, "mem_after_mb": after, "mem_delta_mb": round(after - before, 1), "cpu_pct": cpu, "elapsed_s": round(elapsed, 3), } return row, result
함수를 값으로 넘깁니다

measure(func)에서 func은 실행 결과가 아니라 함수 자체입니다. 괄호 없이 이름만 넘기고, 측정 안에서 func()으로 실행합니다. 이렇게 하면 무엇을 측정하든 같은 함수를 씁니다.

메서드 두 개만 추가하면 with 문에서 쓸 수 있습니다. __enter__는 들어갈 때, __exit__은 나갈 때 반드시 실행됩니다.

ResourceLogger — 최종 형태PYTHON
class ResourceLogger: def __init__(self, path="logs/resource_log.csv"): self.path = path self.rows = [] self.proc = psutil.Process(os.getpid()) def __enter__(self): return self # with ... as logger 의 logger def __exit__(self, exc_type, exc_value, tb): self.save() # 오류가 나도 실행됩니다 return False # 오류는 숨기지 않고 그대로 전달 def measure(self, func, **info): self.proc.cpu_percent(interval=None) before = to_mb(self.proc.memory_info().rss) t0 = time.perf_counter() result = func() elapsed = time.perf_counter() - t0 after = to_mb(self.proc.memory_info().rss) row = {"time": datetime.now().strftime("%Y-%m-%d %H:%M:%S"), "mem_before_mb": before, "mem_after_mb": after, "mem_delta_mb": round(after - before, 1), "cpu_pct": self.proc.cpu_percent(interval=None), "elapsed_s": round(elapsed, 3)} row.update(info) # target, lib, width, height ... self.rows.append(row) return result def save(self): for r in self.rows: append_row(r, self.path)

**info는 이름이 붙은 나머지 인자를 전부 받는 표기입니다. target=, lib=처럼 넘긴 것이 딕셔너리로 들어와 그대로 열에 채워집니다.

카메라가 안 열림다른 프로그램(화상회의 앱)이 점유 중이거나 앞 실행에서 반납 안 됨. 프로그램을 닫고 다시 시도
첫 프레임이 유독 느림카메라 초기화 시간. 앞 몇 프레임은 통계에서 제외하는 것이 맞습니다
검은 화면만 나옴카메라 권한 차단. Windows 설정 → 개인정보 → 카메라 확인
창이 닫히지 않음destroyAllWindows()가 실행되지 않은 경우. with를 쓰면 해결됩니다
메모리가 계속 오름프레임을 리스트에 쌓고 있지 않은지 확인. 측정값만 쌓고 이미지는 버려야 합니다
이미지를 모아 두면 안 됩니다  프레임 한 장이 1280×720×3 ≈ 2.6MB입니다. 200장을 리스트에 담으면 500MB가 넘습니다. 측정 목적이라면 숫자만 남기고 이미지는 버립니다.
