네트워크란
기기끼리 연결해 자원을 나눠 쓰는 것이다

왜 배워야 하나?

우리는 매일 네트워크를 씁니다. 사무실 프린터로 인쇄하고, 공유 폴더에서 파일을 열고, 휴대폰으로 메신저를 보냅니다. 이 모든 일이 어떻게 연결되어 있는지를 알아야 “안 될 때” 어디를 볼지 알 수 있습니다.

네트워크(Network)는 둘 이상의 기기가 케이블이나 전파로 연결되어 데이터를 주고받는 구조입니다. 연결하는 이유는 하나, 혼자서는 없는 자원을 함께 쓰기 위해서입니다.

PRINTER

프린터 공유

사무실 프린터 한 대를 PC 여러 대가 네트워크로 함께 씁니다.

FILE

파일 공유

공유 폴더·NAS에 올린 파일을 팀원 모두가 엽니다.

INTERNET

인터넷 공유

공유기 하나로 가족의 휴대폰·TV·노트북이 모두 인터넷에 연결됩니다.

SERVICE

서비스 이용

웹, 메일, 메신저, 게임은 모두 멀리 있는 서버와 데이터를 주고받습니다.

REMOTE

원격 접속

화면 없는 클라우드 서버를 SSH로 접속해 관리합니다.

IoT

사물 연결

CCTV, 스마트 TV, 센서도 네트워크에 붙은 기기입니다.

비트와 바이트
컴퓨터가 이해하는 최소 단위부터 시작한다

왜 배워야 하나?

네트워크 대역폭(10Mbps, 100Mbps, 1Gbps)은 초당 몇 비트를 전송하는지 나타냅니다. IP 주소는 32비트이고, 서브넷 마스크도 비트 단위로 계산합니다. 비트를 모르면 네트워크 구성을 이해할 수 없습니다.

비트(Bit) — 컴퓨터가 이해하는 최소 단위

컴퓨터는 전기 신호를 통해 데이터를 처리합니다.

  • 비트(Bit) = 0 또는 1
  • 전압이 있음 = 1
  • 전압이 없음 = 0

한 개의 비트로는 2가지 상태만 표현할 수 있습니다. 더 많은 정보를 담으려면 비트를 모아야 하며, 비트가 하나 늘 때마다 표현할 수 있는 상태는 2배가 됩니다(n비트 = 2ⁿ가지).

비트 개수표현 가능한 상태예시
1 bit2가지 (0, 1)LED 켜짐/꺼짐
2 bit4가지 (00, 01, 10, 11)신호등 (빨강, 노랑, 초록, 꺼짐)
3 bit8가지주사위 눈 1~6 (6가지를 담으려면 3비트 필요)
8 bit256가지영문 한 글자, RGB 색상 한 채널
32 bit약 43억 가지IPv4 주소 전체 개수
bps와 B/s

대역폭 단위의 b(소문자)는 bit, 파일 크기의 B(대문자)는 Byte입니다. 1Gbps 회선의 이론상 최대 속도는 1,000,000,000 ÷ 8 = 약 125MB/s입니다.

사람의 숫자를 장비의 숫자로 바꾼다

왜 배워야 하나?

IPv4 주소 192.168.1.1은 사람이 읽기 좋은 10진수 표기법입니다. 하지만 네트워크 장비는 2진수로 처리합니다. IP 주소, 서브넷 마스크, CIDR를 다루려면 진법 변환이 필수입니다.

10진수와 2진수의 관계

10진수Decimal
우리가 일상에서 사용하는 진법. 0~9의 10개 숫자를 사용합니다.
2진수Binary
컴퓨터가 이해하는 진법. 0과 1 두 개의 숫자만 사용합니다. 자리마다 1, 2, 4, 8, 16 … 처럼 2배씩 커집니다.
10 → 2

10진수를 2진수로

방법: 계속 2로 나누고 나머지를 모으기

예: 13을 2진수로

13 ÷ 2 = 6 ... 1
6 ÷ 2 = 3 ... 0
3 ÷ 2 = 1 ... 1
1 ÷ 2 = 0 ... 1

결과: 1101₂ (아래에서 위로)
2 → 10

2진수를 10진수로

방법: 각 자리에 2의 거듭제곱을 곱하기

예: 1101을 10진수로

1×2³ + 1×2² + 0×2¹ + 1×2⁰
= 1×8 + 1×4 + 0×2 + 1×1
= 8 + 4 + 0 + 1

결과: 13₁₀

16진수
2진수 4자리를 한 글자로 줄여 쓴다

왜 배워야 하나?

2진수는 사람이 읽기엔 너무 깁니다. 그래서 MAC 주소, IPv6 주소, 앞 실습의 printf '%x' 결과(c0)는 모두 16진수로 표기합니다. 16진수를 모르면 5장의 IPv6 주소를 읽을 수 없습니다.

16진수(Hexadecimal)는 0~9와 A(10)·B(11)·C(12)·D(13)·E(14)·F(15), 16개 기호를 쓰는 진법입니다. 자리마다 16배씩 커지며, 10진수와 구분하려고 앞에 0x를 붙입니다(0xC0). 대소문자는 구분하지 않습니다. 핵심은 2진수 4자리 = 16진수 1자리입니다.

16진수01234567
10진수01234567
2진수00000001001000110100010101100111
16진수89ABCDEF
10진수89101112131415
2진수10001001101010111100110111101111
2 → 16 · 4자리씩 끊기
192 = 1100 0000₂
1100 → C · 0000 → 0 → 0xC0
16 → 10 · 자릿값 곱하기
0xC0 = 12×16 + 0 = 192
0xFF = 15×16 + 15 = 255

IPv6 주소2001:0db8:85a3:0000:0000:8a2e:0370:73341그룹 = 16진수 4자리(16비트)
× 8그룹 = 128비트

패킷(Packet)
데이터는 조각으로 나뉘어 네트워크를 건넌다

왜 배워야 하나?

ping, traceroute 같은 네트워크 진단 도구는 패킷을 보냅니다. 패킷의 구조를 이해해야 네트워크 통신을 디버깅할 수 있습니다.

패킷이란 무엇인가?

패킷(Packet)은 네트워크를 통해 전송되는 데이터의 단위입니다. 편지처럼 ‘보낸이 주소’, ‘받는이 주소’, ‘내용’을 담고 있습니다.

헤더(Header)+데이터(Payload)+트레일러(Trailer) · 이더넷 프레임
요소포함 정보예시 크기
헤더출발지 IP, 목적지 IP, 프로토콜, TTL20 바이트 (IPv4 기본)
데이터실제 전송할 내용최대 65,515 바이트 (IPv4 패킷 최대 65,535 − 헤더)
트레일러에러 검사 정보 (FCS·CRC) · 이더넷 프레임에 실릴 때 붙음4 바이트

→ 패킷 데이터: "Hello" (5바이트)

MTU (Maximum Transmission Unit)

네트워크는 한 번에 보낼 수 있는 패킷의 최대 크기를 제한합니다. 이를 MTU라 합니다.

  • 이더넷(Ethernet): 1,500 바이트 (표준)
  • 점보 프레임(Jumbo Frame): 9,000 바이트 (고성능 네트워크)

MTU보다 큰 데이터를 보낼 때는 여러 패킷으로 나뉘어 전송됩니다.

IPv4 주소란?

IPv4 주소는 32비트의 숫자로, 4개의 8비트(1바이트) 옥텟으로 표현합니다. 각 옥텟은 0~255의 10진수입니다.

형식: a.b.c.d
범위: 0.0.0.0 ~ 255.255.255.255
예시: 192.168.1.1
2진수: 11000000.10101000.00000001.00000001

왜 배워야 하나?

집의 wifi 라우터는 192.168.x.x 사설 IP를 사용하고, 외부 인터넷은 공인 IP로 연결됩니다. 두 가지의 주소 체계를 이해해야 실무 네트워크 설정을 할 수 있습니다.

공인 IP (Public IP)

공인 IP는 공용 인터넷에서 라우팅 가능한 주소입니다. 다만 공인 IP라고 누구나 접근할 수 있는 것은 아니며, 방화벽·라우팅·서비스 실행 상태에 따라 접근이 막힐 수 있습니다. 주소는 IANA(Internet Assigned Numbers Authority)에서 관리합니다.

  • 인터넷 서비스 제공자(ISP)에서 할당
  • 웹 서버, 메일 서버 같은 공개 서비스에 사용
  • 고가(과거에는 매우 비쌈)
확인 방법

curl ifconfig.me 또는 wget -qO- ifconfig.me로 본인의 공인 IP를 확인할 수 있습니다.

사설 IP (Private IP)

사설 IP는 공용 인터넷에서 라우팅되지 않는 주소입니다. 조직 내부 네트워크에서만 사용되며, RFC 1918에서 정의되었습니다.

C192.168.0.0 ~ 192.168.255.255약 65,000가정, 소규모

사설 IP는 여러 조직에서 중복하여 사용 가능합니다. 예를 들어, 당신의 집과 회사 모두 192.168.1.1을 사용할 수 있습니다.

③ 안쪽 기기는 모두 “게이트웨이” 한 곳을 통해 밖으로 나간다

공인 IP는 외부에 꼭 보여야 하는 곳(웹 서버 앞 로드밸런서 등)에만 쓰고, 나머지 서버는 사설 IP + NAT로 둡니다. 비용도 줄고, 외부에 노출되는 서버가 줄어 보안에도 유리합니다. 주소가 넉넉한 IPv6(5장)은 이 부담이 적습니다.

ping의 원리

ICMP (Internet Control Message Protocol)를 사용하여 에코 요청을 보내고 응답을 기다립니다.

동작:

  1. A 컴퓨터가 B 컴퓨터에 "응답 가능하니?" (ICMP Echo Request)
  2. B 컴퓨터가 "응답합니다" (ICMP Echo Reply)
  3. A는 응답 시간과 성공 여부를 출력

왜 배워야 하나?

ping이 "연결되니?"를 확인한다면, traceroute는 "어떤 경로로 연결되니?"를 보여줍니다. 특정 라우터에서 느려지는 문제를 진단할 수 있습니다.

TTL (Time To Live)

TTL은 패킷이 몇 개의 라우터를 거칠 수 있는지를 정합니다. 라우터를 거칠 때마다 1씩 감소하고, 0이 되면 패킷이 폐기됩니다.

동작 원리:
  1. TTL=1로 설정 → 첫 라우터에서 폐기 → 응답 수신 (1번째 홉)
  2. TTL=2로 설정 → 두 번째 라우터에서 폐기 → 응답 수신 (2번째 홉)
  3. TTL=30 정도까지 반복 → 경로의 모든 라우터 파악

IPv6 주소 구조

왜 배워야 하나?

IPv4는 42억 개 주소만 제공하지만, 현재 세계 인구와 IoT 기기 수는 이를 훨씬 초과했습니다. IPv6은 128비트로 거의 무한한 주소 공간을 제공하며, 점차 일상화되는 기술입니다. 5G, 스마트 홈, 자동차 등이 IPv6을 필요로 합니다.

IPv4 주소는 왜 부족한가?

IPv4 주소는 32비트로 구성되어 있습니다:

32비트 = 2^32 = 약 42억 개 (4,294,967,296개)

이는 인터넷 초기에는 충분했지만, 현재는:

  • 세계 인구: 약 80억 명 (IPv4 주소는 인구보다 적음)
  • IoT 기기: 스마트폰, 태블릿, 스마트 홈, 센서 등으로 폭증
  • 주소 고갈: 2011년 IPv4 주소 고갈 선언, NAT와 프라이빗 주소로 임시 해결 중

IPv6 주소—128비트의 무한한 공간

IPv6은 문제를 근본적으로 해결합니다:

128비트 = 2^128 = 약 340간(澗) 개 · 3.4×10³⁸ (340,282,366,920,938,463,463,374,607,431,768,211,456개)

IPv6 주소 표기법

IPv6은 128비트를 16진법(Hexadecimal)으로 표기합니다. 콜론(`:`)으로 구분된 8개 그룹으로 표현합니다:

0 압축연속된 0000은 0으로 단축2001:db8:85a3::8a2e:370:7334
주소 단축각 그룹에서 선행 0 생략2001:db8:85a3:0:0:8a2e:370:7334

TCP 3-Way Handshake (연결 설정)

TCP는 안정적인 연결을 위해 통신 전에 3단계 악수를 수행합니다:

터미널클라이언트(192.168.64.2) → 서버(192.168.64.3) 연결 과정
$ 클라이언트(192.168.64.2) → 서버(192.168.64.3) 연결 과정 1. SYN (Synchronize) 클라이언트가 서버에 "연결하고 싶어요"라고 신호 2. SYN-ACK (Synchronization Acknowledgment) 서버가 "알겠습니다"라고 답장 3. ACK (Acknowledgment) 클라이언트가 "고마워요"라고 최종 확인 → 이제 데이터 전송 가능!

이점: 연결 전에 양쪽이 준비되었는지 확인하고, 이후 손실된 패킷은 재전송으로 복구합니다.

TLS의 작동 방식 (간략)

  4. 암호화 통신: 이제부터 모든 데이터가 암호화됨
