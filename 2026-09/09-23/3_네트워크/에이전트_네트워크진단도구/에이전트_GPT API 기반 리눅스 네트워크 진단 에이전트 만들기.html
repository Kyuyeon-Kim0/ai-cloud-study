이번 버전에서는 Python 코드가 진단 순서를 고정하지 않습니다. 사용자가 자연어로 문제를 입력하면 GPT가 문제를 해석하고, 필요한 Tool(ping / ss / pgrep / curl)을 선택해서 실행하고, 도구 결과를 다시 읽은 뒤 다음 도구를 쓸지 또는 답변할지를 판단합니다.

Server VM: ubuntu Client VM: ubuntu1 TCP 8000 OPENAI_API_KEY

먼저: 왜 이것은 에이전트인가?

이전 버전: 자동화

if ping 실패:
    종료

if port 없음:
    process 확인

if port 있음:
    curl 확인

판단 규칙을 사람이 Python의 if문으로 모두 작성합니다.

이번 버전: GPT Agent

사용자:

       GPT
        ↓

Agent의 핵심 구성
① Model = 판단하는 두뇌
② Instructions = 역할과 행동 원칙
③ Tools = 실제 세상을 확인하거나 행동하는 함수
④ Runner = GPT ↔ Tool ↔ GPT 루프를 실행

4OPENAI_API_KEY 설정

API Key를 Python 코드에 직접 적지 않습니다.
예: api_key="sk-..." 형태로 소스에 저장하지 않습니다.

현재 PowerShell 창에서만 설정

$env:OPENAI_API_KEY="여기에_본인의_API_KEY"

설정 확인

if ($env:OPENAI_API_KEY) { "API KEY 설정됨" } else { "API KEY 없음" }
왜 환경변수를 사용하는가?
Agents SDK는 OPENAI_API_KEY 환경변수를 사용할 수 있습니다. 소스코드와 비밀키를 분리하면 GitHub 등에 코드를 올릴 때 키가 같이 노출될 위험을 줄일 수 있습니다.
화면 공유 중이라면 API Key 전체를 출력하는 명령은 사용하지 않는 것이 좋습니다.

6run_vm(): Python에서 Multipass 실행

def run_vm(vm_name: str, command: list[str]) -> dict:

    full_command = [
        "multipass",
        "exec",
        vm_name,
        "--",
    ] + command

    result = subprocess.run(
        full_command,
        capture_output=True,
        text=True,
        timeout=10,
    )

vm_name: str

vm_name에 문자열을 받겠다는 타입 힌트입니다.

command: list[str]

문자열 여러 개가 들어 있는 리스트를 받는다는 뜻입니다.

예

run_vm(
    "ubuntu1",
    ["ping", "-c", "2", "172.21.128.10"]
)

실제로 실행되는 명령:

multipass exec ubuntu1 -- ping -c 2 172.21.128.10

capture_output=True

명령 출력 결과를 Python이 받아옵니다.

text=True

stdout/stderr를 문자열로 받습니다.

timeout=10

명령이 멈춰 있더라도 최대 10초 후 종료할 수 있게 합니다.

이 한 줄이 매우 중요합니다.
일반 Python 함수 앞에 @function_tool을 붙이면 Agents SDK가 이 함수를 GPT가 호출할 수 있는 Tool로 등록합니다.

@는?

Python의 Decorator 문법입니다. 기존 함수에 추가 기능을 붙입니다.

-> str는?

이 함수가 문자열을 반환한다는 타입 힌트입니다.

Docstring이 왜 중요한가?

"""
ubuntu1에서 ubuntu로 ping을 보내
기본 네트워크 연결을 확인한다.
"""

GPT는 Tool의 이름과 설명을 보고 언제 이 Tool을 사용할지 판단합니다. 따라서 Tool 설명은 에이전트 설계의 일부입니다.

    """
    ubuntu1에서 ubuntu로 ICMP ping을 보내

    네트워크 연결 여부를 먼저 확인해야 할 때 사용한다.
    """

    server_ip = get_server_ip()

    result = run_vm(
        CLIENT_VM,
        ["ping", "-c", "2", "-W", "2", server_ip],

사용자가 “ubuntu 접속이 아예 안 돼”라고 말하면 GPT는 이 Tool의 설명을 보고 기본 연결 확인에 적합하다고 판단할 수 있습니다.

json.dumps()

Python 딕셔너리를 JSON 문자열로 변환합니다.

{"returncode": 0, "stdout": "...", "stderr": ""}

이 문자열이 Tool 결과로 다시 GPT에게 전달됩니다.

9Tool 2 — check_port_8000()

@function_tool
def check_port_8000() -> str:
    """
    ubuntu에서 TCP 8000번 포트가 LISTEN 상태인지 확인한다.
    ping은 되지만 웹 서비스 접속이 안 될 때 사용한다.
    """

    result = run_vm(
        SERVER_VM,
        ["ss", "-lnt"],
    )

    result["listen_8000"] = ":8000" in result["stdout"]

    return json.dumps(result, ensure_ascii=False)

실제 Linux 명령

ss -lnt
옵션의미
-lLISTEN
-n포트를 숫자로 표시
-tTCP

in 문법

":8000" in result["stdout"]

출력 문자열 안에 :8000이 있는지 확인하고 True/False를 만듭니다.

10Tool 3 — check_http_process()

@function_tool
def check_http_process() -> str:
    """
    ubuntu에서 Python http.server 프로세스가 실행 중인지 확인한다.
    8000번 포트가 열리지 않았을 때 서버 실행 여부 확인에 사용한다.
    """

    result = run_vm(
        SERVER_VM,
        ["pgrep", "-af", "python3 -m http.server"],
    )

    result["process_found"] = result["returncode"] == 0

    return json.dumps(result, ensure_ascii=False)

실제 Linux 명령

pgrep -af "python3 -m http.server"

이 Tool이 있으므로 GPT는:

8000 LISTEN 없음
        ↓
"서버 프로그램 자체가 꺼졌는지 확인해 볼까?"
        ↓
check_http_process()

처럼 추가 도구 호출을 선택할 수 있습니다.

11Tool 4 — http_test()

@function_tool
def http_test() -> str:

    ubuntu1에서 ubuntu:8000으로 실제 HTTP 요청을 보내

14Runner.run() — Agent Loop 시작

result = await Runner.run(
    network_agent,
    question,
)

이 한 줄 뒤에서 개념적으로 다음 과정이 진행됩니다.

1. question을 GPT에게 보냄
2. GPT가 Tool 필요 여부 판단
3. GPT가 Tool 호출
4. Agents SDK가 Python 함수를 실행
5. 함수 결과를 GPT에게 다시 전달
6. GPT가 또 Tool이 필요한지 판단
7. 충분하면 최종 답변 생성

최종 답변:

print(result.final_output)

16전체 코드

import asyncio
import json
import subprocess

from agents import Agent, Runner, function_tool


# ---------------------------------------------------------
# 1. 실습 환경 설정
# ---------------------------------------------------------

SERVER_VM = "ubuntu"
CLIENT_VM = "ubuntu1"
PORT = 8000


# ---------------------------------------------------------
# 2. Multipass VM에서 Linux 명령을 실행하는 공통 함수
# ---------------------------------------------------------

def run_vm(vm_name: str, command: list[str]) -> dict:
    """
    Windows에서 multipass exec를 사용해
    지정한 VM 내부의 Linux 명령을 실행한다.
    """

    full_command = [
        "multipass",
        "exec",
        vm_name,
        "--",
    ] + command

    try:
        result = subprocess.run(
            full_command,
            capture_output=True,
            text=True,
            timeout=10,
        )

        return {
            "vm": vm_name,
            "command": " ".join(command),
            "returncode": result.returncode,
            "stdout": result.stdout.strip(),
            "stderr": result.stderr.strip(),
        }

    except subprocess.TimeoutExpired:
        return {
            "vm": vm_name,
            "command": " ".join(command),
            "returncode": -1,
            "stdout": "",
            "stderr": "명령 실행 시간이 10초를 초과했습니다.",
        }


# ---------------------------------------------------------
# 3. 내부 보조 함수: ubuntu의 IP 주소 확인
#    GPT에게 직접 공개하는 도구는 아니다.
# ---------------------------------------------------------

def get_server_ip() -> str:
    result = run_vm(
        SERVER_VM,
        ["hostname", "-I"],
    )

    if result["returncode"] != 0:
        return ""

    addresses = result["stdout"].split()

    if not addresses:
        return ""

    return addresses[0]


# ---------------------------------------------------------
# 4. GPT가 선택해서 사용할 Tool 1: ping
# ---------------------------------------------------------

@function_tool
def ping_test() -> str:
    """
    ubuntu1에서 ubuntu로 ICMP ping을 보내
    기본 IP 네트워크 연결이 가능한지 확인한다.
    네트워크 연결 여부를 먼저 확인해야 할 때 사용한다.
    """

    server_ip = get_server_ip()

    if not server_ip:
        return json.dumps(
            {"error": "ubuntu의 IP 주소를 확인하지 못했습니다."},
            ensure_ascii=False,
        )

    result = run_vm(
        CLIENT_VM,
        ["ping", "-c", "2", "-W", "2", server_ip],
    )

    result["server_ip"] = server_ip

    return json.dumps(
        result,
        ensure_ascii=False,
    )


# ---------------------------------------------------------
# 5. GPT가 선택해서 사용할 Tool 2: 8000 포트
# ---------------------------------------------------------

@function_tool
def check_port_8000() -> str:
    """
    ubuntu에서 TCP 8000번 포트가 LISTEN 상태인지 확인한다.
    ping은 되지만 웹 서비스 접속이 안 될 때 사용한다.
    """

    result = run_vm(

    )

일반적인 진단 원칙:
1. 기본 통신 자체가 의심되면 ping_test를 사용한다.
2. ping은 되지만 8000 접속이 안 되면 check_port_8000을 고려한다.

18실제로 무엇이 Agent 판단인가?

예를 들어 질문:

ubuntu 웹서버가 안 되는 것 같아. 확인해줘.

가능한 흐름:

GPT
 │
 ├─ "기본 연결부터 확인해야겠다"
 │
 └─ ping_test()
       │
       └─ returncode = 0
             │
             ▼
            GPT
             │
             ├─ "ping은 된다."
             └─ check_port_8000()
                    │
                    └─ listen_8000 = false
                              │
                              ▼
                             GPT
                              │
                              └─ check_http_process()
                                     │
                                     └─ process_found = false
                                               │
                                               ▼
                                              GPT
                                               │
                                               └─ 최종 답변
                                                  "기본 네트워크는 정상이고,
                                                   HTTP 서버가 실행되지 않았습니다."
Python 코드에 if ping 성공하면 port 실행이라는 분기 코드는 없습니다. GPT가 도구 설명, instructions, 이전 도구 결과를 바탕으로 다음 행동을 선택합니다. 이 점이 이번 예제의 핵심입니다.
