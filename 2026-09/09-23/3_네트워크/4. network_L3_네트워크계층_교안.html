왜 배워야 하나?

2계층은 같은 네트워크 안에서만 프레임을 배달합니다. 서울의 노트북에서 미국의 서버까지는 수십 개의 네트워크를 건너야 합니다. 어느 네트워크로 넘겨야 목적지에 가까워지는지 판단하는 것이 3계층이고, 그 판단을 하는 장비가 라우터입니다.

왜 배워야 하나?

Version · IHL · ToS · Total Length
패킷의 크기와 종류

필드값 예자세히
Version (4비트)4IPv4는 4, IPv6는 6. 첫 바이트 0x45의 앞 글자 4가 이것입니다. 받는 쪽은 이 값으로 헤더를 어떻게 읽을지 정합니다.
IHL (4비트)5 → 20BInternet Header Length. 4바이트 단위라서 5 × 4 = 20바이트. 옵션이 붙으면 6~15(최대 60바이트). 첫 바이트 0x45의 뒤 글자 5가 이것입니다.
DSCP (6비트)0 보통 · 46 음성Differentiated Services. 음성 통화처럼 급한 패킷에 높은 값을 줘서 라우터가 먼저 보내게 합니다(QoS). 옛 이름은 ToS.
ECN (2비트)0Explicit Congestion Notification. 라우터가 “막히기 시작함”을 버리지 않고 표시만 해서 알려 줌.
Total Length (16비트)84헤더 + 데이터의 전체 바이트 수. 최대 65,535. ping 기본 84 = IP 헤더 20 + ICMP 헤더 8 + 데이터 56.
첫 바이트 0x45 = 0100 0101
    앞 4비트 0100 = 4 (Version)  ·  뒤 4비트 0101 = 5 (IHL → 5 × 4 = 20바이트)
ping 크기 계산바이트어디서 보나
IP 헤더20Wireshark IP 부분 · Header Length: 20 bytes (5)
ICMP 헤더8type · code · checksum · id · seq
ICMP 데이터56ping 기본값 (-s로 변경)
Total Length84ping 출력의 “56(84) bytes”
+ 이더넷 헤더 1498tcpdump의 “length 98”
두 개의 길이

IP의 Total Length(84)는 3계층 패킷의 크기, tcpdump의 length 98은 2계층 프레임의 크기입니다. 14바이트 차이가 이더넷 헤더입니다.

ID · Flags · Offset · TTL · Protocol
조각과 수명

필드값 예자세히
Identification (16비트)0xbcca (48330)보낸 쪽이 패킷마다 붙이는 번호. 쪼개진 조각들은 같은 ID를 가져서 받는 쪽이 모아 붙입니다. 라우터를 지나도 바뀌지 않아 여러 지점의 캡처에서 같은 패킷을 찾는 열쇠가 됩니다(6.6).
Flags (3비트)010첫 비트: 예약(0) · 둘째: DF Don't Fragment(1이면 쪼개지 마) · 셋째: MF More Fragments(1이면 뒤에 조각 더 있음)
Fragment Offset (13비트)0이 조각이 원래 데이터에서 어디부터인지. 8바이트 단위. 첫 조각은 0.
TTL (8비트)64Time To Live. 라우터를 지날 때마다 1씩 줄고, 0이 되면 버리고 출발지에 ICMP “Time Exceeded”를 보냄. 루프에서 패킷이 영원히 돌지 않게 하는 장치.
Protocol (8비트)1데이터 칸에 든 것. 1 ICMP · 6 TCP · 17 UDP. 받는 쪽 운영체제가 누구에게 넘길지 정함.
바이트 6~7 = 0x4000 = 0100 0000 0000 0000
    앞 3비트 010 → 예약 0 · DF 1 · MF 0  |  뒤 13비트 = Fragment Offset 0
