반복되는 1차 장애 대응을 자동화한다

PROJECT MISSION

인터넷 연결 상태를 자동으로 점검하고, 장애가 감지되면 Wi-Fi 어댑터를 재시작하여 1차 복구를 시도한다.

WHY 사용자가 매번 직접 끄고 켜는 반복 작업을 스크립트가 대신하면 대응 속도와 일관성을 높일 수 있습니다.

network_recovery_agent.ps1
$target = "8.8.8.8"

if (Test-Connection -ComputerName $target -Count 2 -Quiet) {
    Write-Host "네트워크 정상"
}
else {
    Write-Host "네트워크 장애 감지"
    Write-Host "Wi-Fi 재시작"

    Disable-NetAdapter -Name "Wi-Fi" -Confirm:$false
    Start-Sleep -Seconds 10
    Enable-NetAdapter -Name "Wi-Fi" -Confirm:$false

    Start-Sleep -Seconds 5

    if (Test-Connection -ComputerName $target -Count 2 -Quiet) {
        Write-Host "네트워크 복구 성공"
    }
    else {
        Write-Host "네트워크 복구 실패"
    }
}

운영 기준08
SAFETY · LIMITS

자동복구는 무한 반복하면 안 된다

RULE 1

재시도 제한

예: 최대 2~3회까지만 재시작하고 이후에는 사람에게 보고합니다.

RULE 2

로그 기록

언제 장애가 발생했고 어떤 조치를 했는지 남깁니다.

RULE 3

권한 통제

관리자 권한 스크립트는 신뢰할 수 있는 PC와 사용자만 실행합니다.

현재 버전의 한계

한계개선 방향
8.8.8.8 한 곳만 검사게이트웨이·외부 IP·도메인을 순차 검사
Wi-Fi만 지원어댑터 이름을 자동 탐색하거나 이더넷 지원
결과가 화면에만 출력텍스트 로그 또는 Windows Event Log 저장
실패 후 종료실패 사유를 분류하고 관리자 알림

단순 스크립트에서 운영 에이전트로

LV.1 기본 자동화

Ping 검사 → 장애 시 Wi-Fi 재시작 → 다시 Ping

LV.2 자가진단

어댑터, IP, 게이트웨이, 외부 IP, DNS를 순서대로 검사하여 문제 구간을 분류합니다.

LV.3 운영 자동화

로그 기록, 재시도 제한, 장애 횟수 집계, 일정 시간마다 상태 점검 기능을 추가합니다.

LV.4 에이전트

진단 결과를 바탕으로 상황별 조치를 선택하고, 해결되지 않으면 관리자에게 필요한 정보와 함께 보고합니다.

실습 체크리스트

관리자 PowerShell에서 스크립트를 실행해 보았다.
정상일 때 Wi-Fi가 불필요하게 재시작되지 않는 것을 확인했다.
Wi-Fi를 끊은 뒤 실행하여 자동복구 흐름을 확인했다.
복구 실패 시 게이트웨이·외부 IP·DNS 순서로 원인을 나눠 보았다.
