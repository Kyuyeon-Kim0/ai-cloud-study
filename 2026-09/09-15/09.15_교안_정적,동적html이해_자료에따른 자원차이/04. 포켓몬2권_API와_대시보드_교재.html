MISSION

WHY 브라우저는 한 번에 하나씩입니다. 코드로 하면 반복할 수 있고 기록할 수 있습니다. 대신 실패 처리를 직접 해야 합니다.

timeout 을 빼면 서비스가 멈춥니다  상대 서버가 응답하지 않으면 코드가 그 줄에서 멈춘 채 기다립니다. 웹 서비스라면 그 요청을 처리하던 작업이 계속 붙잡혀 있게 됩니다. 운영 코드에서 timeout 없는 호출은 사고의 원인입니다.

실패를 처리하기

call_safe.pyPYTHON
import requests def fetch(name): """포켓몬 하나를 가져온다. 실패하면 None.""" url = f"https://pokeapi.co/api/v2/pokemon/{name}" try: res = requests.get(url, timeout=10) except requests.exceptions.RequestException as e: print("연결 실패:", e) # 네트워크 자체가 안 될 때 return None if res.status_code != 200: print(f"{name}: {res.status_code}") # 404 등 return None return res.json() for n in ("pikachu", "charizard", "없는포켓몬"): d = fetch(n) print(n, "성공" if d else "실패")
두 가지 실패를 구분합니다

연결 자체가 안 되는 것(인터넷 끊김, 서버 다운)과 연결은 됐지만 원하는 게 없는 것(404)은 다릅니다. 앞은 try로, 뒤는 status_code로 잡습니다.

PARSE

중첩 구조를 파고든다

MISSION

받은 데이터에서 이름·타입·능력치·이미지 주소만 꺼내 평평한 형태로 만든다.

WHY API 응답은 200KB인데 우리가 쓸 것은 1KB도 안 됩니다. 필요한 것만 꺼내 두는 것이 저장과 처리의 출발점입니다.

한 겹씩 들어가기

구조 확인PYTHON
data = fetch("pikachu") # 최상위 키 목록 print(list(data.keys())) # ['id', 'name', 'height', 'weight', 'types', 'stats', 'sprites', ...] # 단순한 값은 바로 print(data["name"], data["height"], data["weight"]) # types 는 리스트 → 첫 번째 → type → name print(data["types"][0]["type"]["name"]) # electric # stats 도 리스트 → 각 항목에 이름과 값 for s in data["stats"]: print(s["stat"]["name"], s["base_stat"])

extract.pyPYTHON
def extract(data): """API 응답에서 필요한 값만 꺼내 딕셔너리 하나로.""" types = [t["type"]["name"] for t in data["types"]] stats = {s["stat"]["name"]: s["base_stat"] for s in data["stats"]} return { "id": data["id"], "name": data["name"], "type1": types[0], "type2": types[1] if len(types) > 1 else "", "height": data["height"], "weight": data["weight"], "hp": stats.get("hp", 0), "attack": stats.get("attack", 0), "defense": stats.get("defense", 0), "speed": stats.get("speed", 0), "image": data["sprites"]["front_default"], } print(extract(fetch("pikachu")))
.get()을 쓰는 이유  stats["hp"]는 키가 없으면 오류가 납니다. stats.get("hp", 0)은 없으면 0을 돌려줍니다. 외부에서 받은 데이터는 항상 내가 기대한 모양이 아닐 수 있으므로 이렇게 씁니다.

반복의 대가를 잰다

MISSION

50마리를 받아 보고 시간·전송량·메모리를 측정한다. 요청 한 번의 비용을 숫자로 안다.

WHY 1권의 CSV는 내 디스크에 있었습니다. API는 매번 인터넷을 거칩니다. 성격이 완전히 다릅니다.

반복해서 받기

fetch_many.pyPYTHON
import time, requests from measure import ResourceLogger def fetch_many(n=50): rows, total_bytes = [], 0 for i in range(1, n + 1): url = f"https://pokeapi.co/api/v2/pokemon/{i}" res = requests.get(url, timeout=10) if res.status_code == 200: total_bytes += len(res.content) rows.append(extract(res.json())) time.sleep(0.1) # 서버 배려 — 아래 설명 print(f"전송량 {total_bytes/1024/1024:.1f} MB") return rows with ResourceLogger() as logger: rows = logger.measure(lambda: fetch_many(50), target="pokeapi", action="fetch", lib="requests-50") print(len(rows), "마리")

여기서 보이는 것

50마리에 12초입니다. 대부분이 기다리는 시간입니다. CPU는 거의 놀고 있습니다. 1권에서 10만 행 CSV를 0.4초에 읽은 것과 비교해 보세요. 네트워크는 느립니다.

sleep을 넣는 이유

남의 서버입니다  반복문으로 요청을 쉬지 않고 보내면 상대 서버에 부담이 됩니다. 공개 API는 대개 요청 제한을 두고 있어서, 너무 빠르면 429 Too Many Requests로 막히거나 IP가 차단될 수 있습니다. time.sleep(0.1)은 최소한의 배려입니다.

운영에서 중요한 것

API 호출은 내 서버의 CPU가 아니라 남의 서버와 네트워크를 씁니다. 내 장비를 아무리 올려도 상대가 느리면 그대로 느립니다. 그래서 받아 둔 것을 다시 쓰는 것이 유일한 개선책일 때가 많습니다.

시간이 어디에 쓰이는가

구간비중성격
요청을 보내고 기다림대부분네트워크 — CPU는 놀고 있음
JSON 을 파이썬으로 변환작음CPU 작업
필요한 값 꺼내기매우 작음CPU 작업

그래서 장비를 올려도 빨라지지 않습니다. 네트워크 대기가 대부분이기 때문입니다. 개선하려면 요청 수를 줄이거나 동시에 보내야 합니다.

실습

  • 10마리·50마리·100마리로 바꿔 가며 시간이 비례해 늘어나는지 확인한다
  • time.sleep을 없애고 실행해 얼마나 빨라지는지 본다 단, 한 번만
  • 측정 결과에서 CPU 사용률을 확인한다 — 낮게 나올 것
  • 인터넷을 잠시 끊고 실행해 어떤 오류가 나는지 본다

세 번째가 중요합니다. CPU는 노는데 시간은 오래 걸립니다. 부록에서 배운 “벽시계 시간과 CPU 시간의 차이”가 여기서 드러납니다.

CACHE

두 번 묻지 않는다

MISSION
