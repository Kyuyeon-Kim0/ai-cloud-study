CONCURRENCY

접속자가 늘면 무엇이 달라지나

MISSION

브라우저 탭을 여러 개 열어 동시 접속을 만들고, 메모리와 응답 시간이 어떻게 변하는지 측정한다.

WHY 지금까지는 혼자 쓰는 상태만 봤습니다. 운영에서 중요한 것은 여럿이 동시에 쓸 때입니다. 이 차이를 모르면 사양을 정할 수 없습니다.

무엇이 늘어나고 무엇이 그대로인가

항목접속자가 늘면이유
CPU비례해 증가요청마다 읽고 집계합니다
메모리구성에 따라 다름캐시를 공유하면 덜 늘어납니다
응답 시간점점 느려짐순서를 기다리게 됩니다
디스크 읽기캐시가 없으면 비례같은 파일을 반복해서 읽습니다
프로그램 코드그대로한 번 올라온 코드는 공유됩니다
여기서 캐시가 다시 중요해집니다

캐시가 없으면 접속자 수만큼 파일을 읽고 집계합니다. 캐시가 있으면 한 번 읽은 것을 모두가 나눠 씁니다. 2권에서 붙인 캐시가 여기서 값을 합니다.

이 표에서 읽어야 할 것

관찰운영 관점의 의미
메모리가 비례해 증가접속자 10명이면 3GB. 16GB 장비도 30명을 못 버팁니다
응답 시간도 함께 증가느려지는 것을 사용자가 먼저 느낍니다
캐시가 둘 다 잡는다같은 장비로 훨씬 많은 접속을 받을 수 있습니다
첫 접속은 여전히 느림캐시는 두 번째부터 효과가 있습니다
사양을 올리는 것보다 먼저 할 일  메모리가 부족하다고 바로 장비를 키우면 비용이 비례해 늘어납니다. 캐시 하나로 3분의 1 이하로 줄었다면, 장비를 키우는 것은 그다음입니다. 측정 없이 증설부터 하는 것이 가장 흔한 낭비입니다.

실무에서는 어떻게 세는가

동시 접속Concurrent
같은 순간에 실제로 요청을 처리 중인 수. 사양 산정의 기준입니다.
동시 사용자Concurrent Users
화면을 열어 둔 사람 수. 대부분은 읽고 있을 뿐 요청을 보내지 않습니다.
일 활성 사용자DAU
하루에 한 번이라도 쓴 사람 수. 이 숫자로 사양을 정하면 과합니다.

DAU 1만 명이어도 동시 접속은 수십 명인 경우가 흔합니다. 세 숫자를 구분하지 못하면 필요 이상으로 큰 장비를 사게 됩니다.

MISSION

WHY 클라우드에서 인스턴스를 고르는 일이 이것입니다. 추측이 아니라 계산으로 정해야 과하지도 모자라지도 않습니다.

캐시가 없다면 이야기가 달라집니다  접속당 210MB라면 20명에 4.2GB입니다. 여기에 기본과 여유를 더하면 8GB 이상이 필요합니다. 캐시 하나가 인스턴스 등급을 바꿉니다.

CPU 계산

처리 가능량 추정계산
요청 하나에 CPU 0.3 초 소요 코어 1개가 1초에 처리할 수 있는 요청 = 1 / 0.3 ≈ 3.3 건 목표: 초당 10 건 처리 필요 코어 = 10 / 3.3 ≈ 3 개 여유를 두어 → 4 코어

실제로는 사용률 70% 이하를 유지하도록 잡습니다. 100%에 가까우면 조금만 몰려도 응답이 급격히 느려집니다.

부하를 만드는 간단한 방법

load_test.py — 요청을 반복해서 보냄PYTHON
import time, requests from concurrent.futures import ThreadPoolExecutor URL = "http://localhost:8501" def one_request(i): t0 = time.perf_counter() try: res = requests.get(URL, timeout=30) ok = res.status_code == 200 except Exception: ok = False return ok, time.perf_counter() - t0 def run(n): """동시에 n 개의 요청을 보낸다.""" t0 = time.perf_counter() with ThreadPoolExecutor(max_workers=n) as pool: results = list(pool.map(one_request, range(n))) total = time.perf_counter() - t0 ok = sum(1 for o, _ in results if o) times = sorted(t for _, t in results) print(f"동시 {n:3} | 성공 {ok:3}/{n} | " f"중앙값 {times[len(times)//2]:5.2f}s | " f"최대 {times[-1]:5.2f}s | 전체 {total:5.2f}s") for n in (1, 5, 10, 20, 50): run(n) time.sleep(3) # 회복할 시간을 준다

import logging, os, psutil os.makedirs("logs", exist_ok=True) logging.basicConfig( filename="logs/app.log", level=logging.INFO, format="%(asctime)s [%(levelname)s] %(message)s", encoding="utf-8", ) PROC = psutil.Process(os.getpid()) def log_step(name, elapsed=None, **extra): """작업 하나를 기록한다. 자원 상태를 함께 남긴다.""" rss = PROC.memory_info().rss / 1024**2 parts = [f"step={name}", f"rss={rss:.0f}MB"] if elapsed is not None: parts.append(f"elapsed={elapsed:.2f}s") parts += [f"{k}={v}" for k, v in extra.items()] logging.info(" ".join(parts)) # 사용 log_step("load_start") # ... 작업 ... log_step("load_done", elapsed=6.24, rows=1000000)
