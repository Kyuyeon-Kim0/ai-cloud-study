장부는 두 권입니다

MISSION

shop.db의 menus · orders 두 테이블과 칸의 규칙을 읽고, 두 테이블이 어떻게 이어지는지 설명한다.

WHY SQL을 쓰기 전에 무엇이 어느 칸에 있는지 알아야 합니다. 3장 오류의 대부분은 칸 이름 실수입니다.

그림 3-1 주문에는 메뉴 이름이 아니라 번호(menu_id)만 적습니다. 이름이 필요하면 menus와 이어 봅니다(3-4).

DB 용어 네 개

테이블table · 장부 한 권
칸이 정해진 표. shop.db에는 menus, orders 두 개
행 · 칸row · column
행 = 주문 한 건, 칸 = 주문 시각 · 사이즈 같은 항목
기본 키PRIMARY KEY 🔑
행마다 겹치지 않는 번호. 주문 번호 #1693
외래 키🔗 다른 표를 가리킴
orders.menu_id → menus.id. 이 번호로 두 표를 잇습니다
WHY — 주문마다 “하와이안”이라고 적지 않는 이유

메뉴 이름을 바꾸면 주문 1,692행을 전부 고쳐야 합니다. 번호만 적어 두면 menus 한 줄만 고치면 됩니다.

테이블을 만든 SQL05

tools/make_shop_db.py 안의 CREATE TABLE

tools/make_shop_db.py · 발췌SQL
CREATE TABLE menus ( id INTEGER PRIMARY KEY, name TEXT NOT NULL, emoji TEXT NOT NULL, price_r INTEGER NOT NULL, price_l INTEGER NOT NULL, description TEXT NOT NULL DEFAULT '', tag TEXT NOT NULL DEFAULT '' ); CREATE TABLE orders ( id INTEGER PRIMARY KEY AUTOINCREMENT, ordered_at TEXT NOT NULL, -- 'YYYY-MM-DD HH:MM:SS' menu_id INTEGER NOT NULL REFERENCES menus(id), size TEXT NOT NULL CHECK (size IN ('R', 'L')), crust TEXT NOT NULL, qty INTEGER NOT NULL CHECK (qty BETWEEN 1 AND 10), amount INTEGER NOT NULL, channel TEXT NOT NULL CHECK (channel IN ('배달', '포장', '매장')) ); CREATE INDEX idx_orders_time ON orders(ordered_at);
규칙뜻
INTEGER · TEXT칸의 종류. 날짜도 글자(TEXT)로 'YYYY-MM-DD HH:MM:SS' 형태로 저장
PRIMARY KEY행마다 겹치지 않는 번호표
AUTOINCREMENT새 주문마다 번호가 자동으로 1씩 증가
NOT NULL비워 둘 수 없음
CHECK (…)조건에 맞지 않으면 저장 거부 (3-3에서 실험)
REFERENCES menus(id)이 칸은 menus의 id를 가리킨다는 표시
CREATE INDEX주문 시각으로 찾을 때 빨라지도록 만든 색인

이 파일은 샘플 DB를 만들 때만 실행합니다. 서버(app.py)는 이미 만들어진 shop.db를 열어 쓰기만 합니다.

STEP 3-2 · sqlite3

연결하고, 묻고, 닫는다

MISSION

db.py의 get_conn()이 하는 일과 Row를 쓰는 이유를 설명한다.

WHY db.py의 모든 함수는 같은 순서로 움직입니다. 순서 하나만 익히면 나머지 함수는 SQL만 다른 같은 모양입니다.

db.py · 앞부분완성본
import sqlite3 from pathlib import Path # app.py 와 같은 폴더의 shop.db (어디서 실행해도 같은 파일) DB_PATH = Path(__file__).parent / "shop.db" def get_conn(): conn = sqlite3.connect(DB_PATH) conn.row_factory = sqlite3.Row # 결과를 row["name"] 처럼 이름으로 꺼내기 return conn
import sqlite3파이썬 내장
설치 없이 씁니다. requirements.txt에 없는 이유입니다.
DB_PATH파일 기준 경로
db.py 옆의 shop.db. 어느 폴더에서 서버를 켜도 같은 파일을 엽니다. 파일이 없으면 빈 DB를 새로 만들어 버리므로 경로가 중요합니다.
sqlite3.connect()장부 펼치기
연결(conn)을 돌려줍니다. SQL은 이 연결로 실행합니다.

row_factory = sqlite3.Row 가 있을 때와 없을 때

없으면 — 튜플
(6, '하와이안', '🍍', 19900, 25900, …)
row[1] → '하와이안'
몇 번째 칸인지 외워야 합니다. 칸 순서가 바뀌면 조용히 틀립니다.
있으면 — 이름으로
row["name"] → '하와이안'
dict(row) → {'id': 6, 'name': '하와이안', …}
템플릿의 m.name, JSON 응답에 그대로 쓰도록 딕셔너리로 바꿔 돌려줍니다.

db.py — 메뉴 꺼내기09

모든 함수의 공통 순서

① conn = get_conn()→② conn.execute(SQL)→③ fetchall / fetchone→④ conn.close()→⑤ 딕셔너리로 return
db.py · get_menus() · get_menu()완성본
def get_menus(): conn = get_conn() rows = conn.execute("SELECT * FROM menus ORDER BY id").fetchall() conn.close() return [dict(r) for r in rows] # Row → 딕셔너리 (템플릿·JSON에서 쓰기 쉽게) def get_menu(menu_id): conn = get_conn() row = conn.execute("SELECT * FROM menus WHERE id = ?", (menu_id,)).fetchone() conn.close() return dict(row) if row else None
코드뜻
.fetchall()결과 전부를 리스트로. 메뉴판처럼 여러 행
.fetchone()첫 행 하나. 없으면 None
[dict(r) for r in rows]Row 여러 개를 딕셔너리 리스트로 — 2장에서 본 menus의 정체
dict(row) if row else None없는 번호면 None → app.py가 “이상한 값”으로 판단 (2장 검사)

? 자리 — 값은 SQL에 직접 붙이지 않는다

execute 한 줄 분해PLACEHOLDER
conn.execute("SELECT * FROM menus WHERE id = ?", (menu_id,))
나누어 보면
SQL 틀 — 값 자리는 ? (menu_id,) — ? 에 들어갈 값 (튜플)
쉼표 하나에 주의 값이 하나일 때 (menu_id,)처럼 쉼표가 있어야 튜플이 됩니다. (menu_id)는 그냥 숫자라서 오류가 납니다. 왜 ?를 쓰는지 바로 아래에서 실험합니다.

f-string으로 SQL을 만들면 생기는 일

누군가 채널 값에 배달' OR '1'='1을 넣었다고 해 봅시다. 실제로 실행한 결과입니다.

값을 SQL 글자에 끼워 넣기
f"… WHERE channel = '{ch}'"
→ WHERE channel = '배달' OR '1'='1'
값이 SQL 문법으로 해석되어 조건이 무너집니다. 결과: 1,692건 전부 조회. 이런 공격을 SQL 인젝션이라고 합니다.
? 자리에 값으로 넘기기
"… WHERE channel = ?", (ch,)
값은 끝까지 그냥 글자로 취급됩니다. 그런 채널은 없으니 결과: 0건.
규칙 사용자에게서 온 값은 반드시 ? 자리로 넘깁니다. db.py의 모든 SQL이 이 규칙을 따릅니다.
