A1-M3. BoW·TF-IDF·BM25 정보검색

A1-M2에서 규칙을 직접 검사하는 프로그램을 완성했습니다. 이제 웹 검사 결과에 나타난 rule_id를 보고, 그 규칙의 설명과 관련 근거를 찾아주는 기능을 만들 차례입니다. 이 단계가 A1-M3의 정보검색(Information Retrieval)입니다.

이번 업무 과제: 개발자가 “더보기 링크의 문제가 뭐야?”라고 질문하면, M2의 rules.csv에서 관련 규칙을 찾아 규칙 ID·설명·출처·적용 상태와 함께 상위 결과를 보여주는 검색기를 구현합니다. 검색이 판정 결과를 바꾸지는 않습니다.

01-1. 웹 정합성 검사 업무가 어떻게 이어지는가?

신규 웹페이지를 검사한 뒤 개발자가 검사기 결과를 받아 다음과 같이 물었다고 생각해 봅시다.

② 추가 설명 요청개발자가 “더보기 링크에 무슨 문제가 있어?” 질문자연어 검색어 또는 규칙 ID
③ 후보 자료 준비M2의 현재 유효한 규칙만 선택rules.csv에서 status=applied 필터
④ 관련 규칙 검색본문에서 단어 출현·가중치·순위를 계산BoW → TF-IDF·코사인 → BM25
⑤ 결과와 출처 제시기존 트리와 연결해 규칙의 위치도 보여줌rule_tree.csv → file + rule_id

이 단계에서는 이미 만들어 놓은 검사기와 CSV를 다시 만들지 않습니다. M2의 규칙은 “조건을 충족하는가”에 답하고, M3 검색기는 “어떤 설명·근거를 먼저 읽어야 하는가”에 답합니다. 예를 들어 회사가 “더보기”라는 단독 문구를 금지했다는 사실을 검색했더라도, 이것이 곧 WCAG의 공식 위반 판정이라는 뜻은 아닙니다.

01-2. 왜 단순 문자열 검색이 아니라 정보검색인가?

단어를 숫자 벡터로 바꾸는 첫 단계

02. BoW와 단어 빈도

BoW(Bag of Words)는 단어를 세어서 문서를 일정한 길이의 숫자 벡터로 표현합니다. 문장 속 단어의 순서보다 어떤 단어가 몇 번 등장했는가가 중요합니다.

02-1. 문서 3개를 직접 벡터로 만들어 보자

문서내용해석
D1이미지 대체 텍스트이미지에 관한 대체 텍스트
D2이미지 설명이미지 설명
D3링크 목적링크의 목적

중복을 제거한 어휘 집합을 정렬하면 [대체, 링크, 목적, 설명, 이미지, 텍스트]가 됩니다. 문서를 벡터로 변환할 때는 모든 문서에서 같은 단어가 같은 열에 있어야 합니다.

문서대체링크목적설명이미지텍스트
D1100011
D2000110
D3011000

D1의 [1,0,0,0,1,1]은 1·5·6번째 단어가 한 번 등장한다는 뜻입니다. 각 숫자의 위치에 대응하는 어휘 사전을 잃어버리면 숫자의 의미도 사라집니다.

02-2. 순수 Python으로 단어 인덱스와 DataFrame 만들기

from collections import Counter

corpus = ["이미지 대체 텍스트", "이미지 설명", "링크 목적"]
tokenized = [sentence.split() for sentence in corpus]
vocab = sorted({word for words in tokenized for word in words})

rows = []
for words in tokenized:
    count = Counter(words)                # 단어별 출현 횟수
    rows.append([count[word] for word in vocab])

import pandas as pd
print(pd.DataFrame(rows, columns=vocab, index=["D1", "D2", "D3"]))

Counter는 단어를 빈도 딕셔너리로 바꿉니다. sorted(...)로 열 순서를 고정해 둔 뒤 columns=vocab으로 DataFrame을 만드는 것이 핵심입니다. 복잡한 표 출력 패키지 없이도 결과를 확인할 수 있습니다.

    대체  링크  목적  설명  이미지  텍스트
D1   1   0   0   0    1    1
D2   0   0   0   1    1    0
D3   0   1   1   0    0    0

02-3. 바로 확인할 한계

BoW는 이미지라는 공통 단어를 찾는 데는 유용하지만, 대체와 목적의 문서 내 중요도를 구분하지 못합니다. 또 규칙 위반이 있다와 규칙 위반이 없다 같은 문맥을 충분히 표현하지 못합니다. 단어의 통계적 중요도를 추가한 TF-IDF가 필요한 이유입니다.

단어 중요도와 검색 유사도

03. TF-IDF와 코사인 유사도

TF-IDF(Term Frequency–Inverse Document Frequency)는 특정 문서에서 자주 등장하지만 여러 문서에서는 상대적으로 드문 단어를 강조합니다. 문서와 질문을 같은 어휘 좌표계에서 벡터화한 뒤, 코사인 유사도로 방향의 유사성을 비교합니다.

03-1. TF·DF·IDF를 숫자로 구분

기호뜻3개 문서 예시
TF(t,d)문서 d에서 단어 t의 등장 횟수D1에서 이미지 TF = 1
DF(t)단어 t가 한 번 이상 등장한 문서 개수이미지 DF = 2, 대체 DF = 1
IDF(t)드문 단어에 상대적으로 더 큰 가중치같은 문서 집합에서 대체 IDF > 이미지 IDF

여기서는 scikit-learn의 기본 smooth_idf=True 정의를 사용합니다.

IDF(t) = ln[(N+1) / (DF(t)+1)] + 1

N = 전체 문서 수. 자연로그 ln을 사용하며, 마지막 +1을 빼면 라이브러리 결과와 다릅니다.

단어DF직접 계산IDF
이미지2ln(4/3)+11.288
대체1ln(4/2)+11.693
텍스트1ln(4/2)+11.693

03-2. TF-IDF 벡터를 L2 정규화한다

기본 가중치는 TF × IDF입니다. D1의 가중치 벡터에는 이미지 1.288, 대체 1.693, 텍스트 1.693이 들어갑니다. L2 정규화는 벡터 길이를 1로 맞추어 각 단어 가중치의 상대적인 비중을 비교하기 쉽게 합니다.

D1의 길이 = √(1.288² + 1.693² + 1.693²) ≈ 2.719
정규화된 이미지 = 1.288 / 2.719 ≈ 0.474
정규화된 대체·텍스트 ≈ 0.623

03-3. 질문 “이미지 대체”와 비교

질의도 문서와 같은 IDF·어휘 인덱스로 변환합니다. 코사인 유사도는 두 벡터의 내적을 각각의 길이로 나눈 값입니다.

cos(q,d) = (q · d) / (‖q‖ × ‖d‖)
문서코사인 유사도순위의 의미
D10.7824이미지와 대체가 모두 일치
D20.3664이미지만 일치
D30.0000공유 어휘가 없음

이 값은 접근성 적합률도 정답 확률도 아닙니다. 단지 지금 정의한 TF-IDF 공간에서 두 텍스트 벡터가 비슷하다는 뜻입니다.

03-4. 코드에서 반드시 구분해야 할 fit과 transform

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

corpus = ["이미지 대체 텍스트", "이미지 설명", "링크 목적"]
model = TfidfVectorizer(tokenizer=str.split,
                        token_pattern=None, lowercase=False)
X = model.fit_transform(corpus)           # 문서에서 어휘와 IDF 학습
q = model.transform(["이미지 대체"])     # 동일한 어휘·IDF 재사용
print(cosine_similarity(q, X)[0].round(4))
[0.7824 0.3664 0.    ]

질의에 fit_transform()을 다시 호출하면 질문에 맞추어 새로운 단어 사전을 만드는 잘못된 비교가 됩니다. 문서에는 fit, 질의에는 transform이라는 구분이 중요합니다.

이후 연결: 지금은 세 문서의 점수를 직접 계산하지만, 나중에는 A1-M2의 규칙 설명 7개를 문서로 넣어 Top-k를 구합니다. M4에서는 이 순위가 얼마나 좋은지를 별도 정답셋으로 평가합니다.

검색 점수의 빈도 포화와 길이 보정

04. BM25 검색 점수

BM25(Best Matching 25)는 검색어가 반복될 때 점수 증가가 무한히 비례하지 않도록 빈도 포화를 적용하고, 문서 길이 차이를 보정하여 관련 문서를 순위화합니다.

04-1. 왜 TF-IDF 외에 BM25가 필요한가?

“링크 링크 링크”를 반복한 긴 문서가 항상 가장 좋은 근거가 되지는 않습니다. 반대로 짧은 규칙 제목과 긴 규칙 해설을 같은 검색어로 비교할 때는 문서 길이도 고려해야 합니다.

BM25(q,d) = Σt∈q IDF(t) × [ TF(t,d) × (k₁ + 1) ] / [ TF(t,d) + k₁ × (1 − b + b × |d| / avgdl) ]
이 교안의 IDF(t) = ln[1 + (N − DF(t) + 0.5)/(DF(t) + 0.5)]
변수의미조절하는 요소
k₁단어 빈도 효과를 조절하는 양수검색어 반복에 따른 점수 포화
b문서 길이 보정 계수(보통 0~1)b=0이면 길이 보정 제외
|d| / avgdl문서 길이 / 전체 문서의 평균 길이긴 문서와 짧은 문서의 점수 균형

04-2. 직접 계산하는 3개 문서

문서내용길이“링크” 등장
D1링크 목적21회
D2링크 링크 목적32회
D3이미지 설명20회

문서길이 보정최종 BM25 점수
D10.25 + 0.75 × 2 / 2.333 ≈ 0.8930.5023
D20.25 + 0.75 × 3 / 2.333 ≈ 1.2140.6150

D2는 단어가 2번 나오지만 점수는 D1의 2배가 아닙니다. 반복 빈도 포화와 문서 길이 보정이 동시에 적용되기 때문입니다.

04-3. 순수 Python 검산

from math import log
from collections import Counter

corpus = ["링크 목적", "링크 링크 목적", "이미지 설명"]
docs = [text.split() for text in corpus]
N = len(docs)
df = sum("링크" in words for words in docs)
avgdl = sum(len(words) for words in docs) / N
k1, b = 1.5, 0.75
idf = log(1 + (N - df + 0.5) / (df + 0.5))

for i, words in enumerate(docs, start=1):
    tf = Counter(words)["링크"]
    length_factor = 1 - b + b * len(words) / avgdl
    score = idf * tf * (k1 + 1) / (tf + k1 * length_factor) if tf else 0
    print(f"D{i}: {score:.4f}")
D1: 0.5023
D2: 0.6150
D3: 0.0000

04-5. BM25 라이브러리와 점수가 달라질 수 있다

BM25는 하나의 고정된 소프트웨어가 아니라 알고리즘 계열입니다. rank-bm25의 BM25Okapi, 검색 엔진의 BM25, 이 교안의 양수 IDF 구현은 IDF 보정과 세부 구현이 다를 수 있습니다. 점수값 자체를 동일시하지 말고, 사용한 공식·토큰 단위·파라미터를 기록하고 순위와 평가 결과를 비교해야 합니다.

M3에서는 BM25를 손계산과 작은 함수로 이해합니다. OpenSearch의 실제 인덱스 운영과 하이브리드·벡터 검색은 A2에서 다룹니다.

계층 메타데이터node_id, parent_id, tree_path, source_file트리 탐색·원본 CSV 행으로 돌아가기
판정 엔진용selector, operator, attribute, valuesM2 검사기의 검사 조건. 이번 검색 본문에 무조건 넣지는 않음

규칙 ID 검색은 일반 문장 유사도보다 정확한 식별자 일치가 우선일 수 있습니다. 자연어 문장은 검색 점수로 정렬하고, 규칙 ID를 알고 있으면 원본 행을 직접 조회하는 두 경로를 나눕니다.

05-3. 샘플 검색 화면 — 실제 M2 CSV를 내장

아래 검색기는 M2의 실제 rules.csv 8행과 rule_tree.csv를 교안 안에 내장해 보여줍니다. 인터넷 연결 없이도 질의와 Top-k 결과를 확인할 수 있습니다. 별도 파일을 다운로드하여 변경했다면 ZIP의 Python 예제로 다시 실행합니다.

이 미리보기는 CSV의 본문 필드를 문자 2~3글자 단위로 분해해 브라우저에서 점수를 계산하는 교육용 구현입니다. 수치가 검색 엔진의 모든 구현과 같다는 뜻은 아닙니다.

05-4. CSV 원본 트리 직접 조회

부모·자식 관계를 저장한 트리 CSV의 규칙 노드는 file=rules.csv와 rule_id=COMP-LINK-001 같은 연결 정보를 가집니다. 트리는 규칙 내용을 복제하지 않고 원본의 위치만 가리킵니다.

from search_engine import lookup_by_tree_node

# rule_tree.csv에서 node_id로 규칙 노드를 찾아,
# file=rules.csv / rule_id=COMP-LINK-001인 원본 행으로 이동
result = lookup_by_tree_node("N_COMP_LINK_001")
print(result.document_id)               # COMP-LINK-001
print(result.metadata["tree_path"])    # 규칙이 속한 전체 트리 경로
print(result.metadata["reference_url"])

실행할 때 file은 무조건 임의의 경로를 열어서는 안 됩니다. 이번 교육용 코드에서는 rules.csv만 허용하고, 트리의 연결 ID와 중복도 검사합니다.

05-5. Python 검색 코드와 결과

from search_engine import build_documents, rank_tfidf, rank_bm25

docs = build_documents()  # M2 rules.csv 중 status=applied 7건
question = "더보기 링크 목적이 모호한 경우"

for engine in (rank_tfidf, rank_bm25):
    print(engine.__name__)
    for document, score in engine(question, docs, top_k=3):
        print(document.document_id, round(score, 4))
        print(document.metadata["source_file"],
              document.metadata["tree_path"])

실제 실행에서는 두 방식 모두 LINK-002가 상위에 나왔습니다. 그러나 사내 규칙과 표준 관련 검사 순위는 방식에 따라 달라질 수 있습니다. 원래 검사 결과의 failed나 cantTell는 검색 점수에 의해 변경되지 않습니다.

구분검색 순위 예시주의점
TF-IDFLINK-002 → COMP-LINK-001 → COMP-LINK-002단어 조각의 상대적 중요도와 벡터 방향
BM25LINK-002 → COMP-LINK-002 → COMP-LINK-001빈도 포화·문서 길이 보정
정확 ID 조회COMP-LINK-001 → 원본 행검색 점수가 아닌 식별자 정확 일치

운영 분리: M2 검사 결과를 API나 MySQL에 저장하는 일은 검사 서비스의 책임입니다. M3는 CSV에서 찾은 관련 문서와 출처를 반환합니다. 검색된 문서는 근거 후보이며, 최종 적합 판정 자체가 아닙니다.

06-2. 이해도 테스트 — 정답 펼쳐보기

문제 1. CSV에 이미 열이 있는데 BoW가 필요한 이유는?

CSV는 규칙의 필드를 구분합니다. BoW는 필드 안의 설명 문장을 검색할 수 있도록 단어 빈도를 수치화합니다.

문제 2. IDF에서 왜 DF가 작을수록 값이 커질까요?

전체 문서에서 덜 흔한 단어일수록 문서를 구분하는 통계적 정보가 더 많다고 가정하기 때문입니다. 드물다는 것이 곧 정답을 보장하지는 않습니다.

문제 3. TF-IDF 점수 0.78이면 표준 준수율 78%인가요?

아닙니다. 질의와 문서의 텍스트 벡터가 유사하다는 뜻이며, HTML 접근성 적합성 판정은 M2 검사기 책임입니다.

문제 4. BM25의 k₁과 b는 각각 어떤 문제를 해결하나요?

k₁은 단어 반복에 따른 점수 증가가 포화되도록 조절하고, b는 문서 길이 보정을 조절합니다.

문제 5. M2의 proposed 규칙을 기본 검색에서 빼야 하는 이유는?

승인·시행되지 않은 규칙을 현재 적용되는 정책으로 잘못 인용하지 않기 위해서입니다. 제안 내역 조사에서는 별도로 포함할 수 있지만 상태가 함께 보여야 합니다.

문제 6. 검색 결과가 COMP-LINK-001이면 어떤 필드로 원본을 찾을까요?

rule_id가 정확한 식별자이고 source_file=rules.csv를 사용합니다. 트리에서는 node_id로 해당 노드의 file·rule_id를 얻고, 이를 원본 행과 연결합니다.

06-3. 추가 실습

  1. 가중치 실험: BM25의 k1과 b를 변경해 세 문서의 점수가 어떻게 달라지는지 비교합니다. 순위가 바뀌지 않아도 이유를 설명해 보세요.
  2. 필터 실험: 샘플 검색 화면에서 표준 관련 규칙만 선택하고 “링크 목적”을 검색합니다. 이후 사내 규칙만 검색하여 결과가 다른 이유를 설명합니다.
  3. 트리 연결 실험: rule_tree.csv에서 COMP-LINK-001의 부모 노드를 따라 올라가 분류 경로를 확인하고, 최종 출처 URL까지 표시합니다.
  4. 승인 상태 실험: 기본 검색의 7건과 proposed 포함 8건의 차이를 비교하되 검토 중인 규칙을 현재 정책으로 안내하지 않습니다.
