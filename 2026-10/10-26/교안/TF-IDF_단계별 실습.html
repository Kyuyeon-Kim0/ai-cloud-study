01. 8개 원본 문장만 사용

이 단계가 필요한 이유

왜 문서 집합을 고정할까? TF-IDF의 IDF는 “전체 문서 중 몇 개에 등장했는지”를 사용합니다. 문서 집합이 달라지면 IDF와 유사도도 달라질 수 있으므로, 먼저 비교 대상인 8개 문장을 고정해야 계산을 재현할 수 있습니다.

여기서 얻는 결과: 원본 8개 문장에만 기준을 맞춘 비교가 가능해집니다.

외부 데이터 없이 아래 8개 문장만 분석합니다. 각 문장을 하나의 문서(D1~D8)로 정의합니다.

02. 분석 전: 토큰·토큰화·옵션 이해

이 단계가 필요한 이유

왜 단어로 분리할까? 컴퓨터는 문장 전체를 그대로는 단어별로 셀 수 없습니다. “링크 이름 후보 확인”을 링크·이름·후보·확인으로 나누어야 각 문서의 공통점과 차이점을 수치로 비교할 수 있습니다.

여기서 얻는 결과: 23개의 서로 다른 단어를 열로 사용하는 행렬을 만들 준비가 됩니다.

토큰(Token)은 분석을 위해 텍스트에서 분리한 단위입니다. 여기서는 공백으로 나뉜 단어를 토큰으로 사용합니다. 토큰화(Tokenization)는 문장을 토큰들로 나누는 과정입니다.

token_pattern은 “어떤 글자 묶음을 단어로 인정할지” 정하는 정규표현식입니다. 기본값 (?u)\b\w\w+\b는 보통 한 글자 토큰을 제외합니다. 이번 예제에서는 r'(?u)\b\w+\b'로 한 글자도 허용합니다. \b는 단어 경계, \w는 단어를 구성하는 문자, +는 한 글자 이상을 뜻합니다. (?u)는 유니코드 단어 처리 플래그입니다.

lowercase=True는 영문 대문자를 소문자로 바꿉니다. 예: ALT → alt. 원문의 영문 표기를 유지하려고 이번에는 lowercase=False를 설정합니다.

sample = "이미지 alt 속성 확인"
print(sample.split())

from sklearn.feature_extraction.text import CountVectorizer
cv = CountVectorizer(token_pattern=r"(?u)\b\w+\b", lowercase=False)
print(cv.fit_transform(docs).shape)
print(cv.get_feature_names_out())
이 예제의 명시된 정규식은 공백뿐 아니라 문장부호도 경계로 처리합니다. 이 8개 문장에서는 공백 기준 분리와 동일한 단어가 나옵니다. 형태소 분석은 사용하지 않습니다.

token_pattern을 글자 단위로 읽기

아래는 단어로 인정할 글자 묶음의 규칙입니다. r은 파이썬에서 백슬래시를 정규표현식 그대로 전달하는 원시 문자열 표기입니다. 화면에 복사된 문자열에 보이지 않는 제어문자가 들어가는 일을 피하려면 코드에서는 반드시 \b를 입력하세요.

token_pattern=r"(?u)\b\w+\b"
부분뜻이번 자료에서의 역할
r"..."원시 문자열\b를 백스페이스 문자가 아닌 정규식으로 전달
(?u)유니코드 단어 해석한글도 단어 문자로 취급
\b단어 경계단어의 시작·끝을 찾음
\w문자·숫자·밑줄 등의 단어 문자이미지, alt 등을 추출
+앞의 문자가 1개 이상한 글자 토큰도 허용

왜 기본값 대신 설정하나? scikit-learn 기본 패턴 r"(?u)\b\w\w+\b"은 단어 문자를 최소 2개 요구합니다. 위 사용자 지정 패턴은 최소 1개만 요구합니다. 현재 8개 문장에서는 한 글자 단어가 없어 결과가 같지만, 짧은 텍스트를 다룰 때 차이가 생길 수 있습니다.

lowercase는 왜 신경 쓸까? lowercase=True는 영문 ALT와 alt를 모두 alt로 바꿉니다. False는 구별합니다. 이번 원문은 alt만 있으므로 결과는 같지만, 원래 입력 형태를 유지한다는 목적에 맞춰 False를 사용합니다.

import re
pattern = r"(?u)\b\w+\b"
print(re.findall(pattern, "이미지 alt 속성 확인"))
print(re.findall(pattern, "A alt 링크"))  # 한 글자 A도 나옴

from sklearn.feature_extraction.text import CountVectorizer
v = CountVectorizer(token_pattern=pattern, lowercase=False)
print(v.build_analyzer()("ALT alt 링크"))

03. TF 행렬: 단어가 문서에 몇 번 나왔나?

이 단계가 필요한 이유

왜 TF(빈도)를 먼저 셀까? 어떤 문서에 무슨 단어가 있는지 알아야 문서별 특징을 비교할 수 있기 때문입니다. 단, 이 8개 문장에서는 한 문장 안에 같은 단어가 반복되지 않아, 등장한 단어의 TF는 1입니다. TF만으로는 흔한 단어와 드문 단어의 중요도를 구별하지 못합니다.

여기서 얻는 결과: 행은 문서, 열은 단어, 셀은 출현 횟수인 8×23 행렬을 얻습니다.

TF(Term Frequency) = 문서 안에서 단어가 등장한 횟수. 이번에는 0 또는 1만 등장합니다. 문서가 행, 단어가 열인 8×23 행렬입니다.

from sklearn.feature_extraction.text import CountVectorizer
import pandas as pd

count = CountVectorizer(token_pattern=r"(?u)\b\w+\b", lowercase=False)
X_tf = count.fit_transform(docs)
terms = count.get_feature_names_out()
df_tf = pd.DataFrame(X_tf.toarray(), index=[f"D{i}" for i in range(1,9)], columns=terms)
print(df_tf.to_string())

04. DF·IDF 계산: 여러 문서에 걸쳐 얼마나 흔한가?

이 단계가 필요한 이유

왜 IDF로 단어의 희소성을 볼까? “확인”처럼 여러 문서에 나오는 말은 문서 구분에 상대적으로 덜 도움이 됩니다. 반대로 “자세히”처럼 특정 문서에만 등장하는 단어는 그 문서를 찾는 데 더 유용합니다. 그래서 문서가 적게 등장한 단어에 더 큰 IDF를 줍니다.

여기서 얻는 결과: 단어마다 모든 문서에서 공통으로 사용할 구별력 가중치(IDF)가 생깁니다.

DF(Document Frequency)는 해당 단어가 나타나는 문서의 개수입니다. IDF(Inverse Document Frequency)는 여러 문서에 공통적으로 등장하는 단어의 가중치를 상대적으로 낮추는 값입니다.

smooth_idf=True: IDF(t) = ln((N + 1) / (DF(t) + 1)) + 1

N=8. 예를 들어 자세히의 DF=1 → IDF=ln(9/2)+1≈2.504, 문구는 DF=3 → IDF=ln(9/4)+1≈1.811입니다. smooth_idf=False라면 IDF=ln(N/DF)+1입니다. 여기서 ln은 자연로그입니다.

import numpy as np

N = len(docs)
df_values = (X_tf.toarray() > 0).sum(axis=0)
idf_values = np.log((N + 1) / (df_values + 1)) + 1

df_idf = pd.DataFrame({"단어": terms, "DF": df_values, "IDF": idf_values})
print(df_idf.round(3).to_string(index=False))
print("자세히:", df_idf[df_idf["단어"] == "자세히"])

05. TF-IDF 행렬: TF × IDF

이 단계가 필요한 이유

왜 TF에 IDF를 곱할까? TF만 보면 문장 안에 한 번 등장한 “확인”과 “자세히”가 똑같이 1입니다. 하지만 IDF를 곱하면 여러 문서에서 흔한 “확인”보다 특정 문서에만 나오는 “자세히”가 더 크게 반영됩니다. 즉 “얼마나 나왔나(TF)”와 “다른 문서와 구별되는가(IDF)”를 결합하는 과정입니다.

여기서 얻는 결과: 이 단계의 값은 원시 TF-IDF 가중치입니다. 문서마다 벡터 길이가 달라 아직 길이를 1로 맞추기 전입니다.

각 문서에서의 단어 빈도(TF)에 단어별 IDF를 곱합니다. 아직 벡터 길이를 1로 만들기 전입니다.

TF-IDF(t, d) = TF(t, d) × IDF(t)
X_raw = X_tf.toarray() * idf_values
df_raw = pd.DataFrame(X_raw, index=df_tf.index, columns=terms)
print(df_raw.round(3).to_string())

06. L2 노름과 길이 1 정규화

이 단계가 필요한 이유

왜 벡터 길이를 1로 맞출까? 문서에 단어가 더 많이 포함되면 TF-IDF 값의 전체 크기도 커질 수 있습니다. 비교할 때 단순한 크기보다 “어떤 단어에 상대적으로 무게가 실렸는가”라는 방향을 보려면, 각 문서의 TF-IDF 벡터를 자신의 L2 길이로 나눕니다.

여기서 얻는 결과: 한 문서의 모든 가중치를 동일한 하나의 수(그 문서의 L2 노름)로 나눈 뒤, 제곱합의 제곱근이 1이 됩니다. 원시 값의 상대 비율은 유지됩니다.

L2 노름(Norm)은 각 원소의 제곱을 더한 뒤 제곱근을 구한 벡터 길이입니다. 각 TF-IDF 가중치를 그 문서 벡터 자신의 길이로 나누면 길이가 1이 됩니다. 모든 원소의 합을 1로 맞추는 게 아닙니다.

||v||₂ = √(w₁² + w₂² + ··· + w₂₃²),   v̂ = v / ||v||₂

D7은 사내 자세히 문구 제한입니다. 영(0)이 아닌 원소만 사용하면 다음과 같습니다.

07. 정규화된 TF-IDF 행렬 (8×23)

이 단계가 필요한 이유

왜 정규화한 행렬을 남길까? 이 행렬이 문서별 특성을 비교하는 최종 숫자 표현이기 때문입니다. 새 질문이 들어오면 같은 단어 열에 맞춰 질문을 변환하고 이 문서 벡터들과 비교합니다.

여기서 얻는 결과: 각 문서가 동일한 23개 단어 축 위의 벡터로 표현됩니다.

TfidfVectorizer(norm="l2")의 최종 출력과 같습니다. 소수점은 보기 편하게 셋째 자리까지 표시했습니다.

from sklearn.feature_extraction.text import TfidfVectorizer

tf = TfidfVectorizer(
    token_pattern=r"(?u)\b\w+\b", # 한 글자 이상 단어 허용
    lowercase=False,                  # 대소문자 원형 유지
    smooth_idf=True,                  # 평활화된 IDF 계산
    norm="l2"                         # 문서 벡터 길이를 1로
)
X = tf.fit_transform(docs)
print(pd.DataFrame(X.toarray(), index=df_tf.index, columns=tf.get_feature_names_out()).round(3).to_string())

08. 코사인 유사도와 자기유사도 (8×8)

이 단계가 필요한 이유

왜 문서끼리 유사도를 계산할까? TF-IDF 행렬만으로는 문서 두 개가 얼마나 비슷한지 직관적으로 판단하기 어렵습니다. 코사인 유사도는 두 벡터의 방향이 얼마나 비슷한지 하나의 점수로 바꿉니다. 같은 문서를 자기 자신과 비교한 자기유사도는 0이 아닌 벡터일 때 1입니다.

여기서 얻는 결과: 대각선은 자기유사도 1, 다른 칸은 서로 다른 문서 간 비교 결과입니다.

코사인 유사도는 두 벡터 사이 각도의 코사인입니다. 두 벡터가 같은 방향이면 1입니다. 이번 TF-IDF 값은 음수가 아니므로 0~1 범위에 있습니다.

cos(A,B) = (A · B) / (||A||₂ × ||B||₂)

자기유사도(Self-similarity)는 D1↔D1처럼 한 문서를 자기 자신과 비교한 값입니다. 내용이 있는 벡터는 자기유사도가 항상 1이므로 아래 행렬의 대각선이 1입니다. 이 행렬은 대칭이어서 D2↔D4와 D4↔D2 값이 같습니다.

from sklearn.metrics.pairwise import cosine_similarity

sim = cosine_similarity(X)
sim_df = pd.DataFrame(sim, index=df_tf.index, columns=df_tf.index)
print(sim_df.round(3).to_string())
print("D7 자기유사도:", sim[6,6])
print("D2-D4 유사도:", round(sim[1,3],3))

이 단계가 필요한 이유

왜 인사이트를 따로 정리할까? 유사도 숫자 자체는 결론이 아닙니다. 어떤 단어가 겹쳐서 가까워졌는지 설명해야 문서군을 묶거나 검색 결과를 해석할 수 있습니다.

여기서 얻는 결과: TF-IDF는 문자·단어의 통계적 공통성을 보여줄 뿐, 접근성 위반 여부나 문장의 의미를 확정하지 않습니다.

10. 전체 코드: 단계를 이해한 후 한번에 실행

이 단계가 필요한 이유

왜 마지막에 통합 코드를 실행할까? 앞 단계에서 입력·계산식·중간 행렬을 확인한 뒤 전체 흐름을 한 번에 검증하기 위한 코드입니다. 처음부터 통합 코드만 실행하면 TF, IDF, 정규화의 차이를 놓치기 쉽습니다.

여기서 얻는 결과: 각 단계의 결과가 연결되어 최종 문서 검색으로 이어지는지 확인할 수 있습니다.

여기까지 각 단계의 코드를 따로 실행했다면, 아래 코드는 확인용 요약입니다. 처음부터 이 코드로 시작하지 않아도 됩니다.

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
import pandas as pd

vectorizer = TfidfVectorizer(
    token_pattern=r"(?u)\w+",
    lowercase=False,
    smooth_idf=True,
    norm="l2"
)
X = vectorizer.fit_transform(docs)
terms = vectorizer.get_feature_names_out()
print("최종 행렬:")
print(pd.DataFrame(X.toarray(), index=[f"D{i}" for i in range(1,9)], columns=terms).round(3).to_string())
print("유사도 행렬:")
print(pd.DataFrame(cosine_similarity(X)).round(3).to_string())
옵션 요약: token_pattern은 단어 인식 규칙, lowercase는 영어 대소문자 처리, smooth_idf는 IDF 평활화, norm은 벡터 길이 정규화 방식입니다.

11. 새로운 질문이 들어오면: TF-IDF로 가장 비슷한 문서 찾기

왜 마지막에 검색을 할까?

지금까지 만든 행렬의 실제 사용 목적은 “사용자가 질문을 입력하면, 미리 준비한 8개 문서 중 표현이 가장 비슷한 것을 찾는 것”입니다. 단어를 단순히 세기만 하는 것이 아니라, 그 숫자 표현을 검색에 이용합니다.

중요: 질문은 검색 입력일 뿐 8개 문서에 추가하지 않습니다. 기존 8개로 학습한 단어 목록과 IDF를 그대로 사용해야 질문과 문서를 같은 기준으로 비교할 수 있습니다.

11-1. 질문 입력

새 질문 예시: 링크 이름 확인 — 기존 문장 중 어느 문장과 단어 구성이 가장 비슷한지 찾습니다.

11-2. 질문도 같은 벡터 공간으로 변환

fit_transform(docs)는 8개 문서로 단어 목록과 IDF를 학습하고 문서 행렬을 만듭니다. transform([question])은 다시 학습하지 않고 기존 23개 단어 열에 맞춰 질문만 벡터화합니다. 학습되지 않은 새 단어는 이 모델에서 점수에 기여하지 못합니다.

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

vectorizer = TfidfVectorizer(
    token_pattern=r"(?u)\b\w+\b",
    lowercase=False,
    smooth_idf=True,
    norm="l2"
)
X_docs = vectorizer.fit_transform(docs)  # 앞에서 준비한 원본 8문장
question = "링크 이름 확인"
X_question = vectorizer.transform([question])
print("문서 행렬:", X_docs.shape)        # (8, 23)
print("질문 벡터:", X_question.shape)  # (1, 23)

11-3. 질문 × 문서 코사인 유사도 계산

질문 벡터는 1개, 문서 벡터는 8개이므로 결과는 1×8 유사도 행렬입니다.

S = cosine_similarity(X_question, X_docs) → (1 × 8)
similarities = cosine_similarity(X_question, X_docs)
print(similarities.round(3))

11-4. 높은 점수순으로 검색 결과 확인

scores = similarities[0]
order = scores.argsort()[::-1]
for idx in order:
    print(f"D{idx+1} | {scores[idx]:.3f} | {docs[idx]}")
해석: 질문의 단어와 많이 겹치고, 그 단어의 IDF 가중치가 높은 문서가 위로 올라옵니다. 이는 검색 후보의 순위이지 질문의 의도를 완벽히 이해했다는 뜻은 아닙니다. 모든 점수가 0이면 현재 단어 목록으로는 유사한 문서를 찾지 못했다는 뜻입니다.

11-5. 다른 질문으로 직접 확인

질문만 바꾸고 기존 vectorizer를 그대로 사용해 보세요. 예: 사내 문구 제한, 입력 필드 확인. 원본 문서는 계속 8개입니다.

question = "사내 문구 제한"
X_question = vectorizer.transform([question])  # fit 금지
scores = cosine_similarity(X_question, X_docs)[0]
for idx in scores.argsort()[::-1]:
    print(f"D{idx+1}: {scores[idx]:.3f} | {docs[idx]}")
