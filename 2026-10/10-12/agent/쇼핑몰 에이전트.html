1교시 실습 · 진짜로 일하는 쇼핑몰 에이전트

에이전트의 원리, 그리고 현실의 문제들

핵심 공식: Agent = LLM + Tools + Loop

도구 몇 개를 쥐여주면, 흐름은 모델이 알아서 만듭니다. "키보드 재고 있어? 3개 사면 얼마야?" 한 마디에 모델이 검색 → 재고확인 → 가격계산을 스스로 순서대로 호출합니다. 우리는 순서를 짜주지 않습니다.

이 노트북의 두 막(幕)

1막 — 기본 에이전트 만들기 (STEP 1~3) 도구 3개 + 루프 하나로 "스스로 도구를 골라 쓰는" 에이전트를 만듭니다. 놀랍도록 간단합니다.

2막 — 그런데 현실은 호락호락하지 않다 (STEP 4~7) 기본 에이전트엔 구멍이 많습니다. 하나씩 터뜨려 보고, 하나씩 막습니다.

STEP 문제 해결
4 모델이 없는 상품명을 지어내 호출 (환각) 함수 안에서 검증 + 힌트 담은 에러
5 도구가 에러를 뱉으면 멈춰버림 에러를 결과로 되먹여 모델이 스스로 복구
6 결제 같은 되돌릴 수 없는 행동 실행 직전 사람 확인 (휴먼인더루프)
7 루프가 무한히 돌면? 비용은? max_turns 상한 + 관찰(LangSmith)

💡 이게 1교시의 진짜 메시지입니다 — 에이전트의 뼈대는 쉽다. 어려운 건 그 뼈대를 현실에서 안전하게 굴리는 것이다.

STEP 2 · 에이전트 작성

  • 여러 gpt툴 작성
    • search_product — 상품 검색 (임베딩)
    • check_stock — 재고 확인
    • calc_price — 가격 계산 (3개 이상 10% 할인)
PYTHON 
def search_product(query):
    return [d.page_content for d in vectordb.similarity_search(query, k=2)]

def check_stock(name):
    p = PRODUCTS.get(name)
    return f"{name}: 재고 {p['stock']}개" if p else f"{name}: 없는 상품"

def calc_price(name, qty):
    p = PRODUCTS.get(name)
    if not p:
        return f"{name}: 없는 상품"
    total = p["price"] * qty
    if qty >= 3:
        total = int(total * 0.9)     # 3개 이상 10% 할인
    return f"{name} {qty}개 = {total}원"

TOOLS = {"search_product": search_product,
         "check_stock": check_stock,
         "calc_price": calc_price}
print(" 도구 3개 준비")

STEP 3 · 에이전트 루프 = 한 함수

패턴은 단순합니다: 모델이 도구를 부르는 한 계속 돌고, 안 부르면(=답할 준비됨) 멈춥니다. max_turns는 무한루프를 막는 안전장치예요 (STEP 7에서 자세히).

PYTHON 
def run_agent(question, max_turns=6):
    messages = [{"role": "user", "content": question}]
    for _ in range(max_turns):
        msg = client.chat.completions.create(
            model="gpt-4o", messages=messages, tools=tools).choices[0].message
        messages.append(msg)

        if not msg.tool_calls:                 # 도구 안 부름 → 최종 답
            return msg.content

        for call in msg.tool_calls:            # 부른 도구 실행 → 결과 되먹임
            args = json.loads(call.function.arguments)
            result = TOOLS[call.function.name](**args)
            print(f"  🔧 {call.function.name}({args}) → {result}")
            messages.append({"role":"tool", "tool_call_id":call.id,
                             "content":json.dumps(result, ensure_ascii=False)})
    return " 최대 단계 수 초과"

print(" 에이전트 완성")

def run_agent_with_usage(question, max_turns=6):
    messages = [{"role": "user", "content": question}]
    total_in = total_out = calls = 0
    for _ in range(max_turns):
        resp = client.chat.completions.create(
            model="gpt-4o", messages=messages, tools=tools)
        u = resp.usage
        total_in += u.prompt_tokens          # ← 매 턴 토큰 누적
        total_out += u.completion_tokens
        calls += 1
        msg = resp.choices[0].message
        messages.append(msg)
        if not msg.tool_calls:
            print("=== 에이전트 (도구 주고) ===")
            print(f"LLM 호출 {calls}회")
            print(f"입력 {total_in} + 출력 {total_out} = 총 {total_in+total_out} 토큰")
            return msg.content
        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            result = TOOLS[call.function.name](**args)
            messages.append({"role":"tool","tool_call_id":call.id,
                             "content":json.dumps(result, ensure_ascii=False)})

STEP 5 · 문제 ② — 도구가 진짜 에러를 뱉으면?

STEP 4는 "정상적으로 없음을 알리는" 경우였습니다. 그런데 도구 코드가 진짜로 터지면 (잘못된 타입, 외부 API 실패 등) 루프 전체가 죽어버립니다.

해결: 실행을 try/except로 감싸고, 에러조차 도구 결과로 되먹인다. 그러면 모델이 에러 메시지를 읽고 인자를 고쳐 다시 시도합니다.

PYTHON 
def run_agent(question, max_turns=6):
    messages = [{"role": "user", "content": question}]
    for _ in range(max_turns):
        msg = client.chat.completions.create(
            model="gpt-4o", messages=messages, tools=tools).choices[0].message
        messages.append(msg)
        if not msg.tool_calls:
            return msg.content

        for call in msg.tool_calls:
            args = json.loads(call.function.arguments)
            try:
                result = TOOLS[call.function.name](**args)
            except Exception as e:
                result = f"에러: {e}. 인자를 확인하고 다시 시도하세요."   # ← 죽지 않고 되먹임
            print(f"  🔧 {call.function.name}({args}) → {result}")
            messages.append({"role":"tool", "tool_call_id":call.id,
                             "content":json.dumps(result, ensure_ascii=False)})
    return "⚠️ 최대 단계 수 초과"

STEP 6 · 문제 ③ — 되돌릴 수 없는 행동 (결제)

지금까지 도구는 전부 읽기(검색·조회·계산)였습니다. 막 불러도 안전했죠. 그런데 결제·주문·메일발송은 부작용이 있습니다. 한 번 실행되면 끝이에요. 모델이 환각으로 checkout을 부르면? 실제 돈이 빠져나갑니다.

해결: 휴먼인더루프 — 실행 직전에 사람 확인을 끼운다. 1교시에서 배운 "모델은 의도만 주고, 실행은 우리가 한다" 는 분리 덕분에 가능합니다. 실행이 우리 손 안에 있으니, 그 직전에 input()으로 사람에게 묻습니다.

STEP 7 · 문제 ④ — 무한루프와 비용

모델이 잘못된 인자로 같은 도구를 계속 재시도하는 루프에 빠질 수 있습니다 (틀린 인자 → 에러 → 같은 틀린 인자 → …). 상한이 없으면 비용과 시간이 폭주합니다.

해결 1: max_turns 상한. 사실 우리 루프엔 이미 있습니다 — for _ in range(max_turns) 의 그 숫자예요.

PYTHON 
# max_turns 를 1로 낮추면, 도구를 다 부르기도 전에 강제 종료된다
print("max_turns=1 (일부러 모자라게):")
print(run_agent("키보드 재고 보고 3개 가격까지 계산해줘", max_turns=1))
실행 결과 보기
max_turns=1 (일부러 모자라게):
  🔧 check_stock({'name': '키보드'}) → 에러: 'check_stock'. 인자를 확인하고 다시 시도하세요.
  🔧 calc_price({'name': '키보드', 'qty': 3}) → 에러: 'calc_price'. 인자를 확인하고 다시 시도하세요.
⚠️ 최대 단계 수 초과

왜 비용이 무서운가 — 에이전트는 매 턴 전체 대화를 다시 보냅니다. 루프가 길어질수록 토큰이 곱으로 불어나요. 그래서 실무에선 턴 수뿐 아니라 총 토큰·총 비용에도 상한을 둡니다.

해결 2: 관찰(observability). 지금 우리는 print로 손수 추적했습니다. 하지만 에이전트가 복잡해지면 print로 쫓기 어렵습니다. 이럴 때 LangSmith 같은 추적 도구를 붙이면 어느 턴에 어떤 도구를 어떤 인자로 불렀고, 토큰을 얼마 썼고, 어디서 틀렸는지 를 자동 기록해 보여줍니다.

💡 LangSmith는 환경변수 LANGSMITH_TRACING=true 와 키만 켜면 코드를 거의 안 바꾸고 작동합니다. 우리가 print로 한 일을, 대시보드에서 턴별로 펼쳐 보여주는 셈이에요. (설정은 이 노트북 범위 밖이라 개념만.)
