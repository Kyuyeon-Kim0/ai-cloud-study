2. Python에서 API 직접 호출

공통 흐름: API 키 설정 → 모델 지정 → 질문 전송 → 응답 출력

설치

pip install openai google-genai anthropic python-dotenv

OPENAI_API_KEY=...

OpenAI

from dotenv import load_dotenv
from openai import OpenAI
load_dotenv()
client = OpenAI()
r = client.responses.create(model="gpt-4.1-mini", input="Docker란?")
print(r.output_text)

Gemini

import os
from dotenv import load_dotenv
from google import genai
load_dotenv()
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
r = client.models.generate_content(model="gemini-2.5-flash", contents="Docker란?")
print(r.text)

Claude

from dotenv import load_dotenv
from anthropic import Anthropic
load_dotenv()
client = Anthropic()
r = client.messages.create(
    model="claude-sonnet-4-5", max_tokens=300,
    messages=[{"role":"user", "content":"Docker란?"}]
)
print("".join(b.text for b in r.content if b.type == "text"))

모델 ID는 학습 당시의 예시입니다. 실제 실행 전 각 플랫폼에서 현재 사용 가능한 모델 ID와 API 권한을 확인하세요. API 구독/과금은 웹 챗봇 구독과 별개일 수 있습니다.

3. GPT · Gemini · Claude 공통 모듈 설계

사용자: 플랫폼 선택 + 모델 ID 직접 입력 + 질문 → service.py → factory.py → 해당 Provider → API 응답
multi_llm/
├── main.py                 # 입력과 출력
├── .env                    # 비밀 키
├── .gitignore
├── requirements.txt
└── llm_core/
    ├── __init__.py
    ├── config.py           # 키 조회
    ├── base.py             # 공통 인터페이스
    ├── factory.py          # Provider 선택
    ├── service.py          # ask_llm()
    └── providers/
        ├── __init__.py
        ├── gpt.py
        ├── gemini.py
        └── claude.py

사용자가 원하는 최종 호출 방식

answer = ask_llm(
    provider="gemini",
    model="gemini-2.5-flash",
    prompt="Docker를 설명해줘"
)

각 Provider는 공통 ask(prompt: str) -> str 인터페이스를 구현하고, 생성자에서 API 키와 모델 ID를 받습니다. Factory는 제공업체를 골라 객체를 생성합니다.

장점: 코드 재사용, API 키 분리, 제공업체 교체, FastAPI·MCP·RAG 프로젝트 확장. 주의: 모델별 출력 형식, 에러, 타임아웃, 모델 지원 여부는 별도 검증이 필요합니다.

5. LangChain의 Chain(체인)

체인은 이전 단계의 출력을 다음 단계의 입력으로 전달합니다. | 연산자를 사용하는 구성을 LCEL이라고 합니다.

pip install langchain-core langchain-google-genai python-dotenv
from dotenv import load_dotenv
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()  # .env에 GOOGLE_API_KEY 설정
llm = ChatGoogleGenerativeAI(model="gemini-2.5-flash")
parser = StrOutputParser()

prompt = ChatPromptTemplate.from_template(
    "{topic}을 초보자에게 쉽게 설명해줘"
)
chain = prompt | llm | parser
print(chain.invoke({"topic": "Docker"}))

여러 단계로 확장

주제 분석 → 상세 설명 → AI 자체 검토 → 최종 요약

각 단계를 별도 체인으로 만들고 연결할 수 있습니다. 순차 체인 외에 병렬 처리, 조건부 분기, 검색 결합(RAG), JSON 구조화 출력도 가능합니다.

LLM을 4번 호출하는 체인은 보통 API 요청도 4회 발생합니다. 자체 검토가 사실 정확성을 보장하지는 않습니다.

6. LangChain의 역사

시기발전
2022년 10월Harrison Chase가 LangChain 오픈소스 프로젝트 시작
2023년LLM 앱·RAG·에이전트 활용 확산, LangSmith와 LCEL 발전
2024년상태 기반 에이전트 오케스트레이션을 위한 LangGraph 성장
2025년LangChain·LangGraph 1.0 발표, 에이전트 중심 구조 강화
2026년LangChain·LangGraph·LangSmith를 통한 개발, 실행, 평가 생태계

LangChain: AI 앱/에이전트 개발 · LangGraph: 상태·분기·반복 관리 · LangSmith: 실행 추적·평가·디버깅·운영.

7. OpenAI API 직접 호출 vs LangChain

항목OpenAI API 직접 사용LangChain
기본 성격모델 제공업체의 APILLM 앱 개발 프레임워크
단순 질문간결하고 적합가능하지만 구성 추가
다중 LLM타사 API는 별도 연동공통 인터페이스 제공
여러 단계Python 코드로 직접 구현LCEL 체인으로 조합
RAG내장 File Search 또는 직접 구성문서·검색 컴포넌트 조합
에이전트OpenAI Agents SDK 등LangChain Agents / LangGraph
장점의존성 적음, 원본 기능 직접 제어재사용성, 조합, 제공업체 전환
단점멀티 모델·복잡한 흐름 직접 관리추상화·의존성·디버깅 복잡성

OpenAI API 직접 제공 주요 기능

Responses API, Web Search, File Search, Code Interpreter, Realtime API, Structured Outputs, Batch API, Agents SDK 등. 다만 일부 기능은 타사에도 유사 기능이 있으므로 모두 OpenAI 독점 기술인 것은 아닙니다.

판단 기준: 단순 챗봇은 직접 API, 멀티 LLM 통합은 LiteLLM, 문서 검색·체인·도구를 함께 다루면 LangChain, 복잡한 상태 기반 에이전트는 LangGraph를 검토하세요.
