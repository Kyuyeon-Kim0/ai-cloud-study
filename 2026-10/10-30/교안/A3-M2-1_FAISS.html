01-3. FAISS로 같은 계산 — IndexFlatL2

같은 계산을 FAISS로 합니다. 만들기 → 넣기 → 찾기 세 동작이 모든 인덱스의 기본입니다.

01_FAISS_기초.ipynb · 01-3
database_size, dimension = db_vectors.shape            # (5, 1) → 5개, 1차원
index = faiss.IndexFlatL2(dimension)                     # 1차원 벡터용 '전수 비교' 인덱스
index.add(db_vectors)                                    # 벡터 5개를 넣는다
print("ntotal:", index.ntotal, "| d:", index.d, "| 학습 필요 없음:", index.is_trained)

k = 5                                                    # 가까운 것 5개
distances, indices = index.search(query_vector, k)
print("distances:", distances)
print("indices  :", indices)
print(distances.dtype, indices.dtype, distances.shape)

한 줄씩 읽기

코드문법과 뜻
database_size, dimension = db_vectors.shape튜플 언패킹. shape (5, 1) → 5, 1
faiss.IndexFlatL2(dimension)Flat = 압축·분할 없이 원본 저장, 전부 비교. L2 = 거리 기준. 인자는 차원 하나
index.add(db_vectors)벡터 추가. 번호는 넣은 순서대로 0, 1, 2… 자동
index.ntotal / index.d / index.is_trained들어 있는 개수 / 차원 / 학습 완료 여부(Flat은 학습이 없어 처음부터 True)
distances, indices = index.search(query_vector, k)가까운 k개. 돌려받는 두 배열: D(거리), I(번호), 둘 다 모양 (질문 수, k)
float32 int64거리는 float32, 번호는 int64. 원문 목록에서 꺼낼 때는 int(i)

02. 거리와 정규화 — 내적·코사인, 꺼내 보기

문장 임베딩 검색은 대부분 코사인 유사도를 씁니다. FAISS에는 ‘코사인 인덱스’가 따로 없습니다. 길이 1로 정규화 + 내적(IP)으로 만듭니다. 왜 그래도 되는지 숫자로 확인합니다.

02-1. 내적(IP)과 코사인 유사도

01_FAISS_기초.ipynb · 02-1
ip = faiss.IndexFlatIP(2)                                # 내적: 클수록 가깝다
ip.add(db2)
print("내적  :", ip.search(query2, 3))

db_n = db2.copy()                                        # 원본을 지키려고 복사
q_n = query2.copy()
faiss.normalize_L2(db_n)                                 # 제자리에서 길이 1로 (반환값 None)
faiss.normalize_L2(q_n)
print("길이:", np.linalg.norm(db_n, axis=1).round(3))

cos = faiss.IndexFlatIP(2)
cos.add(db_n)
print("코사인:", cos.search(q_n, 3))

코드문법과 뜻
faiss.IndexFlatIP(2)IP = Inner Product(내적). L2와 반대로 클수록 가깝다. 결과도 큰 순
db_n = db2.copy()정규화는 원본을 바꿔 버리므로 복사본
faiss.normalize_L2(db_n)각 행을 길이 1로 제자리에서 바꿈. 반환값 None — x = faiss.normalize_L2(x)로 쓰면 x가 None이 됨
np.linalg.norm(db_n, axis=1)행마다 길이. 모두 1.0이면 정규화 완료

04. K-means — 비슷한 것끼리 묶는 원리와 faiss.Kmeans 문법

IVF 인덱스도, PQ 압축도 안에서 K-means를 돌립니다. 그래서 K-means가 어떻게 움직이는지, 어떤 때 잘못 묶는지를 먼저 손으로 확인합니다. 눈으로 보이는 2차원 점 12개로 시작합니다.

비유로 먼저

택배 물류센터 3곳의 위치를 정한다고 합시다. ① 일단 아무 데나 3곳을 찍고 ② 집마다 가장 가까운 센터를 배정하고 ③ 센터를 배정받은 집들의 한가운데로 옮깁니다. ②와 ③을 센터가 더 움직이지 않을 때까지 반복하면 끝입니다. 이 ‘배정 → 이동’ 반복이 K-means의 전부입니다.

def kmeans_step_by_step(x, init_idx, n_iter=10):
    x = x.astype(np.float64)
    C = x[init_idx].copy()                                     # 시작 중심 = 고른 점들
    print("시작 중심:", C.tolist())
    for it in range(1, n_iter + 1):
        d2 = ((x[:, None, :] - C[None, :, :]) ** 2).sum(axis=2)  # [12, 3] 점마다 세 중심까지 제곱거리
        assign = d2.argmin(axis=1)                              # ① 배정: 가장 가까운 중심 번호
        obj = d2[np.arange(len(x)), assign].sum()              # 오차 = 자기 중심까지 거리의 합
        newC = np.array([x[assign == c].mean(axis=0) for c in range(len(C))])   # ② 갱신: 평균 위치로
        print(f"반복 {it}: 소속 {assign}  오차 {obj:6.2f}  → 새 중심 {newC.round(2).tolist()}")
        if np.allclose(newC, C):
            print("   중심이 그대로 → 수렴(멈춤)")
            break
        C = newC
    return C, assign

print("[A] 시작 중심을 0, 1, 8번 점으로")
kmeans_step_by_step(x, [0, 1, 8])
print("\n[B] 시작 중심을 0, 4, 8번 점으로")
kmeans_step_by_step(x, [0, 4, 8])

05. IVF — 묶어 담고, 몇 묶음만 뒤진다

IVF(Inverted File)는 ① K-means로 중심 nlist개를 만들고(train) ② 벡터마다 가장 가까운 중심의 목록에 넣고(add) ③ 질문이 오면 가까운 중심 nprobe개의 목록만 비교합니다(search). 세 단계를 작은 예제로 하나씩 열어 봅니다.

비유로 먼저

도서관이 책을 주제별 서가(목록)에 꽂아 둡니다. 질문이 오면 서가 안내판(중심점)만 보고 가장 관련 있는 서가 1~2개로 가서 그 안의 책만 펼쳐 봅니다. 서가 수가 nlist, 찾아가는 서가 수가 nprobe입니다. 안내판을 정하는 일이 train(K-means)입니다.

trainK-means → 중심 nlist개를 quantizer에
→
add벡터마다 가까운 중심의 목록에
→
search 1단계질문 ↔ 중심 nlist개
→
search 2단계가까운 nprobe개 목록 안만 비교

06. IVF 실전 — nprobe·nlist 고르기, 데이터가 바뀔 때

2만 개·64차원 데이터로 nprobe와 nlist를 바꿔 가며 정확도(recall)와 거리 계산 횟수를 잽니다. FAISS가 직접 세 주는 계산 횟수를 보면 ‘왜 빨라지는지’가 숫자로 보입니다. 마지막으로 새 주제의 데이터가 몰려올 때 IVF가 어떻게 기우는지 확인합니다.

06-1. 2만 개로 실험 — nprobe별 정확도·거리 계산 수·시간

import faiss, time
import numpy as np

rng = np.random.default_rng(0)
d, n, k = 64, 20000, 10
centers = rng.normal(0, 10, (50, d)).astype("float32")          # 숨은 주제 50개
xb = (centers[rng.integers(0, 50, n)] + rng.normal(0, 1, (n, d))).astype("float32")   # 문서 2만 개
xq = (centers[rng.integers(0, 50, 100)] + rng.normal(0, 1, (100, d))).astype("float32")  # 질문 100개

flat = faiss.IndexFlatL2(d)
flat.add(xb)
t = time.perf_counter(); _, I_true = flat.search(xq, k); t_flat = time.perf_counter() - t

def recall(I):                     # 정답(전수 비교) k개 중 몇 개를 찾았나, 평균
    return np.mean([len(set(I[i]) & set(I_true[i])) / k for i in range(len(I))])

print(f"문서 {xb.shape}, 질문 {xq.shape}, Flat 검색 {t_flat*1000:.1f} ms (질문 100개)")

nlist = 100
ivf = faiss.IndexIVFFlat(faiss.IndexFlatL2(d), d, nlist)
ivf.train(xb)
ivf.add(xb)
sizes = [ivf.invlists.list_size(i) for i in range(nlist)]
print(f"목록 크기: 최소 {min(sizes)}, 최대 {max(sizes)}, 평균 {np.mean(sizes):.0f}")
for p in [1, 2, 4, 8, 16, 100]:
    ivf.nprobe = p
    faiss.cvar.indexIVF_stats.reset()                  # FAISS가 센 거리 계산 횟수 초기화
    t = time.perf_counter(); _, I = ivf.search(xq, k); el = time.perf_counter() - t
    ndis = faiss.cvar.indexIVF_stats.ndis / len(xq)    # 질문 1개당
    print(f"nprobe={p:<3} recall={recall(I):.3f}  질문당 거리계산 {ndis:7.0f}번 (Flat {n})  {el*1000:5.1f} ms")

07. PQ·SQ — 벡터를 압축해서 저장하기

IVF가 ‘어디를 뒤질지’를 줄였다면 PQ·SQ는 ‘벡터 하나의 크기’를 줄입니다. 384차원 float32 벡터는 1,536바이트입니다. 1억 개면 150GB. PQ는 이것을 수십 바이트로 줄입니다. 원리를 4차원 벡터로 손계산합니다.

비유로 먼저

긴 주소 ‘서울시 강남구 테헤란로 123’을 그대로 적지 않고, 시·구·도로를 각각 미리 정한 번호표(코드북)에서 골라 ‘3-17-205’처럼 적는 것과 같습니다. 벡터를 조각(M개)으로 자르고, 조각마다 K-means로 만든 대표값 중 가장 가까운 번호만 저장합니다.

07-1. 준비 — 2만 개 데이터

import faiss, time
import numpy as np

rng = np.random.default_rng(0)

    return np.mean([len(set(I[i]) & set(I_true[i])) / k for i in range(len(I))])

print(f"문서 {xb.shape}, 질문 {xq.shape}, Flat 검색 {t_flat*1000:.1f} ms (질문 100개)")

rng2 = np.random.default_rng(1)
xt = rng2.normal(0, 1, (2000, 4)).astype("float32")   # 학습용 4차원 벡터
pq = faiss.ProductQuantizer(4, 2, 2)                  # d=4, M=2조각, nbits=2 → 조각마다 대표값 2²=4개
pq.train(xt)
print("조각 수 M:", pq.M, "| 조각 차원 dsub:", pq.dsub, "| 대표값 수 ksub:", pq.ksub)

codebook = faiss.vector_to_array(pq.centroids).reshape(pq.M, pq.ksub, pq.dsub)
for m in range(pq.M):
    print(f"조각 {m} 코드북 (대표값 {pq.ksub}개):", codebook[m].astype(float).round(2).tolist())

v = xt[0]
print("\n원본 벡터:", v.astype(float).round(2).tolist())
code = []
for m in range(pq.M):
    sub = v[m * pq.dsub:(m + 1) * pq.dsub]                     # m번째 조각
    dist = ((codebook[m] - sub) ** 2).sum(axis=1)              # 대표값 4개까지 거리
    code.append(int(dist.argmin()))
    print(f"조각 {m} {sub.astype(float).round(2).tolist()} → 대표값 거리 {dist.astype(float).round(2).tolist()} → 번호 {code[-1]}")
print("손으로 만든 코드:", code)

approx = np.concatenate([codebook[m][code[m]] for m in range(pq.M)])
print("코드로 되살린 벡터:", approx.astype(float).round(2).tolist())
print("faiss decode     :", pq.decode(pq.compute_codes(v[None]))[0].astype(float).round(2).tolist())

07-3. 압축된 벡터와 거리 재기 — 거리표(ADC)

압축된 벡터와 질문의 거리는 어떻게 잴까요? 질문을 압축하지 않고, 질문 조각과 대표값들의 거리표를 한 번만 만들어 둔 뒤 코드로 표에서 꺼내 더합니다(ADC, 비대칭 거리 계산).

08. HNSW — 이웃 그래프를 층층이 따라가기

HNSW(Hierarchical Navigable Small World)는 Chroma·Qdrant·pgvector·OpenSearch의 기본 인덱스입니다. 학습이 없고 정확도가 높아 가장 많이 쓰입니다. 점 30개짜리 그래프를 실제로 들여다보고, 검색이 그래프를 어떻게 타고 내려가는지 한 걸음씩 따라갑니다.

비유로 먼저

모르는 동네의 한 집을 찾아갈 때 고속도로(맨 위층, 점이 아주 적음)로 근처 도시까지 가고, 국도(중간층)로 동네 입구까지, 골목길(맨 아래층, 모든 점)로 집 앞까지 갑니다. 층마다 ‘지금보다 목적지에 가까운 이웃이 있으면 그쪽으로 한 칸’만 반복합니다.

설정뜻언제 정하나올리면
M점마다 연결하는 이웃 수 (맨 아래층은 2M)만들 때정확도 ↑, 메모리 ↑, 만들기 느려짐
efConstruction만들 때 이웃 후보를 얼마나 넓게 볼지만들 때 (add 전)그래프 품질 ↑, 만들기 느려짐
efSearch검색할 때 맨 아래층에서 들고 다니는 후보 수검색할 때 언제든정확도 ↑, 검색 느려짐

def search_layer0(ep, ef):                            # 맨 아래층: 후보를 ef개까지 넓게 들고 탐색
    global ndis
    visited = {ep}
    cand = [(dist(ep), ep)]                            # 앞으로 볼 후보 (가까운 순)
    top = [(-dist(ep), ep)]                            # 지금까지 찾은 좋은 점 ef개 (먼 것이 맨 위)
    while cand:
        dc, c = heapq.heappop(cand)
        if len(top) >= ef and dc > -top[0][0]:
            break                                      # 남은 후보가 다 지금 결과보다 멀면 끝
        for nb in neighbors(c, 0):
            if nb in visited:
                continue
            visited.add(nb); ndis += 1
            dn = dist(nb)
            if len(top) < ef or dn < -top[0][0]:
                heapq.heappush(cand, (dn, nb)); heapq.heappush(top, (-dn, nb))
                if len(top) > ef:
                    heapq.heappop(top)
    return sorted((-dneg, i) for dneg, i in top), visited

def load_store(folder, expect_model=None):
    folder = Path(folder)
    manifest = json.loads((folder / "manifest.json").read_text(encoding="utf-8"))
    if expect_model and manifest["model"] != expect_model:
        raise ValueError(f"모델 불일치: 저장={manifest['model']} / 지금={expect_model}")
    index = faiss.read_index(str(folder / "index.faiss"))
    docs = {int(k): v for k, v in json.loads((folder / "docs.json").read_text(encoding="utf-8")).items()}
    assert index.ntotal == manifest["count"] == len(docs), "개수가 맞지 않음"
    return index, docs, manifest

def evaluate(test_cases, k=3):
    hit1 = hit3 = 0
    for q, gold in test_cases:
        got = [h[0] for h in search(q, k)]
        hit1 += got[:1] == [gold]
        hit3 += gold in got
        mark = "O" if got[:1] == [gold] else ("△" if gold in got else "X")
        print(f"{mark} {q:<22} 정답 {gold} 검색 {got}")
    n = len(test_cases)
    print(f"Hit@1 = {hit1}/{n} = {hit1/n:.2f}   Hit@3 = {hit3}/{n} = {hit3/n:.2f}")

15. 정리 — FAISS 문법 한 장

다음 모듈(Chroma)에서는 FAISS에서 직접 만든 원문 저장·필터·영속화를 DB가 대신해 주는 모습을 봅니다. 내부 인덱스는 이 모듈의 HNSW입니다.

하고 싶은 일문법
만들기IndexFlatL2(d), IndexFlatIP(d), IndexIVFFlat(IndexFlatL2(d), d, nlist), IndexHNSWFlat(d, M), index_factory(d, "IVF100,SQ8")
학습·넣기train(x) (IVF·PQ·SQ) → add(x) / add_with_ids(x, ids)
찾기D, I = search(q, k), params=SearchParameters(sel=IDSelectorBatch(ids)), SearchParametersIVF(nprobe=)
손잡이ivf.nprobe, hnsw.hnsw.efSearch, hnsw.hnsw.efConstruction(add 전)
들여다보기invlists.list_size(c), rev_swig_ptr(get_ids(c), n), hnsw.levels, indexIVF_stats.ndis, hnsw_stats.ndis
꺼내기·삭제reconstruct (IDMap2), remove_ids (HNSW 불가)
군집Kmeans(d, k, niter, nredo, seed, spherical) → train → index.search(x, 1)
저장write_index / read_index, serialize_index / deserialize_index + docs.json + manifest.json

15-1. OpenSearch로 가져갈 다섯 가지

  1. HNSW의 m · ef_construction은 만들 때, ef_search는 검색할 때 정한다. recall과 속도를 평가 질문으로 잰다.
  2. IVF는 학습(train)이 필요하고, 데이터 분포가 바뀌면 다시 학습한다. nlist·nprobes는 √N과 recall 목표로 정한다.
  3. PQ·SQ(encoder)는 메모리를 줄이는 대신 정확도를 낸다. SQ8이 무난한 출발점이다.
  4. 코사인은 정규화 + 내적. 인덱스와 질문이 같은 모델·같은 정규화인지 항상 확인한다.
  5. RAG는 검색 결과를 그대로 쓰지 않는다. 중복 제거·다양화·필터를 거쳐 근거를 고른다.
