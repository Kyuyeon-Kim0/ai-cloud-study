00. 벡터 DB 지도 — ‘DB에 벡터를 붙이기’와 ‘전용 벡터 DB’

벡터 검색 도구는 크게 두 갈래입니다. 이미 쓰는 데이터베이스에 벡터 열을 붙이는 방식(pgvector, OpenSearch, Redis …)과, 벡터 검색만을 위해 만든 전용 DB(Qdrant, Milvus, Weaviate, Pinecone …)입니다. 이 모듈은 각 갈래의 대표인 pgvector와 Qdrant를 실습합니다.

이 모듈에서 할 일

pgvector로 PostgreSQL 테이블에 벡터 열을 만들고, SQL로 검색·필터·JOIN을 합니다. HNSW·IVFFlat 인덱스를 만들어 실행 계획과 정확도를 확인하고, 필터와 인덱스가 만날 때 생기는 문제를 재현합니다. Qdrant로는 점(point)·payload 구조와 Filter 문법 전체를 익힙니다. 마지막으로 같은 쇼핑몰 Q&A를 두 DB로 만들어 문법과 결과를 비교합니다.

01. pgvector — PostgreSQL에 벡터 열 붙이기

pgvector는 PostgreSQL 확장입니다. 설치하면 vector(차원)이라는 열 종류와 거리 연산자, HNSW·IVFFlat 인덱스가 생깁니다. 벡터 DB를 따로 운영하지 않고 기존 DB에서 RAG를 할 수 있다는 것이 가장 큰 장점입니다.

PostgreSQL테이블·SQL·트랜잭션
→
+ pgvectorvector 열 · 거리 연산자 · 인덱스
→
psycopg파이썬 접속
→
pgvector.psycopgnumpy ↔ vector 변환

01-1. 접속과 확장 켜기

01_pgvector_시작하기.ipynb · 01-1
import os, psycopg, numpy as np
from pgvector.psycopg import register_vector

# Docker로 띄운 PostgreSQL(pgvector 포함)에 접속. 다른 주소면 환경변수 PG_DSN으로 바꾼다
DSN = os.getenv("PG_DSN", "postgresql://postgres:postgres@localhost:5432/postgres")
conn = psycopg.connect(DSN, autocommit=True)          # autocommit: 문장마다 바로 반영
conn.execute("CREATE EXTENSION IF NOT EXISTS vector")  # pgvector 켜기 (DB마다 한 번)
register_vector(conn)                                   # numpy 배열 ↔ vector 자동 변환
print("PostgreSQL:", conn.execute("SHOW server_version").fetchone()[0])
print("pgvector  :", conn.execute("SELECT extversion FROM pg_extension WHERE extname = 'vector'").fetchone()[0])

03. 검색은 ORDER BY 거리 LIMIT k — 필터는 그냥 WHERE

pgvector 검색은 새 문법이 아니라 평범한 SQL입니다. ‘거리 순으로 정렬해서 위에서 k개’. 필터는 WHERE, 다른 표와의 결합은 JOIN입니다. Chroma의 where 사전이 그대로 SQL이 됩니다.

03-1. 검색 SQL — ORDER BY 거리 LIMIT k

03-3. 파이썬 검색 함수와 평가

01_pgvector_시작하기.ipynb · 03-3
from shop_faq import TESTS
def search(question, k=3, cat=None):
    v = emb.encode([question], kind="query")[0]
    where, params = ("WHERE cat = %s", [cat]) if cat else ("", [])
    rows = conn.execute(f"""SELECT id, 1 - (embedding <=> %s) FROM faq {where}
                            ORDER BY embedding <=> %s LIMIT %s""", [v, *params, v, k]).fetchall()
    return [(int(i), round(float(s), 3)) for i, s in rows]

print(search("택배 언제 와요?"))
hit1 = sum(search(q, 1)[0][0] == g for q, g in TESTS)
print(f"Hit@1 {hit1}/{len(TESTS)}")

08. Filter — must · should · must_not

Qdrant의 필터는 세 칸짜리 상자입니다. must(모두 만족, AND), should(하나 이상, OR), must_not(하나도 만족하지 않음, NOT). 각 칸에 조건(FieldCondition 등)을 목록으로 넣습니다.

Filter 상자
칸뜻SQL로 읽으면
must=[A, B]A AND BWHERE A AND B
should=[A, B]A OR BWHERE A OR B
must_not=[A]NOT AWHERE NOT A
must=[A], must_not=[B]A AND NOT BWHERE A AND NOT B
조건문법뜻
값 같음FieldCondition(key="cat", match=MatchValue(value="환불"))cat = '환불'
목록 중 하나match=MatchAny(any=["환불", "교환반품"])cat IN (…)
목록이 아님match=MatchExcept(**{"except": ["환불"]})cat NOT IN (…)
범위FieldCondition(key="year", range=Range(gte=2025, lt=2027))2025 ≤ year < 2027
배열에 값FieldCondition(key="tags", match=MatchValue(value="자주묻는질문"))배열 payload는 원소 중 하나와 비교
id 범위HasIdCondition(has_id=[301, 302])이 id들 중에서
값이 비었나IsEmptyCondition(is_empty=PayloadField(key="tags"))키가 없거나 빈 값

12. 정리 — A3 벡터 검색 전체

A3-M1에서 문장을 토큰과 벡터로 바꾸고, M2에서 FAISS로 빠르게 찾는 원리를, M3·M4에서 그것을 DB로 운영하는 법을 익혔습니다. 다음 과정 OpenSearch는 이 모두를 한 검색엔진 안에서 합니다.

단계모듈핵심
문장 → 조각A3-M1토크나이저(형태소·서브워드·tiktoken), 토큰 기반 유사도
조각 → 벡터A3-M1임베딩(e5, OpenAI), 정규화 + 내적 = 코사인
빠르게 찾기A3-M2Flat → IVF(nlist·nprobe) · PQ·SQ · HNSW(M·ef), 클러스터로 다양화
DB로 운영A3-M3·M4컬렉션·테이블, 필터(where·WHERE·Filter), upsert 동기화, 인덱스 설정
다음: OpenSearch—knn_vector(faiss 엔진의 HNSW·IVF) + BM25 하이브리드 + 필터

12-1. 꼭 기억할 다섯 가지

  1. pgvector 검색은 ORDER BY 거리 LIMIT k, 필터는 WHERE. 인덱스 ops와 연산자는 짝을 맞추고 EXPLAIN으로 확인한다.
  2. HNSW + 필터는 결과가 모자랄 수 있다. ef_search, 부분 인덱스, iterative_scan, 필터를 함께 적용하는 DB로 해결한다.
  3. Qdrant는 점 = id + 벡터 + payload, 필터는 must·should·must_not. 폴더 모드는 전수 비교다.
  4. 점수의 방향을 확인한다: Chroma·pgvector는 거리(작을수록), Qdrant는 score(클수록).
  5. DB가 달라도 같은 벡터면 결과는 같다. 품질은 임베딩과 평가, 속도는 인덱스 설정, 운영은 동기화와 필터가 정한다.
