형태소 분석은 왜 필요한가?

“배달이 너무 늦었어요”를 의미 단위로 나누면 VOC의 공통 표현을 찾기 쉽습니다.

구분결과한계/효과
원문배달이 너무 늦었어요그대로는 표현 비교가 어려움
공백 분리배달이 / 너무 / 늦었어요조사와 어미가 남음
형태소 분석배달/명사 · 이/조사 · 너무/부사 · 늦/형용사품사와 의미 단위를 구분
왜 필요한가? 표현이 다른 문장에서도 배달·늦다와 같은 공통 정보를 찾는 데 도움이 됩니다.

업무에서 필요한 이유

고객이 “배달이 늦어요”, “배달이 늦었습니다”, “배달 지연이 심해요”라고 썼을 때 공백으로만 나누면 ‘늦어요’와 ‘늦었습니다’는 다른 문자열입니다. 형태소 분석은 활용된 표현을 분석하고 품사 정보를 제공하여 공통 표현을 찾아볼 출발점을 마련합니다. 단, ‘배달 지연’이라는 업무 이슈로 묶는 일은 별도의 규칙이나 AI 판정이 필요합니다.

수업 목표: 문장 전체를 무작정 세는 대신, 무엇(명사)·어떤 행위(동사)·어떤 평가(형용사)·얼마나(부사)를 구분하는 이유를 이해합니다.

토큰화와 형태소 분석은 다릅니다

토큰화는 처리 단위로 나누는 넓은 개념이고 형태소 분석은 문법 정보를 판별합니다.

개념설명예
어절 분리공백 기준배달이 / 늦었어요
토큰화작업에 필요한 단위로 분리단어·형태소·서브워드
형태소 분석형태소와 품사 판별배달/NNG · 이/JKS
정규화표현 통일늦었어요 → 늦다
왜 필요한가? Kiwi는 한국어 형태소 분석기입니다. LLM의 서브워드 토크나이저와 같은 목적의 도구가 아닙니다.

토큰과 형태소의 차이를 실제 문장으로

‘배달이’는 공백 기준으로 하나의 어절이지만, 형태소 분석에서는 ‘배달/NNG’와 ‘이/JKS’처럼 나뉠 수 있습니다. ‘늦었어요’도 어간과 어미가 구분됩니다. 토큰은 프로그램이 반환하는 분석 단위이며, 형태소는 문법적 의미나 기능을 가진 단위입니다.

형태소 분석기는 품사를 예측하는 도구입니다. 예컨대 ‘배’는 과일일 수도 신체일 수도 있으므로 주변 문맥이 중요합니다. 분석 결과를 언제나 정답으로 취급하지 않고 원문과 대조해야 합니다.

고전적인 형태소 분석기 종류

분석기마다 사전·모델·품사 체계가 달라 같은 문장도 결과가 달라질 수 있습니다.

도구특징학습 관점
HannanumKAIST 계열 형태소·품사 분석전통적인 분석
Kkma세분화된 품사, 문장 분리문법 구조
Komoran세종 기반 품사, 사용자 사전정형 문서
MeCab-ko사전·통계 기반의 빠른 처리대량 데이터
OktSNS 표현 정규화·어간 추출 옵션댓글·리뷰
Kiwi문맥 분석·위치·사용자 단어·오타 처리이번 실습
왜 필요한가? KoNLPy는 여러 분석기를 Python에서 사용하게 하는 패키지이고, Kiwi는 별도의 kiwipiepy 패키지입니다.

왜 분석기마다 결과가 다른가?

사전에 들어 있는 단어, 어미를 분리하는 방식, 품사 태그의 세분화, 학습 데이터가 다르기 때문입니다. Okt는 비교적 단순한 품사 체계로 SNS 문장을 실습하기 편하고, Kkma는 세분화된 태그로 문법을 자세히 볼 수 있습니다. MeCab-ko는 사전 기반 분석을 빠르게 수행하는 용도로 많이 쓰입니다. 속도·정확도 순위는 데이터와 실행 환경에 따라 달라집니다.

KoNLPy 주의: KoNLPy는 여러 분석기를 Python에서 사용하도록 돕는 패키지이고, Kiwi는 kiwipiepy 패키지로 별도 사용합니다. 두 이름을 같은 분석기로 혼동하지 않습니다.

왜 기존 분석기 설치가 어렵다고 느낄까?

형태소 분석은 Python 코드만으로 끝나지 않는 경우가 있습니다. Java 기반 분석기는 JDK/JVM과 Python 연결 설정이 필요할 수 있고, MeCab-ko는 운영체제에 따라 엔진·사전 설치와 빌드 절차가 추가될 수 있습니다. 특히 Windows에서 강의실 PC 여러 대를 맞추면 환경별 차이가 수업 시간을 잡아먹습니다. 반면 Kiwi의 Python 바인딩인 kiwipiepy는 지원되는 환경에서 pip 설치만으로 시작하기 쉬워 초보 실습에 적합합니다.

도구 계열설치에서 확인할 점수업에 미치는 영향
Hannanum·Kkma·Komoran 등Java/JVM, 관련 Python 연동 환경Java 설치·경로 설정 점검이 필요할 수 있음
MeCab-ko엔진·사전·운영체제별 패키지환경에 따라 설치 절차가 달라질 수 있음
OktJava 연동 환경 등일부 환경에서 추가 설정 필요
Kiwi / kiwipiepy지원 Python 버전과 배포 패키지py -m pip install kiwipiepy로 시작 가능
주의: 모든 기존 분석기가 항상 설치하기 어려운 것은 아닙니다. 패키지·운영체제·Python 버전에 따라 차이가 있고, Kiwi 역시 미지원 환경에서는 설치 문제가 발생할 수 있습니다.

Kiwi의 특징과 한계

Kiwi를 사용하는 이유와 Kiwi만으로 해결되지 않는 일을 구분합니다.

Kiwi가 제공하는 기능VOC 활용
형태소·품사 분석명사·동사·형용사·부사 구분
원문 위치 정보분석 근거 추적
사용자 단어 등록브랜드·상품명 처리
오타 관련 기능비표준 고객 표현 대응
왜 필요한가? Kiwi가 고객 감정·심각도·환불 요구까지 자동으로 완벽하게 판정하는 것은 아닙니다. 별도 업무 규칙이나 AI 판정이 필요합니다.

Kiwi로 할 수 있는 일과 할 수 없는 일

Kiwi는 형태소 경계와 품사를 분석하고 토큰의 원문 위치를 알려줍니다. 사용자 사전으로 고유한 상품명 등을 보완할 수 있으며 오타에 대응하는 옵션도 있습니다. 반면 “환불이 필요한 긴급 불만인지”, “배송 담당 부서가 어디인지” 같은 업무 판정은 Kiwi 자체의 출력이 아닙니다.

VOC에서는 Kiwi로 후보 단어를 추출한 뒤, 필요하면 표준화 규칙과 LLM 판정을 연결합니다. 이 구분을 이해해야 형태소 분석 결과를 곧바로 감정분석 결과로 오해하지 않습니다.

VOC에서 Kiwi를 선택하는 이유

현업 문제Kiwi가 주는 도움검수할 점
"늦었어요", "늦고" 등 활용형이 다름형태소·어미 분해로 비교 가능한 후보 생성같은 의미로 묶을지 확인
"배달앱", 브랜드·상품명사용자 사전으로 도메인 단어 보완사전 등록 전후 결과 비교
오타·구어체 VOC오타 관련 분석 기능 활용 가능원문을 임의로 덮어쓰지 않기
AI가 명사·형용사 열을 잘못 작성품사·원문 위치로 검수 후보 만들기최종 의미 판단은 별도 수행
핵심: Kiwi를 선택하는 이유는 설치 편의성 하나가 아니라 한국어 형태소 분석 + 품사·위치 정보 + 도메인 사전 + 검증 가능한 구조화 출력을 한 도구에서 활용할 수 있기 때문입니다.

Kiwi를 이용한 메타데이터 정합성 검증

여기서 메타데이터는 VOC 원문을 분석해 붙인 명사·동사·형용사·카테고리 등의 구조화 정보입니다. 정합성은 이 정보가 원문 및 분석 규칙과 어긋나지 않는지를 뜻합니다.

불일치 후보
원문: 배달이 너무 늦었어요
AI 명사_대상: 결제
원문에 근거가 없는 대상이 기록됨
Kiwi 교차 확인
명사 후보: 배달
부사 후보: 너무
행위·상태 후보: 늦다
원문에서 확인되는 품사 후보와 비교

왜 별도 검증이 필요한가?

AI가 생성한 분석표는 형식이 맞더라도 내용이 틀릴 수 있습니다. 예를 들어 명사_대상에 원문과 무관한 단어가 들어가거나, 형용사_평가에 동사가 들어갈 수 있습니다. Kiwi 결과와 대조하면 검토할 행을 자동으로 좁힐 수 있습니다. 단, Kiwi도 오류가 가능하며 동의어·생략·문맥 추론 때문에 단순 문자열 불일치가 반드시 오류는 아닙니다.

검사 항목검사 방법최종 처리
품사 일치AI가 적은 단어의 Kiwi 품사 확인불일치 후보 표시
원문 근거토큰 위치·원문 표현 대조원문으로 재확인
카테고리 타당성추출 단어와 업무 분류표 대조업무 규칙·사람이 판단
중요한 구분

Kiwi = 형태소 분석 도구, Kiwi 기반 정합성 검증 = Kiwi 결과를 활용해 별도로 설계한 검사 절차입니다. Kiwi 자체가 VOC 메타데이터의 진위를 보증하지는 않습니다.

초간단 검수 코드

AI 결과의 명사 후보를 대조해 보기

from kiwipiepy import Kiwi

kiwi = Kiwi()
text = "배달이 너무 늦었어요"
ai_noun = "결제"

nouns = []
for token in kiwi.tokenize(text):
    if token.tag.startswith("NN"):
        nouns.append(token.form)

print("Kiwi 명사 후보:", nouns)
print("검토 필요:", ai_noun not in nouns)
출력 형태 예시 · Kiwi 명사 후보: ['배달'] / 검토 필요: True. 이는 자동 오답 확정이 아닌 검토 알림입니다. 명사 품사 태그는 일반명사·고유명사 등을 포함합니다.

for t in kiwi.tokenize(text):

출력은 학습용 예시입니다. 실제 어미 분해는 설치된 Kiwi에서 확인하세요.

처음 실행할 때 점검할 것

Windows PowerShell에서 py -m pip install kiwipiepy pandas를 실행합니다. 가상환경을 사용 중이면 해당 환경의 Python으로 설치해야 합니다. 설치가 성공해도 편집기의 인터프리터가 다르면 ModuleNotFoundError가 발생할 수 있습니다.

kiwi = Kiwi()는 분석기를 준비하는 단계이고, kiwi.tokenize(text)가 실제 문장을 분석합니다. 첫 실행은 모델 로딩 때문에 이후 실행보다 시간이 걸릴 수 있습니다.

개념 · 사례 · 코드 · 해석

토큰 객체 이해하기

form, tag, start, len은 토큰을 이해하는 가장 중요한 속성입니다.

속성뜻왜 보나
form형태소 문자열단어 추출
tag품사 태그품사별 필터
start원문 시작 위치근거 추적
len원문 대응 길이범위 확인
text = "음식이 맛있어요."
for t in kiwi.tokenize(text):
    print(t.form, t.tag, t.start, t.len)
왜 필요한가? 분석된 기본형과 원문 표면형이 다를 수 있습니다. 원문은 따로 보존해야 합니다.

토큰의 위치 정보가 중요한 이유

form은 분석된 형태소 문자열, tag는 품사, start는 원문 내 시작 위치, len은 길이입니다. 위치 정보로 원문의 어느 부분에서 나온 분석인지 추적할 수 있습니다. 토큰의 표면형이 원문의 연속 부분 문자열과 항상 똑같지는 않을 수 있으므로 위치 정보와 분석형을 구분해 보세요.

확인 실습: 각 토큰에 대해 print(t.form, t.tag, t.start, t.len)을 실행하고, 조사가 명사와 분리되는지 살펴봅니다.

VOC에서는 대상·행위·평가·정도를 분리하는 데 품사 태그를 사용합니다.

태그의미VOC 활용

VV동사행위
VA형용사맛·상태·평가

왜 필요한가? “늦다”는 Kiwi에서 VA로 나타날 수 있습니다. 동사/형용사는 직감이 아니라 실제 태그로 구분합니다.

품사 태그를 외우기보다 질문으로 연결

NNG·NNP는 ‘무엇을 말했나’, VV는 ‘무슨 일이 일어났나’, VA는 ‘어떻게 평가했나’, MAG는 ‘정도나 양상이 어떤가’를 살펴보는 데 사용합니다. 조사와 어미도 문장 구조를 이해하는 데 중요하지만 VOC 키워드 집계에서는 목적에 따라 제외할 수 있습니다.

주의: ‘늦다’는 한국어 문법상 형용사로 분석될 수 있습니다. 일상적인 ‘행동’이라는 의미와 품사 태그의 동사는 다릅니다. 업무상의 ‘지연’ 분류는 별도 규칙으로 처리합니다.

명사를 모두 핵심 이슈라고 해석하면 안 되는 이유

‘배달’이 30회 등장하더라도 긍정 VOC에서 등장했는지, 불만에서 등장했는지는 아직 알 수 없습니다. 명사 빈도는 자주 언급되는 대상을 찾는 출발점입니다. 다음 단계에서 평가극성·심각도와 교차분석해야 문제의 크기를 알 수 있습니다.

동사·형용사·부사 추출

어떤 일이 있었고 어떻게 평가했는지를 분리합니다.

text = "배달이 너무 늦고 음식이 정말 맛있어요."

품사업무 질문
VV어떤 행위가 있었나?
VA어떻게 평가했나?
MAG정도·양상이 어떤가?
왜 필요한가? 형용사를 맛·온도·서비스·기분 등으로 묶는 것은 Kiwi 품사 분석 이후의 별도 의미 분류 작업입니다.

형용사는 ‘평가 영역’으로 한 번 더 묶을 수 있습니다

‘맛있다·짜다·싱겁다’는 맛, ‘따뜻하다·차갑다’는 온도·상태, ‘친절하다·불친절하다’는 응대라는 평가 영역으로 연결할 수 있습니다. 다만 문맥에 따라 의미가 달라지므로 사람이 확정한 기준표를 사용합니다.

동사도 ‘환불하다·취소하다’처럼 업무 행위 유형으로 묶을 수 있지만, 품사별 추출과 업무 카테고리 분류는 서로 다른 단계입니다.

사용자 사전과 오타

서비스명이나 고객 특유의 표현은 기본 분석만으로 부족할 수 있습니다.

kiwi.add_user_word("배달앱", "NNG")
for t in kiwi.tokenize("배달앱에서 결제가 안 돼요"):
    print(t.form, t.tag)

배달안옴띄어쓰기 누락

왜 필요한가? 사용자 사전 등록 전후 결과를 비교하고, 오타 처리 기능은 설치 버전의 설정을 확인한 후 적용합니다. 원문은 변경하지 않습니다.

사용자 사전이 필요한 실제 사례

서비스명, 제품명, 사내 약어는 기본 사전에서 잘못 나뉠 수 있습니다. 예를 들어 특정 서비스명을 하나의 명사로 취급하려면 사용자 사전에 추가합니다. 다만 사전 추가는 모든 문맥에서 반드시 그 단어로 분석됨을 보장하지 않습니다. 전후 결과를 비교하고 과도한 등록을 피해야 합니다.

오타 교정은 의도하지 않은 변경 가능성이 있으므로 원문은 별도로 보존합니다. ‘넘’ 같은 표현을 ‘너무’로 통일할지는 분석 목적과 교정 옵션을 확인한 뒤 결정합니다.

여러 VOC를 DataFrame으로

한 문장 실습을 여러 고객 문장으로 확장합니다.

import pandas as pd

texts = [
    "배달이 너무 늦어요",
    "음식이 정말 맛있어요",
    "결제가 계속 실패해요"
]

rows = []
for text in texts:
    nouns = []
    for t in kiwi.tokenize(text):
        if t.tag in ("NNG", "NNP"):
            nouns.append(t.form)
    rows.append([text, ";".join(nouns)])

df = pd.DataFrame(rows, columns=["VOC_원문", "명사_대상"])
print(df.to_string(index=False))
왜 필요한가? 이 구조가 VOC Step 1의 품사별 분석 열로 이어집니다. 다만 업무용 카테고리·극성·심각도는 별도 판정이 필요합니다.

DataFrame에서 반드시 보존할 열

여러 문장을 처리할 때는 VOC_ID·VOC_원문·명사_대상·동사_행위·형용사_평가·부사_정도를 한 행으로 관리합니다. 원문을 보존해야 형태소 분석이 이상할 때 되돌아가 확인할 수 있습니다.

빈 값과 ‘분석 실패’는 구분해야 합니다. 특정 품사가 없는 문장과 분석 자체가 실패한 문장을 동일하게 처리하면 나중에 빈도와 비율이 왜곡됩니다.
