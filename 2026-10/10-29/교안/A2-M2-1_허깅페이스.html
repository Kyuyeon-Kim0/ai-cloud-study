00. 왜 Hugging Face로 RAG를 만드는가

이 과정의 최종 목표는 RAG(검색 증강 생성)입니다. 01~10번 코드는 모두 RAG의 한 부품을 직접 만들어 보는 단계이고, Hugging Face는 그중 검색(Retrieval)을 책임집니다.

RAG란 무엇인가

GPT 같은 생성 모델은 학습이 끝난 시점 이후의 정보, 그리고 회사 내부 문서처럼 공개되지 않은 정보를 알지 못합니다. 모르는 것을 물으면 그럴듯하게 지어내기도 합니다(환각). RAG는 질문과 관련된 문서를 먼저 찾아서 그 문서를 근거로 붙여 준 뒤 답하게 하는 방식입니다.

공통 모듈: core.py

04·09·10번은 같은 임베딩 함수를 공유합니다. 검색 품질은 이 파일 하나로 결정되므로, 각 줄의 의미를 04장에서 자세히 다룹니다.

core.py
"""A2-M2: 하나의 E5 인코더를 활용하는 공통 코드. 실행 시 최초 모델 다운로드가 필요하다."""
import torch
import torch.nn.functional as F
from transformers import AutoTokenizer, AutoModel

MODEL_ID = "intfloat/multilingual-e5-small"


def load():
    tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, use_fast=True)
    model = AutoModel.from_pretrained(MODEL_ID)
    model.eval()
    return tokenizer, model


def mean_pool(last_hidden_state, attention_mask):
    mask = attention_mask.unsqueeze(-1).to(last_hidden_state.dtype)
    summed = (last_hidden_state * mask).sum(dim=1)
    counts = mask.sum(dim=1).clamp(min=1)
    return summed / counts


@torch.inference_mode()
def embed(texts, tokenizer, model, kind="passage", max_length=256):
    if kind not in ("query", "passage"):
        raise ValueError("kind는 query 또는 passage")
    prefixed = [f"{kind}: {text}" for text in texts]
    encoded = tokenizer(prefixed, padding=True, truncation=True,
                        max_length=max_length, return_tensors="pt")
    result = model(**encoded)
    pooled = mean_pool(result.last_hidden_state, encoded["attention_mask"])
    return F.normalize(pooled, p=2, dim=1)
함수하는 일왜 필요한가
load()E5 토크나이저·모델을 불러오고 eval() 모드로 전환추론 전용이므로 dropout을 끄고 결과를 고정
mean_pool()토큰 벡터 평균, 단 attention_mask로 PAD 제외패딩까지 평균내면 짧은 문장 벡터가 왜곡됨
embed()접두어(query:/passage:) → 토큰화 → 모델 → 평균 → L2 정규화정규화된 벡터끼리는 내적 = 코사인 유사도

RAG 여정에서 이 단계의 의미

RAG는 여러 모델을 조합합니다. 임베딩 모델, 분류 모델, 생성 모델이 각각 다른 Task용입니다. 모델 이름만 보고 가져오면 “분류 모델로 임베딩을 뽑는” 식의 실수가 생깁니다. 그래서 모델의 Task·라벨·최대 입력 길이를 먼저 읽는 습관이 첫 단계입니다.

01_model_task.py
"""Hugging Face Hub에 올라온 사전학습 모델의 설정(config)과 토크나이저를 불러와
이 모델이 어떤 Task(예: 문장 분류)용인지, 입력을 어떻게 처리하는지 확인한다.
모델 가중치는 내려받지 않으므로 가볍게 실행된다.
"""
from transformers import AutoConfig, AutoTokenizer

# Hub 모델 ID: "작성자/모델이름" 형식
# KR-FinBert-SC: 한국어 금융 문장 감성 분류(Sentiment Classification) 모델
name = "snunlp/KR-FinBert-SC"

# AutoConfig: 모델 구조·라벨 정보가 담긴 config.json만 불러온다 (가중치 X)
config = AutoConfig.from_pretrained(name)
# AutoTokenizer: 모델에 맞는 토크나이저 클래스를 자동으로 골라 불러온다
tok = AutoTokenizer.from_pretrained(name)

print("모델:", name)

# model_type: 기반 아키텍처 (bert, roberta, gpt2 등)
print("model_type:", config.model_type)

# num_labels / id2label / label2id: 분류 모델이면 출력 클래스 정보가 들어 있다
# - 라벨이 여러 개 → 분류(Sequence/Token Classification) Task 모델임을 알 수 있음
# - id2label: 모델 출력 인덱스 → 사람이 읽는 라벨 이름 (예측 결과 해석에 사용)
# - label2id: 라벨 이름 → 인덱스 (학습 데이터 라벨을 숫자로 바꿀 때 사용)
print("num_labels:", config.num_labels)
print("id2label:", config.id2label)
print("label2id:", config.label2id)

# 토크나이저 종류: 문장을 어떤 방식(WordPiece, BPE 등)으로 쪼개는지 결정
print("tokenizer:", type(tok).__name__)

# vocab_size: 토크나이저가 아는 토큰(단어 조각) 개수
print("vocab_size:", tok.vocab_size)

# 입력 최대 길이(토큰 수): 이보다 긴 문장은 잘라서(truncation) 넣어야 한다
# tokenizer 설정에 최대 길이가 없으면 매우 큰 값(약 1e30)이 들어가므로
# 그때는 모델이 실제로 처리할 수 있는 위치 임베딩 개수(max_position_embeddings)를 사용
max_len = tok.model_max_length if tok.model_max_length < 100_000 else config.max_position_embeddings
print("입력 최대 길이:", max_len)

print("이 정보는 어떤 Task의 모델인지 판단할 때 필요합니다.")

Q. AutoConfig만 불러오면 예측을 할 수 있나요?

아닙니다. config는 설계도일 뿐 학습된 숫자(가중치)가 없습니다. 예측하려면 02번처럼 AutoModelFor…로 가중치를 불러와야 합니다.

Q. id2label과 label2id는 왜 둘 다 있나요?

id2label은 예측 결과(숫자)를 사람이 읽는 이름으로 바꿀 때, label2id는 학습 데이터의 라벨 이름을 숫자로 바꿀 때 씁니다. 07번 파인튜닝에서 직접 두 값을 지정합니다.

02_config_pipeline.py
"""교안 02: AutoModel·AutoTokenizer·pipeline으로 문장을 분류하고 라벨별 점수를 확인한다.
01에서는 config만 봤다면, 여기서는 모델 가중치까지 내려받아 실제로 예측을 해 본다.
"""
from transformers import AutoTokenizer, AutoModelForSequenceClassification, pipeline

# Hub 모델 ID: 한국어 금융 문장 감성 분류 모델 (negative / neutral / positive)
name = "snunlp/KR-FinBert-SC"

# AutoTokenizer: 문장 → 토큰 ID로 바꿔 주는 토크나이저
tok = AutoTokenizer.from_pretrained(name)
# AutoModelForSequenceClassification: 문장 분류용 헤드(출력층)가 붙은 모델
# - 가중치(pytorch_model.bin / model.safetensors)까지 내려받는다
# - 모델 config도 함께 로드되므로 model.config로 라벨 정보를 볼 수 있다
model = AutoModelForSequenceClassification.from_pretrained(name)

# id2label: 모델 출력 인덱스 → 라벨 이름 (예측 결과를 사람이 읽을 수 있게 해 줌)
print("config.id2label:", model.config.id2label)
# num_labels: 분류할 클래스 개수 = 모델 출력(logits) 차원 수
print("config.num_labels:", model.config.num_labels)

# pipeline: 토큰화 → 모델 추론 → 후처리(softmax, 라벨 이름 붙이기)를 한 번에 해 주는 도구
# - "text-classification": 문장 분류 Task
# - model / tokenizer: 위에서 불러온 객체를 그대로 넘겨 재사용 (다시 다운로드하지 않음)
# - device=-1: CPU 사용 (GPU가 있으면 0, 1, ... 처럼 GPU 번호 지정)
classifier = pipeline("text-classification", model=model, tokenizer=tok, device=-1)

# 분류해 볼 예시 문장: 긍정적인 문장 1개, 부정적인 문장 1개
texts = ["기업 실적이 크게 개선되었다.", "기업의 주가가 크게 하락했다."]

# 기본 호출: 문장마다 점수가 가장 높은 라벨 1개만 돌려준다
# 결과 형태: [{'label': ..., 'score': ...}, ...]  (문장 수만큼)
print("\n[가장 높은 분류]")
for text, pred in zip(texts, classifier(texts)):
    print(f"  {text} → {pred['label']} ({pred['score']:.4f})")

# top_k=None: 모든 라벨의 점수를 높은 순으로 돌려준다
# - score는 softmax 확률이므로 한 문장의 라벨 점수를 모두 더하면 1이 된다
# - 1등과 2등 점수 차이를 보면 모델이 얼마나 확신하는지 알 수 있다
print("\n[모든 라벨별 점수]")
for text, preds in zip(texts, classifier(texts, top_k=None)):
    print(f"  {text}")
    for p in preds:
        print(f"    {p['label']:<8} {p['score']:.4f}")

03. 토크나이저: 문장이 숫자가 되는 과정

모델은 글자를 읽지 못하고 토큰 ID만 받습니다. tokenize → encode → decode, 그리고 여러 문장을 묶을 때 필요한 padding·truncation·attention_mask를 직접 확인합니다.

RAG 여정에서 이 단계의 의미

RAG에서 문서를 몇 글자씩 자를지(청킹)는 글자 수가 아니라 토큰 수로 정해야 합니다. 모델의 최대 길이를 넘으면 truncation이 뒤쪽을 조용히 버리고, 그 안에 있던 근거는 검색에서 영영 사라집니다. 이 장의 마지막 출력 문장이 바로 그 경고입니다.

네 가지 변환

메서드입력 → 출력언제 쓰나
tok.tokenize()문장 → 토큰 문자열어떻게 쪼개지는지 눈으로 확인
tok.encode()문장 → 토큰 ID(특수 토큰 포함)모델에 실제로 들어가는 값
convert_ids_to_tokens()ID → 토큰 문자열특수 토큰 위치 확인
tok.decode()ID → 문장모델 출력·검증용 복원
03_tokenizer.py
"""교안 03: tokenize/encode/decode와 padding, truncation, token_type_ids.
모델은 글자를 직접 읽지 못하고 숫자(토큰 ID)만 받는다.
토크나이저가 문장을 어떻게 쪼개고 숫자로 바꾸는지, 여러 문장을 한 번에 넣을 때
길이를 어떻게 맞추는지 확인한다. 토크나이저 파일만 내려받으므로 가볍게 실행된다.
"""
from transformers import AutoTokenizer

# klue/bert-base: 한국어 BERT 모델 (WordPiece 방식 토크나이저 사용)
name = "klue/bert-base"
tok = AutoTokenizer.from_pretrained(name)

sentence = "이미지에 대체 텍스트를 제공해야 합니다."
print("원문:", sentence)

# tokenize: 문장 → 토큰(문자열) 목록
# - WordPiece는 자주 쓰이는 단어 조각 단위로 쪼갠다
# - '##'이 붙은 토큰은 앞 토큰에 이어지는 조각이라는 뜻 (예: '이미지' + '##에' = '이미지에')
print("토큰:", tok.tokenize(sentence))

# encode: 문장 → 토큰 ID(숫자) 목록. 모델에 실제로 들어가는 값이다
# - 기본적으로 앞뒤에 특수 토큰 [CLS](시작), [SEP](끝)의 ID가 자동으로 붙는다
#   그래서 위 토큰 개수보다 ID가 2개 더 많다
ids = tok.encode(sentence)
print("ID:", ids)

# convert_ids_to_tokens: ID → 토큰 문자열. 특수 토큰이 붙은 것을 눈으로 확인할 수 있다
print("ID→토큰:", tok.convert_ids_to_tokens(ids))

# decode: ID → 원래 문장으로 복원
# - skip_special_tokens=True: [CLS], [SEP] 같은 특수 토큰은 빼고 복원
print("디코딩:", tok.decode(ids, skip_special_tokens=True))

# special_tokens_map: 이 토크나이저가 쓰는 특수 토큰 목록
# - [UNK]: 사전에 없는 토큰, [PAD]: 길이 맞추기용 빈칸, [MASK]: 가려진 토큰(사전학습용)
print("특수토큰:", tok.special_tokens_map)

# 여러 문장을 한 번에(batch) 토큰화
# - 문장마다 길이가 다르면 텐서(행렬)로 묶을 수 없으므로 길이를 맞춰야 한다
# - padding=True: 가장 긴 문장 길이에 맞춰 짧은 문장 뒤에 [PAD](ID 0)를 채운다
# - truncation=True + max_length=32: 32토큰보다 길면 뒤를 잘라낸다
# - return_tensors="pt": 결과를 PyTorch 텐서로 돌려준다
inputs = tok([sentence, "WCAG 2.4.4 링크 목적 확인"], padding=True,
             truncation=True, max_length=32, return_tensors="pt")

# 결과는 세 가지 텐서로 구성되며, shape은 [문장 수, 맞춰진 길이]
# - input_ids: 토큰 ID. 짧은 첫 문장 끝에 0([PAD])이 채워진 것을 볼 수 있다
# - token_type_ids: 문장 구분 번호. 문장 2개를 한 입력으로 넣을 때(질문+문단 등)
#   첫 문장은 0, 두 번째 문장은 1이 된다. 여기서는 각각 한 문장이라 모두 0
# - attention_mask: 실제 토큰은 1, [PAD]는 0. 모델이 패딩 부분을 무시하게 해 준다
print("\n[배치 토큰화 결과]")
for key, value in inputs.items():
    print(f"{key} {tuple(value.shape)}")
    for row in value.tolist():
        print("  ", row)

# 주의: truncation은 max_length를 넘는 부분을 그냥 버린다
# RAG에서 긴 문서를 그대로 넣으면 뒤쪽에 있던 근거가 잘려 사라질 수 있으므로
# 문서를 미리 적당한 길이로 나눠(chunking) 넣는 것이 좋다
print("\ntruncation=True는 길이를 넘는 부분을 잘라내므로 근거 손실을 유발할 수 있습니다.")

04_embedding_search.py
"""교안 04: Last Hidden State, 패딩 제외 평균, L2 정규화, 코사인 비교.
문장을 하나의 벡터(임베딩)로 바꾸는 과정을 단계별로 확인한다.
모델 출력(토큰별 벡터) → 평균으로 문장 벡터 1개 → 길이 1로 정규화 → 코사인 유사도 비교.
공통 함수(load, embed, mean_pool)는 core.py에 있다.
"""
import torch
from core import load, embed, mean_pool

# load(): core.py의 MODEL_ID(intfloat/multilingual-e5-small) 토크나이저와 모델을 불러온다
# - E5는 문장 임베딩(검색)용으로 학습된 다국어 인코더 모델
tok, model = load()

# 비교할 문장: 앞의 두 개는 비슷한 의미, 세 번째는 전혀 다른 주제
sentences = ["이미지 대체 텍스트", "이미지 alt 설명", "서버 배포 장애"]

# E5 모델은 입력 앞에 용도를 알려 주는 접두어를 붙여야 성능이 제대로 나온다
# - "passage: " → 검색 대상 문서, "query: " → 검색 질문
batch = tok(["passage: " + s for s in sentences], padding=True, truncation=True,
            return_tensors="pt")

# inference_mode: 학습이 아니라 추론만 하므로 기울기(gradient) 계산을 끄고 빠르게 실행
with torch.inference_mode():
    output = model(**batch)
    # last_hidden_state: 마지막 층의 출력. 토큰마다 벡터가 하나씩 있다
    # mean_pool: 토큰 벡터들의 평균을 내 문장 벡터 1개로 만든다
    # - attention_mask를 이용해 [PAD] 토큰은 평균에서 제외한다
    #   (패딩까지 평균에 넣으면 짧은 문장일수록 벡터가 왜곡됨)
    pooled = mean_pool(output.last_hidden_state, batch["attention_mask"])

# shape 변화로 과정을 확인
# - input_ids: [문장 수, 토큰 수]
# - last_hidden_state: [문장 수, 토큰 수, 히든 크기 384] → 토큰마다 384차원 벡터
# - pooled: [문장 수, 384] → 토큰 축을 평균 내서 문장당 벡터 1개
print("input_ids:", tuple(batch["input_ids"].shape))
print("last_hidden_state:", tuple(output.last_hidden_state.shape))
print("pooled:", tuple(pooled.shape))

# embed(): 위 과정(접두어 → 토큰화 → 모델 → mean_pool)에 L2 정규화까지 한 번에 해 주는 함수
# - L2 정규화: 벡터를 길이(norm)로 나눠 길이를 1로 만든다
vec = embed(sentences, tok, model, kind="passage")
print("정규화 문장 벡터:", tuple(vec.shape))

# 정규화 전에는 길이가 제각각(약 4.6), 정규화 후에는 모두 1
# (0.99999994처럼 보이는 것은 부동소수점 오차로, 사실상 1)
print("정규화 전 L2:", [round(x, 4) for x in pooled.norm(dim=1).tolist()])
print("정규화 후 L2:", [round(x, 4) for x in vec.norm(dim=1).tolist()])

# 코사인 유사도 = 두 벡터의 내적 / (길이 × 길이)
# 벡터 길이가 1로 정규화되어 있으므로 내적(@)만 하면 바로 코사인 유사도가 된다
# - vec[0] @ vec.T: 첫 문장 벡터와 모든 문장 벡터의 유사도를 한 번에 계산
# - 1에 가까울수록 의미가 비슷하다. 자기 자신과의 유사도는 1
# - E5 모델은 점수가 전체적으로 높게(0.8~1.0) 나오는 편이라
#   절대값보다 문장 간 순위(어느 쪽이 더 높은지)를 보는 것이 중요하다
print("\n[첫 문장과의 코사인 유사도]")
for s, score in zip(sentences, (vec[0] @ vec.T).tolist()):
    print(f"  {sentences[0]} ↔ {s}: {score:.4f}")

Q. 왜 PAD를 평균에서 빼야 하나요?

"""교안 05: Pipeline Task와 BART. 큰 모델은 옵션으로 단계별 사용.
pipeline에 Task 이름만 바꿔 주면 분류·빈칸 채우기·요약·제로샷 분류를 같은 방식으로 실행할 수 있다.
모델이 클수록 다운로드와 실행이 오래 걸리므로 --task 옵션으로 하나씩 골라 실행한다.

실행 예:
  python 05_pipeline_bart.py                    # 기본: classify (한국어 감성 분류)
  python 05_pipeline_bart.py --task mask        # 빈칸 채우기 (bart-base, 약 0.5GB)
  python 05_pipeline_bart.py --task summary     # 요약 (bart-large-cnn, 약 1.6GB)
  python 05_pipeline_bart.py --task zero-shot   # 제로샷 분류 (bart-large-mnli, 약 1.6GB)
"""
import argparse
from transformers import AutoTokenizer, pipeline

# argparse: 명령줄 옵션(--task)을 받아 실행할 Task를 고른다
parser = argparse.ArgumentParser()
parser.add_argument("--task", choices=["classify", "mask", "summary", "zero-shot"], default="classify")
args = parser.parse_args()

if args.task == "classify":
    # text-classification: 문장 → 정해진 라벨 중 하나로 분류 (02에서 사용한 모델과 동일)
    # - model, tokenizer에 모델 ID 문자열을 주면 pipeline이 알아서 불러온다
    # - device=-1: CPU 사용
    model = "snunlp/KR-FinBert-SC"
    task = pipeline("text-classification", model=model, tokenizer=model, device=-1)
    # top_k=None: 모든 라벨 점수를 높은 순으로 출력
    print(task("기업 실적이 개선되었다.", top_k=None))

elif args.task == "mask":
    # fill-mask: 문장 속 가려진 자리(마스크 토큰)에 들어갈 단어를 예측
    # - BART는 사전학습 때 가려진 부분을 복원하도록 학습되어 빈칸 채우기를 할 수 있다
    # - 영어 모델이므로 영어 문장을 넣어야 한다
    name = "facebook/bart-base"
    tok = AutoTokenizer.from_pretrained(name)
    task = pipeline("fill-mask", model=name, tokenizer=tok, device=-1)
    # 마스크 토큰은 모델마다 다르다 (BERT는 [MASK], BART는 <mask>)
    # 그래서 문자열을 직접 쓰지 않고 tok.mask_token으로 가져온다
    # top_k=3: 점수가 높은 후보 3개만 출력
    print(task(f"I went to the {tok.mask_token} today.", top_k=3))

elif args.task == "summary":
    # 요약: 긴 글 → 짧은 요약문 생성
    # - bart-large-cnn: CNN/DailyMail 뉴스 요약 데이터로 파인튜닝된 영어 요약 모델
    # - transformers v5부터 "summarization" pipeline이 삭제되어,
    #   pipeline 대신 모델을 직접 불러와 generate()로 요약문을 생성한다
    # - AutoModelForSeq2SeqLM: 입력 문장을 읽고(인코더) 새 문장을 써 내는(디코더) 모델
    from transformers import AutoModelForSeq2SeqLM
    name = "facebook/bart-large-cnn"
    tok = AutoTokenizer.from_pretrained(name)
    model = AutoModelForSeq2SeqLM.from_pretrained(name)
    # 같은 문장을 15번 반복해 긴 입력을 만든다
    text = ("Artificial intelligence can analyze long reports and organize information. " * 15)
    # 토큰화 (BART 최대 입력 1024토큰을 넘으면 잘라냄)
    inputs = tok(text, truncation=True, max_length=1024, return_tensors="pt")
    # generate: 요약문 토큰을 한 개씩 생성
    # - max_new_tokens=50: 요약문을 최대 50토큰까지만 생성
    # - min_length=10: 모델 기본 설정의 최소 길이(56)가 최대 길이보다 커서 경고가 나므로 낮춰 준다
    # - do_sample=False: 무작위 샘플링 없이 가장 확률 높은 단어를 골라 매번 같은 결과가 나온다
    summary_ids = model.generate(**inputs, max_new_tokens=50, min_length=10, do_sample=False)
    # decode: 생성된 토큰 ID → 문장 (특수 토큰 제외)
    print([{"summary_text": tok.decode(summary_ids[0], skip_special_tokens=True)}])

else:
    # zero-shot-classification: 따로 학습하지 않은 라벨로도 분류
    # - bart-large-mnli: 두 문장이 서로 맞는지(함의/모순) 판단하도록 학습된 모델
    # - 원리: 라벨마다 "This text is about {라벨}." 문장을 만들고
    #   입력 문장과 얼마나 잘 맞는지(함의 확률)를 점수로 사용한다
    # - 그래서 후보 라벨(technology, sports)을 실행할 때 마음대로 바꿀 수 있다
    task = pipeline("zero-shot-classification", model="facebook/bart-large-mnli", device=-1)
    result = task("A new smartphone has an improved camera.", ["technology", "sports"],
                  hypothesis_template="This text is about {}.")
    # 결과: sequence(입력 문장), labels(점수 높은 순 라벨), scores(라벨별 점수, 합계 1)
    print(result)

# Task마다 모델 크기, 지원 언어(한국어/영어), 라벨 정의가 다르므로

BERT는 [MASK], BART는 <mask>처럼 모델마다 다르기 때문입니다. 문자열을 직접 쓰면 모델을 바꿀 때 오류가 납니다.

"""교안 06: CSV → Dataset → DatasetDict, map 배치 및 컬럼 처리.
학습용 데이터를 Hugging Face datasets 형식으로 불러와 train/test로 나누고,
토크나이저를 적용해 모델에 넣을 수 있는 형태(input_ids 등)로 바꾸는 과정을 확인한다.
같은 폴더에 feedback_sample.csv(text, label 컬럼)가 있어야 한다.
"""
from pathlib import Path
import pandas as pd
from datasets import Dataset, DatasetDict, load_dataset
from transformers import AutoTokenizer

# Path(__file__).with_name(): 이 py 파일과 같은 폴더의 CSV 경로
# (어느 폴더에서 실행하든 파일을 찾을 수 있다)
csv_file = Path(__file__).with_name("feedback_sample.csv")

# 1) pandas로 CSV 읽기: shape은 (행 수, 컬럼 수)
df = pd.read_csv(csv_file)
print("pandas:", df.shape, df.columns.tolist())

# 2) pandas DataFrame → Hugging Face Dataset
# - preserve_index=False: pandas의 행 번호(index)는 컬럼으로 가져오지 않는다
# - features: 컬럼 목록, num_rows: 행(샘플) 수
base = Dataset.from_pandas(df, preserve_index=False)
print("Dataset:", base)

# 3) train/test 나누기
# - test_size=0.25: 25%를 평가용으로 떼어 낸다 (9행 → train 6 / test 3)
# - seed=42: 섞는 순서를 고정해 실행할 때마다 같은 결과가 나오게 한다
splits = base.train_test_split(test_size=0.25, seed=42)

# DatasetDict: 여러 Dataset을 이름("train", "test")으로 묶어 한 번에 다루는 dict
dsd = DatasetDict({"train": splits["train"], "test": splits["test"]})
print("DatasetDict:", dsd)

# (참고) pandas 없이 load_dataset("csv")로 CSV를 바로 DatasetDict로 불러올 수도 있다
# - data_files에 {"split 이름": 파일 경로}를 주면 그 이름으로 만들어진다
print("load_dataset(csv):", load_dataset("csv", data_files={"train": str(csv_file)}))

# 4) 토크나이저를 데이터셋 전체에 적용
tok = AutoTokenizer.from_pretrained("klue/bert-base")

def encode_batch(batch):
    # batched=True이면 batch["text"]는 문장 1개가 아니라 문장 리스트로 들어온다
    # truncation + max_length=48: 48토큰보다 긴 문장은 잘라낸다
    # (padding은 여기서 하지 않고, 학습할 때 배치 단위로 맞추는 것이 효율적)
    return tok(batch["text"], truncation=True, max_length=48)

# map: 모든 행에 함수를 적용해 반환한 값을 새 컬럼으로 추가한다
# - batched=True: 여러 행을 묶어서 한 번에 처리 (한 줄씩보다 빠름)
# - batch_size=2: 한 번에 2행씩 묶음 (보통은 기본값 1000을 그대로 쓴다)
# - DatasetDict에 적용하면 train, test 모두에 적용된다
tokenized = dsd.map(encode_batch, batched=True, batch_size=2)

# 토크나이저 결과(input_ids, token_type_ids, attention_mask)가 컬럼으로 추가됨
print("추가된 컬럼:", tokenized["train"].column_names)
print("첫 행:", tokenized["train"][0])

# 5) 필요 없는 컬럼 제거
# - 모델은 숫자만 입력받으므로 원문 text 컬럼은 학습할 때 필요 없다
# - remove_columns는 새 데이터셋을 돌려줄 뿐, 원래 데이터셋은 그대로 둔다
removed = tokenized.remove_columns(["text"])
print("text 컬럼을 제거한 결과:", removed["train"].column_names)
print("원본 데이터셋은 변경되지 않습니다:", dsd["train"].column_names)

"""교안 07: 제조품질 3분류 Trainer 실습. CPU에는 시간이 걸림. 시험용 소규모 데이터.
사전학습된 klue/bert-base에 분류 헤드를 붙이고, 제조 품질 문장(불량/정상/경미한 불량)으로
파인튜닝(추가 학습)한 뒤 독립 테스트 데이터로 평가하고 모델을 저장한다.
같은 폴더에 manufacturing_sample.csv(text, label 컬럼)가 있어야 한다.
"""
import csv
from pathlib import Path
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score, f1_score, classification_report
from datasets import Dataset
from transformers import (AutoTokenizer, AutoModelForSequenceClassification,
                          DataCollatorWithPadding, Trainer, TrainingArguments, set_seed)

# set_seed: 무작위 값을 고정해 실행할 때마다 같은 결과가 나오게 한다
# - 새로 붙는 분류 헤드는 모델을 불러올 때 무작위로 초기화되므로,
#   TrainingArguments의 seed만으로는 부족하고 모델 로드 전에 고정해야 한다
set_seed(42)

# 1) CSV 읽기
# - encoding="utf-8-sig": 엑셀에서 저장한 CSV 맨 앞의 BOM 문자를 자동으로 제거
# - csv.DictReader: 각 행을 {"text": ..., "label": ...} 형태의 dict로 읽는다
source = Path(__file__).with_name("manufacturing_sample.csv")
with source.open(encoding="utf-8-sig", newline="") as f:
    rows = list(csv.DictReader(f))
labels = [int(r["label"]) for r in rows]
index = list(range(len(rows)))

# 2) train / valid / test 3개로 나누기 (60% / 20% / 20%)
# - train: 학습에 사용, valid: 학습 중 성능 확인, test: 학습이 끝난 뒤 한 번만 평가
# - stratify=labels: 나눈 각 데이터에 라벨 비율이 원본과 같게 유지되도록 한다
#   (데이터가 적을 때 한쪽에 특정 라벨이 몰리는 것을 막음)
# - random_state=42: 나누는 결과를 고정
train_idx, other_idx = train_test_split(index, test_size=0.4, random_state=42, stratify=labels)
valid_idx, test_idx = train_test_split(other_idx, test_size=0.5, random_state=42,
                                       stratify=[labels[i] for i in other_idx])

def as_data(ids):
    # 인덱스 목록 → Hugging Face Dataset
    # Trainer는 정답 컬럼 이름을 "labels"로 기대하므로 이름을 맞춰 준다
    return Dataset.from_dict({"text": [rows[i]["text"] for i in ids],
                              "labels": [int(rows[i]["label"]) for i in ids]})

# 3) 토큰화
name = "klue/bert-base"
tok = AutoTokenizer.from_pretrained(name)

def preprocess(batch):
    # 96토큰보다 긴 문장은 잘라낸다. 패딩은 아래 DataCollator가 배치마다 처리
    return tok(batch["text"], truncation=True, max_length=96)

train_ds = as_data(train_idx).map(preprocess, batched=True)
valid_ds = as_data(valid_idx).map(preprocess, batched=True)
test_ds = as_data(test_idx).map(preprocess, batched=True)

# 4) 모델 준비
# - klue/bert-base는 분류용으로 학습된 모델이 아니므로 분류 헤드(classifier)가 없다
# - num_labels=3을 주면 3개 클래스를 출력하는 분류 헤드를 새로 붙인다 (값은 무작위로 시작)
#   → 실행 시 나오는 MISSING(classifier.weight/bias) 메시지는 이 새 헤드를 뜻하므로 정상
#   → UNEXPECTED(cls.predictions...)는 사전학습용 헤드라 분류에서는 버려지는 것이므로 무시해도 된다
# - id2label / label2id를 함께 저장해 두면 예측 결과를 라벨 이름으로 볼 수 있다
labels_dict = {0: "불량", 1: "정상", 2: "경미한 불량"}
model = AutoModelForSequenceClassification.from_pretrained(
    name, num_labels=3, id2label=labels_dict,
    label2id={v: k for k, v in labels_dict.items()})

def metrics(p):
    # 평가 지표 계산 함수: Trainer가 평가할 때마다 호출한다
    # - p.predictions: 모델 출력 점수(logits), [샘플 수, 3]
    # - argmax: 점수가 가장 높은 클래스 번호를 예측값으로 사용
    # - f1 average="macro": 클래스별 F1을 단순 평균 (라벨마다 똑같은 비중으로 평가)
    pred = np.argmax(p.predictions, axis=-1)
    return {"accuracy": accuracy_score(p.label_ids, pred),
            "f1": f1_score(p.label_ids, pred, average="macro", zero_division=0)}

# 5) 학습 설정
# - output_dir: 체크포인트(중간 저장 모델)를 저장할 폴더
# - num_train_epochs=1: 학습 데이터를 1번만 훑는다 (실습용으로 짧게)
# - per_device_*_batch_size=4: 한 번에 4문장씩 학습/평가
# - eval_strategy / save_strategy="epoch": 에폭이 끝날 때마다 valid 평가와 저장
# - report_to="none": wandb 같은 외부 기록 도구를 쓰지 않음
# - seed=42: 가중치 초기화·데이터 섞기 순서를 고정
args = TrainingArguments(output_dir="./outputs/07", num_train_epochs=1,
    per_device_train_batch_size=4, per_device_eval_batch_size=4,
    eval_strategy="epoch", save_strategy="epoch", report_to="none", seed=42)

# Trainer: 학습 반복문(순전파 → 손실 → 역전파 → 가중치 갱신)과 평가를 대신 처리
# - processing_class=tok: 저장할 때 토크나이저도 함께 다룬다
# - DataCollatorWithPadding: 배치마다 그 배치에서 가장 긴 문장 길이에 맞춰 패딩
#   (전체 최대 길이로 패딩하는 것보다 계산이 적다)
trainer = Trainer(model=model, args=args, train_dataset=train_ds, eval_dataset=valid_ds,
    processing_class=tok, data_collator=DataCollatorWithPadding(tokenizer=tok),
    compute_metrics=metrics)

# 학습 실행: 진행률과 함께 eval_loss, eval_accuracy, eval_f1 등이 출력된다
trainer.train()

# 6) 독립 테스트 평가: 학습·검증에 쓰지 않은 test 데이터로 최종 성능을 확인
result = trainer.predict(test_ds)
pred = np.argmax(result.predictions, axis=-1)
# classification_report: 클래스별 precision(정밀도), recall(재현율), f1, support(샘플 수)
# - 데이터가 30행뿐이라 결과가 실행 환경에 따라 조금씩 달라질 수 있다
print("독립 테스트 평가:\n", classification_report(
    result.label_ids, pred, labels=list(labels_dict),
    target_names=list(labels_dict.values()), zero_division=0))

# 7) 저장: 모델 가중치·config와 토크나이저를 같은 폴더에 저장
# → 저장한 폴더를 다시 불러오는 방법은 08_save_reload.py에서 다룬다
trainer.save_model("./saved_model_07")
tok.save_pretrained("./saved_model_07")
print("모델 저장: saved_model_07")

"""교안 08: 모델 + 토크나이저 save_pretrained 후 로컬 재로딩.
Hub에서 받은 모델을 로컬 폴더에 저장하고, 인터넷 없이 그 폴더에서 다시 불러와 예측해 본다.
파인튜닝한 모델(07의 saved_model_07)도 같은 방법으로 불러올 수 있다.
"""
from pathlib import Path
from transformers import AutoTokenizer, AutoModelForSequenceClassification, pipeline

# Hub 모델 ID: 한국어 금융 문장 감성 분류 모델
name = "snunlp/KR-FinBert-SC"
# 저장할 로컬 폴더 (없으면 save_pretrained가 만들어 준다)
folder = Path("saved_model_08")

# 1) Hub에서 모델과 토크나이저 불러오기
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name)

# 2) 로컬 폴더에 저장
# - 모델: config.json(구조·라벨 정보) + model.safetensors(가중치)
# - 토크나이저: tokenizer.json(단어 사전·규칙) + tokenizer_config.json(설정)
# - 모델과 토크나이저는 반드시 짝을 맞춰 같은 폴더에 저장해야 한다
#   (토크나이저가 다르면 같은 문장이 다른 토큰 ID로 바뀌어 예측이 엉망이 됨)
model.save_pretrained(folder)
tok.save_pretrained(folder)
print("저장된 파일:", sorted(p.name for p in folder.iterdir()))

# 3) 로컬 폴더에서 다시 불러오기
# - from_pretrained에 Hub ID 대신 폴더 경로를 주면 로컬에서 불러온다
# - local_files_only=True: 인터넷에 접속하지 않고 로컬 파일만 사용
#   (폐쇄망·오프라인 환경이나 네트워크 오류가 날 때 유용)
local_tok = AutoTokenizer.from_pretrained(folder, local_files_only=True)
local_model = AutoModelForSequenceClassification.from_pretrained(folder, local_files_only=True)

# config.json에 저장된 라벨 정보가 그대로 복원되었는지 확인
print("라벨:", local_model.config.id2label)

# 4) 다시 불러온 모델로 예측
# 원본 모델과 같은 결과가 나오면 저장·재로딩이 제대로 된 것이다
clf = pipeline("text-classification", model=local_model, tokenizer=local_tok, device=-1)
print("로컬 예측:", clf("기업 실적이 증가했습니다."))

09_hf_cosine_search.py
"""교안 09: Hugging Face만 이용하는 코사인 Top-k 검색.
RAG의 Retrieval(검색) 단계를 직접 만들어 본다.
문서들을 미리 벡터로 바꿔 두고, 질문이 들어오면 질문 벡터와 코사인 유사도가 높은 문서를 찾는다.
search() 함수는 10_hf_gpt_rag.py에서 불러와 사용한다.
"""
from core import load, embed

# 검색 대상 문서 (문서 ID, 내용)
# 실제 서비스에서는 수천~수만 개의 문서 조각(chunk)이 들어간다
DOCS = [
    ("R01", "의미 있는 이미지에는 대체 텍스트를 제공한다."),
    ("R02", "장식용 이미지는 빈 alt를 사용할 수 있다."),
    ("R03", "링크 목적은 링크 텍스트 또는 문맥으로 이해할 수 있어야 한다."),
    ("R04", "입력 필드에는 명확한 이름과 레이블이 필요하다."),
]

# E5 임베딩 모델과 토크나이저 불러오기 (core.py 참고)
tok, model = load()

# 문서 벡터는 질문마다 다시 계산할 필요가 없으므로 시작할 때 한 번만 만들어 둔다
# - 문서와 질문에 같은 모델을 사용하되 E5의 접두어를 구분한다
#   문서는 "passage: ", 질문은 "query: "
# - 결과 shape: [문서 수, 384], 각 벡터는 길이 1로 정규화되어 있다
doc_vectors = embed([text for _, text in DOCS], tok, model, kind="passage")


def search(question, top_k=3):
    """질문과 가장 비슷한 문서 top_k개를 (문서 ID, 내용, 점수) 목록으로 돌려준다."""
    # 질문 1개를 벡터로 변환 → [1, 384]이므로 [0]으로 꺼내 [384]로 만든다
    query_vector = embed([question], tok, model, kind="query")[0]
    # L2 정규화된 벡터의 내적 = 코사인 유사도
    # [문서 수, 384] @ [384] → [문서 수]: 모든 문서와의 점수를 한 번에 계산
    scores = doc_vectors @ query_vector
    # argsort(descending=True): 점수가 높은 순으로 문서 번호를 정렬하고, 앞에서 top_k개만 사용
    ids = scores.argsort(descending=True)[:top_k].tolist()
    return [(DOCS[i][0], DOCS[i][1], float(scores[i])) for i in ids]


# 이 파일을 직접 실행할 때만 아래 대화형 검색을 실행한다
# (10번에서 import할 때는 실행되지 않고 search 함수만 가져간다)
if __name__ == "__main__":
    print("문서벡터 shape:", tuple(doc_vectors.shape))
    while True:
        try:
            question = input("\n질문 (q 종료): ").strip()
        except (EOFError, KeyboardInterrupt):
            # 입력이 끝났거나(EOF) Ctrl+C를 누르면 에러 없이 종료
            break
        if question.lower() == "q":
            break
        if not question:
            # 빈 입력은 검색하지 않고 다시 묻는다
            continue
        # 출력: 문서 ID / 코사인 유사도 / 문서 내용 (점수 높은 순)
        # E5는 점수가 전체적으로 높게(0.8 근처) 나오므로 절대값보다 순위를 보는 것이 중요하다
        for doc_id, content, score in search(question):
            print(f"{doc_id} / {score:.4f} / {content}")

검색 품질을 숫자로 측정하기: Hit@k

정답 문서가 상위 k개 안에 들어 있으면 성공(1), 아니면 실패(0)로 보고 평균을 냅니다. 위 두 질문은 Hit@1 = 2/2 = 1.0입니다. 06장의 rag_eval.csv로 자동화하면, 임베딩 모델이나 청킹 방식을 바꿀 때마다 객관적으로 비교할 수 있습니다.

from importlib import import_module
search = import_module("09_hf_cosine_search").search

eval_set = [
    ("이미지 대체 텍스트는 어떻게 제공하나요?", "R01"),
    ("장식용 이미지에는 alt를 어떻게 쓰나요?", "R02"),
    ("링크 텍스트 작성 기준은?", "R03"),
    ("입력창에 무엇을 표시해야 하나요?", "R04"),
]

for k in (1, 2):
    hits = sum(answer in [d for d, _, _ in search(q, top_k=k)] for q, answer in eval_set)
    print(f"Hit@{k} = {hits}/{len(eval_set)} = {hits/len(eval_set):.2f}")

10. RAG 완성: Hugging Face 검색 + GPT API 생성

09번의 검색 결과를 근거로 붙여 GPT에게 전달하고, “근거만 사용해 답하라”는 지시로 답변을 생성합니다. R(검색) → A(근거 결합) → G(생성)가 하나로 연결됩니다.

RAG 여정에서 이 단계의 의미

01~09에서 만든 모든 부품이 여기서 합쳐집니다. Hugging Face 임베딩이 무엇을 근거로 쓸지 정하고, GPT는 그 근거만으로 문장을 씁니다. 근거에 없는 질문에는 모른다고 답하게 만드는 것이 RAG의 핵심 가치입니다.

R · A · G 세 단계와 코드

"""교안 10: 09의 Hugging Face 검색 재사용 + GPT API 응답.
RAG(Retrieval-Augmented Generation) 전체 흐름을 완성한다.
  (1) Retrieval: 09의 임베딩 검색으로 질문과 관련된 문서를 찾고
  (2) Augmentation: 찾은 문서를 근거(context)로 프롬프트에 붙여
  (3) Generation: GPT가 그 근거만 사용해 답변을 생성한다
같은 폴더의 .env 파일에 OPENAI_API_KEY가 있어야 한다 (.env.example 참고).
"""
import os
from dotenv import load_dotenv
from openai import OpenAI
from importlib import import_module

# load_dotenv: .env 파일의 값(OPENAI_API_KEY, OPENAI_MODEL)을 환경변수로 불러온다
# - API 키를 코드에 직접 쓰지 않고 .env에 따로 두면 코드 공유 시 키가 노출되지 않는다
load_dotenv()
# 키가 없으면 무거운 임베딩 모델을 불러오기 전에 바로 종료
if not os.getenv("OPENAI_API_KEY"):
    raise SystemExit(".env에 OPENAI_API_KEY를 설정해야 합니다.")

# 파일명이 숫자로 시작하면 "import 09_hf_cosine_search"처럼 쓸 수 없으므로
# importlib로 검색 모듈을 불러온다
# - 이때 09 파일의 모델 로드와 문서 벡터 생성이 실행된다 (대화형 검색 부분은 실행 안 됨)
search = import_module("09_hf_cosine_search").search

try:
    question = input("질문: ").strip()
except (EOFError, KeyboardInterrupt):
    question = ""
if not question:
    raise SystemExit("질문을 입력하세요.")

# (1) Retrieval: 임베딩 모델과 코사인 유사도로 관련 문서 top_k개 검색
# - top_k가 너무 작으면 필요한 근거를 놓치고, 너무 크면 관련 없는 내용이 섞여 답변이 흐려진다
results = search(question, top_k=2)
for doc_id, text, score in results:
    print(f"검색: {doc_id} / {score:.4f} / {text}")

# (2) Augmentation: 생성 모델에 전달할 근거 본문 만들기
# - 문서마다 [R01] 같은 ID를 붙여 두면 GPT가 답변에 출처를 표시할 수 있다
# - 유사도 점수는 "질문과 얼마나 비슷한가"일 뿐, 정답일 확률이 아니므로 GPT에는 넘기지 않는다
context = "\n".join(f"[{doc_id}] {text}" for doc_id, text, score in results)

# (3) Generation: GPT API가 검색된 근거를 사용해 답변을 생성
# - OpenAI(): 환경변수 OPENAI_API_KEY를 자동으로 읽는다
client = OpenAI()
# responses.create: OpenAI Responses API 호출
# - model: .env의 OPENAI_MODEL을 사용하고, 없으면 gpt-4.1-mini
# - instructions: 모델의 행동 규칙 (시스템 프롬프트 역할)
#   "근거만 사용", "모르면 모른다고 말하기"는 환각(hallucination)을 줄이기 위한 지시
# - input: 실제 질문과 검색된 근거
response = client.responses.create(
    model=os.getenv("OPENAI_MODEL", "gpt-4.1-mini"),
    instructions="검색된 근거만 사용해 답하세요. 근거가 부족하면 모른다고 말하고 근거 문서 ID를 붙이세요.",
    input=f"질문: {question}\n\n검색 근거:\n{context}",
)
# output_text: 응답에서 생성된 텍스트만 꺼낸다
print("\n답변:\n", response.output_text)
